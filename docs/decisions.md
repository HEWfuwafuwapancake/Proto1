新しく決まったことは、合う節に1行足します。古い決まりを置きかえたときは、古い方を [archive/decisions_old.md](archive/decisions_old.md) へ移します。

- 腕ごとの操作と効き方は [plan/03_新しいアームの仕様.md](plan/03_新しいアームの仕様.md)、ゲームのルールは [plan/01_企画の要点.md](plan/01_企画の要点.md) にあります。
- （　）の中は、決めた日とタスクの番号です。

## 1. 作業の進め方

- **進め方**：タスクは1つずつ「プラン → 管理者の確認 → 実装 → テスト → 完了チェック」。1タスク ＝ 1フィーチャーブランチ ＝ 1 PR。
- **状態の記録**：タスクの状態は `tasks.md` と Notion の両方をそろえる（Notion はステータスと PR のリンクだけ）。プランは `handoff.md` の「次にやること」だけに書く。
- **確認と記録を軽くする**（2026-10-23）：画面を撮るのは見た目が変わるタスクだけ。わざと壊す確認は新しい計算のファイルだけを1回で。PR の説明は短く。詳しくは `CLAUDE.md` の「確認と記録を軽くする」。
- **テストは主な動きだけ**（2026-10-27）：端っこ・おかしな入力だけのテストや、同じことを何度も確かめるテストは足さない。実際に出た不具合を再現するテストは足す。
- **単体テストは Google Test**（2026-11-06）：googletest v1.15.2 のソースを `third_party/googletest` に入れて一緒にコンパイルする（NuGet・submodule は使わない）。
- **やらないことにしたタスク**（2026-11-27）：No.19（調整用の値の整理）・23（サウンドの残りの BGM）・27（同じ腕の合体・腕を奪う・柱で復帰）・28（ステージが崩れる・縮む）・40（ハサミ）・53（ほかのコントローラーの実機確認）は、管理者が一覧から消した。

## 2. AI（Claude・Codex）の使い方

- **共有フォルダ**（2026-10-23）：Claude と Codex は同じ `Proto1` を交代で使い、同時には作業しない。切り替える前にコミット・push と引き継ぎメモの更新をする。
  触るファイルが重ならないときだけ、Codex は別のフォルダ（git worktree）の別ブランチで同時に作業してよい（2026-11-13）。
- **分担**：実装とレビューの分担は、管理者が指定したときに決める。Notion の「委譲先」「レビュー担当」は当面使わず、担当欄も変えない。
  - 【当面】Claude の担当も Codex が行う（2026-10-27。Claude のトークンが少ないため。戻すのは管理者が言ったとき）。段階1 プラン → 段階2 コーディング → 段階3 テストに分ける。詳しくは `AGENTS.md`。
  - Codex はコードとテストのコードを書き、Debug のビルドが通ることだけ確かめる。テストの実行・Release のビルド・わざと壊す確認・画面の確認・修正は Claude が行う（2026-10-24）。
- **マージ**（2026-10-23）：AI がこの流れで作った PR は、テストとビルドが通れば、管理者に聞かずに `gh pr merge <番号> --merge --admin --delete-branch` でマージしてよい。ほかの人の PR はマージしない。
- **署名を付けない**（2026-11-16）：PR の「Generated with Claude Code」とコミットの `Co-Authored-By: Claude` は付けない（`.claude/settings.json` の `attribution` を空にしてある）。
- **ゲームの画面確認**（2026-11-12）：Codex がゲームを起動して管理者に知らせ、管理者が操作して確かめる。Computer Use は当面使わない。
- **Maya MCP**（2026-11-13）：クリップ作りのために、自由なコードの実行を許可している（`MAYA_MCP_ENABLE_RAW_EXECUTION`）。
- **ビルド**：MSBuild の場所は PC によって違う（Community と Enterprise がある）。`vswhere.exe` で探してから使う。一時フォルダ（%TEMP%）でビルドするときは `/t:Rebuild` を付ける。
- **Claude の許可**：自動モードの安全チェックがマージ・`start-work.ps1`・Notion の更新を止めることがあるので、管理者の PC だけ `.claude/settings.local.json`（GitHub には送らない）の `permissions.allow` に次を入れる。
  `PowerShell(gh pr merge:*)`・`Bash(gh pr merge:*)`・`PowerShell(.\tools\start-work.ps1:*)`・Notion の `notion-update-page`（ツール名の `mcp__〇〇__` は PC ごとに違う）。
  Visual Studio Enterprise の PC は設定済み、メインPC はまだ（作るときは管理者に確認する）。許可を足しても「先に確認する」決まりは変わらない。

## 3. コードの作り方

- **ゲームの部品はクラスで足す**（2026-10-27、No.44）：`src/game` の部品は `Game` が持つクラスにし、相手は `Initialize` で参照を受け取る（`g_〇〇` と外から呼ぶ自由関数は作らない）。データだけの構造体（定数バッファ・`VEC3`・`〇〇_PARAMS` など）と `core`・`input`・`render` は `struct` と関数のまま。手順は `docs/dev/01_DX11基盤の構成.md`。
- **時間**（No.4）：動きは「1秒にどれだけ × `GameTimeGetDeltaTime()`」で書く。1フレームは 1/60 秒で固定。
- **FBX は Assimp で読む**（2026-11-06）：授業で配られた Assimp 5.2.4（x64 の DLL）を `third_party/assimp` に入れる。`.obj` は自作の読み込みのまま。
- **コントローラーは外部ライブラリなしで読む**：Raw Input・HID・XInput・WinUSB だけを使う。ボタンは文字ではなく位置で合わせる（下 → ×、右 → ○）。Switch 2 Pro コンは USB だけ（2026-11-02）。
- **起動とデバッグの情報**（2026-11-04、No.83・84）：起動は最大化した枠ありのウィンドウ。全画面は `--fullscreen` と F11 / Alt+Enter のときだけ。ゲームは 16:9 のまま黒い帯を付けて真ん中に描く。
  デバッグの情報は ImGui などを使わず、プログラムで作る2つ目のウィンドウに出す（No.57）。**数値を変えるのはオプションの画面だけ**で、デバッグ用ウィンドウは情報を見るだけ（2026-11-16）。
- **マウス操作は止めてある**（2026-10-24）：ゲーム中にカーソルを取られないよう、`main.cpp` の `WM_ACTIVATE` の `MouseSetLock` と、`Update` の Tab の3行をコメントアウトしてある（左右クリックの腕は使える）。
  AI が画面確認でマウスが必要なときだけ一時的に戻し、終わったらコメントアウトに戻す（戻したものはコミットしない）。元に戻すのは管理者が言ったときだけ。

## 4. ゲームのルール

- **名前は「ブラキオンファイト」**（2026-11-16）：タイトル画面とタイトルバーに出す名前（英字は BRACHION FIGHT）。リポジトリ名・フォルダ名は Proto1 のまま。
- **試合**（2026-11-10）：スコア制（ストックなし）。相手を場外にしたら +1、落ちても減点なし。ルールはキャラ選択の画面で GAME / DEBUG を選ぶ（DEBUG は腕をいつでも切り替えられる）。
- **腕の拾い方**（2026-11-10）：腕は最初は持たず、そこら中に出るカプセルを拾って装着する。両手がふさがっていたら拾わない。素手は攻撃できず、腕のない見た目のまま。場外から復活すると両手とも素手に戻る。
- **腕の耐久**（2026-11-13）：腕は耐久（最大100）で、使い切ると崩壊する。当たった・外れた・強攻撃で減る量を腕ごとに変え、外しても減る。パリィでは減らず、パリィできなかったガードは50減る。値の表は `plan/06_腕の耐久/`。
- **腕は8本**：触手・ハンマー・ナックル・レーザー・刀・モーニングスター・槍・ミサイル（数字キー 1〜8）。C4・トゲ・ガンランスは消した（2026-11-16、No.164）。各腕の操作は `plan/03_新しいアームの仕様.md`。
- **操作はシンプルに**（2026-10-24）：腕はどれも「単押し」と「長押し」だけで使う。長押しは押している間ためて、離した瞬間に出す（2026-11-16、No.160）。
- **ガードとパリィ**（2026-11-12）：パリィ専用のボタンは作らない。左右の腕でガードし（Z / X、L2 / R2）、構えた直後に受けるとパリィで腕を失わない。
- **動き**（2026-11-12・16・19）：空中ジャンプとダッシュがある。ゲーム全体を速くした（移動・ジャンプ・ダッシュ・腕のためと休み。吹っ飛びの距離は変えない）。吹っ飛ばされてから % に比例した間（100% で 0.5 秒）は何もできないが、吹っ飛び中のダッシュは吹っ飛びの速度を 0 にしてふつうのダッシュをする。
- **復活**（2026-11-16）：場外から 1.5 秒で復活し、待つ間は場外にした相手を映す。GAME の復活の場所は相手が近くにいないランダムな点（DEBUG は最初の場所）。復活後2秒は点滅して攻撃を受けない。
- **エフェクトを作る**（2026-11-27）：プレイヤーの手ごたえのために、ヒットストップ・画ぶれ・パーティクルを足す（`plan/11_エフェクトと手ごたえ`）。ヒットストップは当てた人と当てられた人だけ止める（全員の PC で同じに計算する）。画ぶれはその2人の画面だけで、最後のカメラの位置に上乗せする（追従の計算を乱さない）。パーティクルは見た目だけなので通信の確かめに入れない。
- **CPU**（2026-11-18）：人と同じ入力を作る CPU にした（腕・カメラ・当たり判定は人と同じ）。オフラインだけで、オンラインの空き枠はダミー。

## 5. カメラと狙い

- **カメラは3つの状態**（2026-11-16、No.162）：F / R3 でハードロック → ソフトロック → フリーの順に切り替え、今の状態を画面に出す。ソフトロックは自由に回せて、画面に見えている相手を狙う。ロックオン中の攻撃は相手の高さへ当たる。
- **カメラの動き**（2026-10-24）：角度・高さ・距離・見ている点を別々の臨界減衰バネ（SmoothDamp）で追う（単純な Lerp は使わない）。小さな動き・ジャンプでは揺れない。
- **キャラの向き**（2026-10-24）：ロックオンしているときは相手を向き、いないときは進む向きを向く（モンハン式）。
- **フリーカメラの攻撃**（2026-11-13）：体の向き（使い始めた瞬間に左スティックを倒していればその向き）へ出し、攻撃中は体を回さない。足場のふち・刀のワープ先など地形を狙うものはカメラで狙う。ナックルの空中の突進は、カメラを上へ向けた分だけ斜め上へ出す（2026-11-16）。
- **触手で足場へ飛ぶのはフリーカメラの間だけ**（2026-11-10）：ロックオン中は相手か足場か分からないため。ただし場外から戻るときは、ロックオンのままでも足場に付ける。

## 6. 見た目

- **腕の取付位置と構え**（2026-10-27）：どの腕も共通の `Arm::GetShoulder`・`Arm::GetRestDirection` を使う。肩を少し後ろへ引き、待機の腕を左右に開く。右手は左手の鏡写し。
- **キャラの見た目の動き**（2026-11-07、No.90）：脚（体全体）は進む向き、上半身は狙う向き（ガンダムオンライン風。描画だけで、当たり判定と `m_Yaw` は変えない）。最初に選ばれるキャラとダミーは MekaGirl。
  触腕はアニメで振らず、節を物理でぶら下げる。付け根の箱は人の肩の可動域の中で振らせる（No.91）。
- **武器の攻撃アニメ**（2026-11-10、No.103）：攻撃中の武器は Maya の腕・手の骨の向きで描く（描画だけ）。左右の手は別の振り方にする。
- **メニューの見た目はポップな C 案**（2026-11-20、No.184）：ピンク・黄緑・紫の斜めの帯、太いふちとずらした影の見出し、選ぶと弾むボタン。背景はステージのまわりを回るカメラの3Dをぼかしたもの。ロゴや絵は、あとでチームが手で描いたものに置きかえてよい。

## 7. メニューと画面の流れ

- **流れ**（2026-11-18・24）：GAME START → 対戦方法 → キャラ選択 → マップ選択 → 試合 → 結果。
- **キャラ選択はスマブラ式**（2026-11-18、No.172）：参加した全員が1つの画面で、決定で参加 → 左右でキャラ → 決定で準備OK。全員が準備OKなら 1P（オンラインはホスト）の決定で開始。戻るで準備OKの取り消し → 参加をやめる。
  ルール（GAME / DEBUG）と、人のいない枠のキャラ・相手（ダミー / CPU よわい・ふつう・つよい。はじめは CPU ふつう）は 1P が選ぶ。結果から「キャラ選択へ」戻れる。
- **マップは 1P が選ぶ**（2026-11-24、No.189）：オンラインはホスト（＝1P）が同じ画面で選ぶ。「もう一度」は同じマップ。
- **試合中のメニュー**（2026-11-20、No.185）：オフラインで OPTIONS / R を押すと試合を止めて開く（再開する・ロビーに戻る・タイトルに戻る）。
- **メニューのパッド操作**（2026-11-20、No.187・188）：左スティックはカーソル（横に並ぶものは左右、縦に並ぶものは上下）を動かすだけ。十字キーは選んでいるものの中身（左右でキャラ・ルール・値、上下で強さ・IP の数値）を変えるだけで、カーソルは動かさない。キーボードは W A S D（と ↑ ↓）が左スティック、← → が十字キー。新しいメニューもこれに従う。
- **腕の切り替え（DEBUG）**：キーボードは Q / E で手を選んでから数字キー（数字だけで左手・Shift＋数字で右手も使える）。パッドは十字キー（← → で手、↑ ↓ で腕）。

## 9. オンライン対戦

- **つなぎ方**（2026-10-29）：IP を指定してつなぐ（NAT 越えは作らない）。離れた人とは Tailscale でつなぐ。中継サーバーは、Tailscale なしで遊びたくなったら足す。
- **しくみ**（2026-10-29、No.26）：1台に1人で自分だけの全画面。Winsock の UDP で入力だけを送り合うロックステップ。
- **入力の遅れ**（2026-10-30、No.49）：ホストが試合の開始時に ping から自動で決める（下限は 4）。起動の引数 `--delay` を付けたときは固定。
- **exe**（2026-11-02、No.56）：各自が同じ develop の版をビルドしてつなぐ。ホストはソースの中身の番号が違う参加を断り、Visual Studio の版の違いは警告だけにする。
- **IP 入力の Backspace**（2026-10-30）：入力があれば1文字消し、全部空ならモード選択へ戻る。パッドの×はいつでも戻る。
