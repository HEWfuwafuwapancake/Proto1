# DX11 基盤の構成

授業（DX21）のひな形をもとに、3D ゲームを作り始められるようにした土台です（`HEW2026GitTest` から、水のレイトレーシングを除いて持ってきたもの）。
起動すると、初期配置の浮島に半透明のおおいとタイトル・参加一覧・操作案内が出ます。○／Enterを押した機器が順に1P〜4Pとして参加し、参加済みの1Pがもう一度押すと試合になります。空きはダミーで、1人でも開始できます。試合は人数に応じて分割し、残り秒数・自分のKOと%・相手の%を出します。時間切れ後は1Pの決定でKO順位へ進み、RETRY / TITLEを選びます。
カメラは敵へロックオンする TPS カメラです（左右の弾きで対象を切り替え、角度・距離・注視点を別々のバネで追う。つかんでいる間・敵がいないときは自由に回せる）。

浮島・プレイヤー・ダミーは仮の形です。企画書（`docs/plan/`）に合わせて作り変えていきます。

## 操作
| 操作（キーボード＋マウス） | パッド（DUALSHOCK 4 / DualSense、USB） | 動き |
|---|---|---|
| W / A / S / D | 左スティック | 歩く（前 = カメラが向いている向き） |
| Space | × | ジャンプ |
| ← → / マウスを素早く左右へ | 右スティックを左右へ弾く | ロックオンする敵を、指定側の次の敵へ切り替える |
| マウスの上下 / ↑ ↓ | 右スティックの上下 | カメラを上下に回す。敵がいないとき・つかんでいる間は左右も自由に回せる |
| 左クリック / 右クリック | L1 / R1 | 左右の触腕（伸ばしてつかむ／もう一度で投げる） |
| R | OPTIONS | 1Pがやり直し（試合・結果から。参加者と装備は保つ） |
| W / S | 左スティックの上下 | 1Pが結果の項目を選ぶ（倒しっぱなしでは連続で動かない） |
| Enter | ○ | タイトルでその機器が参加、1Pの再入力で開始。試合後の決定も1P |
| V | SHARE / CREATE | 振動の ON / OFF（起動したときは OFF。ON にすると短く振動して知らせる。今の状態はタイトルバーに出る） |
| Tab | — | マウスのロック（カーソルを隠して見回す）の ON / OFF |
| ESC | — | 終了 |

**今はマウス操作を止めています**（2026-10-24、管理者の指示。カーソルを取られないように）。マウスのロックをしないので、
マウスでカメラを回す・ターゲットを切り替えることと、Tab は効きません（左右クリックの触腕は使えます）。
戻すときは `main.cpp` の `WM_ACTIVATE` の `MouseSetLock` と、`Update` の Tab の3行のコメントを外します。
戻したときは、ウィンドウを選ぶと自動でマウスがロックされ（カーソルが消える）、ほかのウィンドウに切り替えたときや終了確認が出たときは自動でロックが外れます。
浮島から落ちて場外に出ると、体と腕が消え、2秒後に浮島の真ん中へ0%で戻ります。
ダミーにぶつかると押せます。押して浮島から落とすと、2 秒後に最初の場所に 0% で戻ります（Debug ビルドでは出力ウィンドウに「ダミー〇：場外」「復活」と出る）。
触腕で敵をつかむと手元へ引き寄せ、同じボタンをもう一度押すとカメラの左右の向きへ水平に投げます。保持は3秒で解除され、投げると12%加算します。F1の仮攻撃は削除しました。

## フォルダ構成
| フォルダ | 入れるもの |
|---|---|
| `src/core/` | ウィンドウ・メインループ・DX11・シェーダーの読み込み・時間・デバッグ出力 |
| `src/input/` | キーボード・マウス・パッド、入力を「行動」に変える仕組み |
| `src/render/` | 形・2D・数字の表示など、描画の部品 |
| `src/game/` | プレイヤー・カメラ・ステージ・敵・触腕・試合の流れ |
| `src/physics/` | 当たり判定・吹っ飛びの計算（DirectX を使わない。単体テストする） |
| `shaders/` | シェーダー（`.hlsl` / `.hlsli`） |
| `tests/` | 単体テスト |
| `assets/models/` | モデル（OBJ。Git LFS）。元の Maya のファイルは `assets/models/source/`、書き出しは `tools/export-tentacle-obj.ps1` |

- `#include` は `src` からのパスで書く（例：`#include "core/dx11.h"`）。プロジェクトの設定で `src` をインクルードのフォルダにしてある。
- Visual Studio のソリューションエクスプローラーも、同じフォルダ分けで表示される（`.vcxproj.filters`）。
- 細かいルール（依存の向き・計算と描画を分ける・調整用の値）は `CLAUDE.md` の「コードの構成」。

## 腕の共通の仕組み・腕の足し方（No.35）

- `src/game/arm.h / .cpp` に、片手の腕の基本クラス `Arm`（純粋仮想関数 `Update(bool trigger)`・`Draw()`・`Reset()`・`IsActive()`・`IsHolding()`）と、左右の装備を持つ `ArmManager` がある。`ArmManager` は起動時に左右それぞれ全種類の腕を `ARM_FACTORIES`（腕の種類 → `CreateArm<腕のクラス>`、未実装は `nullptr`）から作って持ち、装備している腕だけを更新・描画する。
- 腕が使う相手（`FighterManager`・自分のスロット番号・カメラ・ステージ）は `ARM_LINKS` にまとめて `Arm(int hand, const ARM_LINKS& links)` で受け取り、派生クラスは `protected` の `GetPlayer()`（自分の`Fighter`）・`GetFighters()`・`GetSlot()`・`GetCamera()`・`GetStage()` で使う。候補は`GetTarget(相手のスロット, GetSlot())`、攻撃・保持操作にも自分のスロットを渡す。肩の位置 `GetShoulder()`・待機の向き `GetRestDirection()`・左右と効いている間の色 `GetColor()`・モデル1個の配置 `DrawPiece()`・右手の X を鏡写しにして読む `LoadModel()` も `Arm` の `protected` で共通にする（値と計算は `arm.cpp`）。
- `src/physics/armcalc.h / .cpp` は使える腕の直接選択（DirectX なし）。`nullptr` の種類は選べない。Q（左手）・E（右手）で切り替えモードに入り、続けて 1〜6 でその手を選ぶ（同じキーでモードを抜ける。計算は `input/actioncalc` の `ActionCalcEquipKey`、キーは `action.cpp` の「調整用の値」）。既存の数字だけ／Shift＋数字による左手／右手の直接選択も残す。パッドの十字キー・□・○ で腕は切り替えない（○ はメニューの決定）。装備と切り替えモードはタイトルバーに出す。
- `ArmManager::Update(試合中か)` は試合シーンで、カメラとキャラの向きの更新後に呼ぶ（`Game::Update`）。装備切り替えは時間切れ後も受け付け、腕の更新は試合中だけ左→右の順。切り替える手は今の腕を `Reset()` してから付けかえる（敵はダメージなしで離す）。`ArmManager::Reset` は装備を変えない。
- No.25：F1〜F4で腕の切り替え先（1P〜4P、初期は1P）を選ぶ。Q / E と数字・Shift＋数字は選んだ人のスロットだけに届く。`ActionGetEquipKey(player)`・`ActionGetEquipMode(player)`はスロット0〜3を受け取り、省略時は1P。切り替えモードはスロットごとに持ち、`ActionGetEquipPlayer()`で選択先を読む。腕の振動は`Arm::Rumble`から本人のパッドへ出し、キーボードの人の腕では振動しない。ライトバーは`Game::UpdatePadLights`で1P赤・2P青・3P緑・4P黄にし、未参加は消灯する。色の値は`Fighter::GetPlayerColor`で体・HUDと共用する。
- **腕を足すとき**：
  1. `src/game/arm_〇〇.h / .cpp` に `Arm` を派生したクラス（例：`MagnetArm`）を作る。コンストラクタは `(int hand, const ARM_LINKS& links)` で `Arm(hand, links)` を呼び、モデルを `LoadModel` で読んで `Reset()` する。5つの純粋仮想関数を `override` する。状態は `private` の `m_〇〇` に持つ（1インスタンスが1本の手）。
  2. `arm.cpp` の `ARM_FACTORIES` の該当行を `CreateArm<MagnetArm>` に置き換える（`#include` も足す）。ほかの腕のファイルは変更不要。

## プレイヤーとカメラ
- `main.cpp`の`ActionUpdate`のあとに`Game::Update`を呼ぶ。タイトルでは全機器の決定を`JoinOrStart`へ渡し、試合開始時に`ConfigurePlayers`で機器と画面を割り当てる。試合は`Stage` → `FighterManager::Update`（全員の体・場外とKO・体当たり）→ 人ごとの`Camera::Update` → `FighterManager::UpdateFacing` → 人ごとの`ArmManager::Update` → `SceneCalc::Step` → `Match::Update`。時間切れ後は体と腕を止め、カメラと装備切り替えは受け付ける。RETRYは`Restart`、TITLEは参加を消して`ConfigurePlayers`。タイトル・結果では試合の時間を止める。ライトバーは全シーンで参加者に合わせる。
- ダミーの体の動き（重力・着地）は、プレイヤーと同じ `PlayerBodyCalc::Step` に「歩かない・ジャンプしない」を渡して動かしている。
- 人とダミーの体は、足元から作った縦のカプセル（`DummyCalcBodyCapsule`）どうしで当たり判定をする。人対ダミーは従来どおり横からダミーだけを押す。人対人は横の押し出しを半分ずつ受け、頭に乗ったときは上の体を押し上げる（`VersusCalcPushBodies`）。復活待ち・保持中・吹っ飛び中・引っぱられ中の体は体当たりから除く。
- プレイヤーの移動の向きは、カメラの左右の向き（`Camera::GetYaw()`）で決める。W（左スティックを上）で、カメラが向いている向きへ歩く。
- キャラの左右の向きは `Fighter::GetYaw()`。ターゲットがいればターゲットへ、いなければ歩く方向へ `TURN_SPEED` の上限つきで回る。対象も移動もなければ最後の向きのまま。腕のボタンを押した瞬間、または `ArmManager::IsActive()`（触腕なら伸長・保持・収縮中）が true の間は、更新後のカメラの正面へ即座に向く。肩の球はキャラの向きで置く。No.30 の伸長方向は下の「触腕」を参照。投げる方向はカメラの正面へ水平にする。
- 動きの計算は `PlayerBodyCalc::Step`（`physics/playercalc.h`）：横の速度 → ジャンプ（立っているときだけ）→ 重力 → 着地（浮島の上の面を上から通り過ぎたときだけ）。浮島の横の面とはぶつからない。
- カメラ（No.29 のバネと No.33 のロックオン）は、毎フレーム次の順に動く（計算は `physics/cameracalc.h`）。
  - 最初に自分を候補から除き、相手の生存・場外・保持状態を調べる。開幕・やり直し・対象が消えたときは `CameraCalcPickFocus` で正面に最も近い相手（全周・距離無制限）を選ぶ。左右の弾きは `CameraCalcNextTarget` で対象への向きを基準に指定側の最小角を選ぶ。保持中は対象を退避して自由カメラへ、解放後は退避した相手、選べなければ正面の相手へ戻る。`Camera::GetTarget()` はロック中の相手のスロット番号（0〜3で自分以外）、なし・保持中は-1。
  - ロックオン中は、以下の自由カメラの手順1の左右角を敵への水平角に、手順3の注視点の目標を `CameraCalcFocusPoint` に置き換える。上下は手動。切り替え後 `SWITCH_TIME` の間は角度のバネに `SWITCH_SMOOTH_TIME` を使い、速度を持ち越す。ジャンプ中の接地高さの保持は共通。
  - 対象がいないとき・保持中は次の自由カメラとして動く。
  1. 手動入力を左右・上下の目標角度へ足す（上下は -35°〜0°）。試合中は横入力に比例して左右の目標角度を回す（sway）。手動操作後は `MANUAL_PAUSE` 秒止める
  2. 左右・上下の角度を別々の臨界減衰バネ（`CameraCalcSmoothDampAngle` / `CameraCalcSmoothDamp`）で追う。速度は呼ぶ側で値ごとに保持する
  3. 注視点の XZ は `LOOK_DEADZONE` を超えた分だけ目標を動かす。Y は `Fighter::IsOnGround()` で最後に立っていた足元＋頭の高さを記憶し、ジャンプ中は変えない。足元が浮島の上面より下へ落ちたら落下を追う。XZ・Y を別のバネで追う
  4. 注視点からカメラへの線が浮島にぶつかるなら、ぶつかる手前（面から `STAGE_MARGIN`）まですぐ近づける（`CameraCalcClipToStage`）。離れるときだけ距離のバネで戻す
  5. 追った角度・距離と注視点から `CameraCalcOrbitPosition` で位置を出す。復活・やり直しではバネを使わず目標へ合わせ、速度をすべて0にする
- カメラは浮島としかぶつからない。ダミーなどは通り抜けて見える。

## 描画の順番（`main.cpp` の `Draw` → `Game::Draw`）
1. `Clear()` で画面と深度バッファを消す
2. 人ごと（`Game::Draw`）：`SetViewport`（範囲は `VersusCalcViewport`。1人は全画面、2人は左右、3〜4人は4分割）のあと、
   - **3D**：`SetDepthEnable(true)` → その人の `Camera::Draw()` → ライトON → 浮島・全員の体・全員の腕を描く
   - **2D（UI）**：`SetDepthEnable(false)` → ライトOFF → その人の `Hud::Draw()`（`Shader_Set2DSize` で 1280×720 の座標を縦横同じ倍率でその画面に当てはめる）
3. 画面全体に戻し、3人のときの空きを黒で塗り、`Hud::DrawScene()`（タイトル・結果のおおい）を重ねる
4. `Present()` で画面に出す（垂直同期あり。`dx11.cpp` の `VSYNC` で切り替えられる）

## メインループ（`main.cpp` の `WinMain`）
- `Update` と `Draw` は **1秒に60回**（17・17・16ミリ秒の間隔を繰り返す）。待っている間は `Sleep(1)` で休むので、CPU をほとんど使わない
- 来ているウィンドウメッセージ（マウスの移動など）は、毎回全部処理してからフレームを進める
- **タイトルバーに FPS** が出る。60 より下がっていたら、処理が重くて間に合っていない
  （1フレームの秒数は 1/60 秒で固定しているので、FPS が下がるとゲーム全体がゆっくりになる）
- **垂直同期**（`dx11.cpp` の `VSYNC`）：モニターの書き換えに合わせて表示するので、画面のちらつき（ティアリング）が出ない

## 時間の使い方（`src/core/gametime.h`）
- `main.cpp` の `Update` の最初で `GameTimeUpdate()` を呼び、時間を1フレーム分進める。
- 動きは **「1秒にどれだけ進むか × `GameTimeGetDeltaTime()`」** で書く（例：`playercalc.cpp` の移動。`body.X += body.VelocityX * dt`）。
  こう書いておくと、`GameTimeSetScale(0.0f)` で時間を止めたとき（ヒットストップ）に動きも止まる。
- 1フレームの秒数は 1/60 秒で固定（実際にかかった時間ではない）。同じ操作で毎回同じ結果になり、吹っ飛びなどの計算が安定する。
- 「○秒たったら」は `TIMER` を使う：`TimerStart(timer, 90.0f)` → 毎フレーム `TimerUpdate(timer, GameTimeGetDeltaTime())` → `TimerIsFinished(timer)`。
- カメラを回す速さ（矢印キー・右スティック）も「1秒に何度 × dt」。マウスは動かした量そのまま（dt を掛けない）。
  そのため、`GameTimeSetScale(0.0f)` で時間を止めると、矢印キーと右スティックでは回らなくなる（マウスでは回る）。

## 気をつけること
- **ポリゴンの表は時計回り。** 見る側から見て頂点が時計回りに並んでいない面は描かれません（バックフェースカリング）。
- **シェーダーの定数バッファ**は `shader.h` / `shader.cpp` の構造体と `shaderCommon.hlsli` の並びをそろえること。片方だけ変えると色や位置がおかしくなります。

  C++ のファイル（`.cpp` / `.h`）は **BOM付きUTF-8**。
- ビルドすると `.cso`（コンパイル済みのシェーダー）がプロジェクトのフォルダにできます（Git には入れない）。
  exe を直接ダブルクリックすると .cso が見つからずエラーになるので、Visual Studio から実行してください。

## PS5 コントローラー（No.46）

## 当たり判定の使い方（`src/physics/collision.h`）
- 形は3つ：`SPHERE`（中心・半径）、`CAPSULE`（線分の両端・半径。プレイヤー・ダミーは縦、触腕は斜め）、`BOX`（向きなしの直方体。浮島）。
- `CollisionSphereSphere` / `CollisionSphereCapsule` / `CollisionCapsuleCapsule` / `CollisionSphereBox` は `HIT_RESULT` を返す。
  `Hit` が true なら、1つ目の形を `Normal` の向きに `Depth` だけ動かすと離れる（重ならないように押し出すときに使う）。ちょうど触れているだけなら `Hit` は false。
- 攻撃（触腕など）は、始めるときに `HitRecord::Clear`、当たったら `HitRecord::TryAdd(相手の番号)` が true のときだけダメージや吹っ飛びを与える（同じ攻撃で2回当たらない）。

## 触腕（No.13）
- `src/game/tentacle.h / .cpp`：`TentacleArm`（`Arm` の派生）。`ArmManager` から渡される片手の入力、敵との連携、OBJ をつないで揺らす描画（読み込み失敗時は球）。最大長8、伸長24/秒、収縮30/秒、保持3秒、投げ12%・強さ2を調整用定数で管理する。パッドの振動（伸びる間は最大・つかむ・投げる）もここから `PadRumble` で出す。

- No.30 の伸長方向は、押した瞬間の `Camera::GetTarget()` があれば各肩から対象カプセルの中心へ、なければカメラ正面へ水平に固定する。`TentacleCalcAim` で高さを除いて正規化し、水平距離がほぼ0ならカメラ正面を使う。対象が遠くても向けるが最大長8は変わらず、伸長中は追尾しない。投げる方向は再入力時の `Camera::GetYaw()` から作る水平の向きを使う。
- 左腕の後に右腕を処理し、`FighterManager::Grab` の保持状態で二重つかみを防ぐ。`HitRecord` は1回の伸長ごとにリセットする。
- `FighterManager::Update` は保持中の通常物理を止める。`TentacleArm::Update` はカメラ更新後に保持位置を決め、`FighterManager::MoveHeld` で反映する。

- 投げは `FighterManager::Release` → `FighterManager::Hit` でダメージ・速さを計算し、`KnockbackCalcDirectedVelocity` で上下を含む方向へ飛ばす。通常攻撃の固定角の計算は維持する。
- 最大距離または浮島に達した空の腕は戻る。保持する敵は半径・半高で拡張した浮島の箱を越えない位置に止める。

## 参加と結果（No.25 段階D）

## 試合の流れ（No.14）
- `src/game/match.h / .cpp`：`Match`（制限時間・得点・時間切れ）。やり直しは `Game::Restart`。`src/physics/matchcalc.h / .cpp`：得点・時間・状態の計算（DirectX なし）。
- `VersusCalc`が最後の攻撃者を記録し、体の場外イベントでその人に+1する。人対人・人対ダミーは同じ。未攻撃の自滅とダミーの攻撃では加点しない。場外で攻撃記録を消し、次の復活へ持ち越さない。`Grab`・`AddDamage`・`Hit`・`Launch`・`Push`が攻撃記録を更新し、通常の体当たりは更新しない。全員のKO合計を`MatchCalc`へ渡して得点イベントと制限時間を扱い、HUDと結果は個人の`FighterManager::GetScore(slot)`を読む。同時に2体落とせば+2。時間切れと同じフレームのKOも入る。時間切れ後は体を更新しないので得点も止まる。落ちた人の減点はない。
- 時間切れ：`Match` が `ArmManager::Reset()`（つかんでいる敵を離す）→ 状態が「時間切れ」→ 次のフレームから、プレイヤー・ダミー・腕の動きが止まる（カメラは回せる。装備切り替えは受け付ける）。
- やり直し（OPTIONS / R。いつでも）：`Game::Restart` で、腕 → 全員の体とKO・攻撃記録 → カメラ → 試合（制限時間と表示得点）の順に`Reset()`。機器の割り当て・`GameTime`・装備は戻さない。
- 残り時間・スコアは画面に出る（下の「画面表示（No.15）」）。タイトルバーは FPS・左右の装備・振動のオン／オフ。Debug では出力ウィンドウにも得点・時間切れ・やり直し・装備の変更が出る。
