# DX11 基盤の構成（プログラムの手引き）

Proto1 のプログラムがどう分かれていて、新しいものをどう足すかの手引きです。コードを書くときに読みます。
授業（DX21）のひな形をもとにした土台です（`HEW2026GitTest` から、水のレイトレーシングを除いて持ってきた）。

- **フォルダの決まり・依存の向き・コメントの書き方**は `CLAUDE.md` の「コードの構成」「コードの約束」にあります。
- **仕組みの細かい記録**（タスクの番号ごとに、どの関数が何をするか）は [05_仕組みの詳細.md](05_仕組みの詳細.md) にあります。ここには、足すときに必要なことだけを書きます。
- 操作の一覧は [05_操作一覧.md](../team/05_操作一覧.md)、起動の引数は [04_コマンド一覧.md](../team/04_コマンド一覧.md) の6節。

## 起動から試合までの流れ

1. `src/core/main.cpp` がウィンドウと基盤（DX11・シェーダー・入力・音など）を作り、ゲームの中身である `Game`（`src/game/game.h`）を1つだけ持つ。
2. 画面は **タイトル → 対戦方法（SOLO・LOCAL VS・ONLINE HOST・ONLINE JOIN）→ キャラ選択（ルールもここで選ぶ）→ マップ選択 → 試合 → 結果** と進む。
   - 画面の移り変わりは `physics/scenecalc`、試合以外の画面の描画は `game/codex_menu`、試合中の表示は `game/hud`。
3. 試合では、4つの枠（1P〜4P）に人・CPU・ダミーが入る。人の数に合わせて画面を分ける（オンラインは自分だけの全画面）。

## 1フレームの流れ

### メインループ（`main.cpp` の `WinMain`）
- `Update` と `Draw` は **1秒に60回**（17・17・16ミリ秒の間隔を繰り返す）。待っている間は `Sleep(1)` で休むので、CPU をほとんど使わない
- 来ているウィンドウメッセージ（マウスの移動など）は、毎回全部処理してからフレームを進める
- **タイトルバーに FPS** が出る。60 より下がっていたら、処理が重くて間に合っていない
  （1フレームの秒数は 1/60 秒で固定しているので、FPS が下がるとゲーム全体がゆっくりになる）
- **垂直同期**（`dx11.cpp` の `VSYNC`）：モニターの書き換えに合わせて表示するので、画面のちらつき（ティアリング）が出ない

### 時間の使い方（`src/core/gametime.h`）
- `main.cpp` の `Update` の最初で `GameTimeUpdate()` を呼び、時間を1フレーム分進める。
- 動きは **「1秒にどれだけ進むか × `GameTimeGetDeltaTime()`」** で書く（例：`playercalc.cpp` の移動。`body.X += body.VelocityX * dt`）。
  こう書いておくと、`GameTimeSetScale(0.0f)` で時間を止めたとき（ヒットストップ）に動きも止まる。
- 1フレームの秒数は 1/60 秒で固定（実際にかかった時間ではない）。同じ操作で毎回同じ結果になり、吹っ飛びなどの計算が安定する。
- 「○秒たったら」は `TIMER` を使う：`TimerStart(timer, 90.0f)` → 毎フレーム `TimerUpdate(timer, GameTimeGetDeltaTime())` → `TimerIsFinished(timer)`。
- カメラを回す速さ（矢印キー・右スティック）も「1秒に何度 × dt」。マウスは動かした量そのまま（dt を掛けない）。
  そのため、`GameTimeSetScale(0.0f)` で時間を止めると、矢印キーと右スティックでは回らなくなる（マウスでは回る）。

### 入力の使い方（`src/input/action.h`）
- ゲームの側は、キーやボタンではなく **行動**（`ACTION_JUMP` など）を見る。キーボードでもパッドでも同じように動く。
- `Game` が毎フレーム、機器ごとの入力を `PLAYER_INPUT` にまとめて各枠へ配る（オンラインでも同じ形で送る）。体と腕は `Fighter::IsPress`・`IsTrigger`・`GetMoveInput` で読む。
- 行動は通信で送るボタンのビットを兼ねていて、**16 個で使い切っている**。足すときは `PLAYER_INPUT::Buttons` と `lockstepcalc` の通信の形も変える。
- キーとボタンの割り当ては `action.cpp` の `ACTION_KEYS`・`ACTION_PAD_BUTTONS`。変えたら [05_操作一覧.md](../team/05_操作一覧.md) と `hud.cpp` の `CONTROL_GUIDE_LINES` もそろえる。

### 試合中の更新の順番（`Game::UpdateFrame`）
CPU の入力を作る → `Stage` → `FighterManager::Update`（全員の体・場外と KO・体当たり）→ 腕カプセル → 人ごとの `Camera::Update` → `FighterManager::UpdateFacing`（体の向き）→ 人ごとの `ArmManager::Update` → `SceneCalc::Step` → `Match::Update` → HUD。

### 描画の順番（`main.cpp` の `Draw` → `Game::Draw`）
1. `Clear()` で画面と深度バッファを消す
2. 人ごと（`Game::Draw`）：`SetViewport`（範囲は `VersusCalcViewport`。1人は全画面、2人は左右、3〜4人は4分割）のあと、
   - **3D**：`SetDepthEnable(true)` → その人の `Camera::Draw()` → ライトON → 浮島・全員の体・全員の腕を描く
   - **2D（UI）**：`SetDepthEnable(false)` → ライトOFF → その人の `Hud::Draw()`（`Shader_Set2DSize` で 1280×720 の座標を縦横同じ倍率でその画面に当てはめる）
3. 画面全体に戻し、3人のときの空きを黒で塗り、`Hud::DrawScene()`（タイトル・結果のおおい）を重ねる
4. `Present()` で画面に出す（垂直同期あり。`dx11.cpp` の `VSYNC` で切り替えられる）

## 新しいオブジェクトを足すとき
`fighter.h / .cpp`（`Fighter` クラス）の寿命・更新・描画の分け方を参考にして作ります。

1. クラスを作り、メンバー関数 `Initialize / Reset / Finalize / Update / Draw` を持たせる。状態は `private` の `m_〇〇`、読むのは `GetXxx() const`。ファイルの中の `g_〇〇`（グローバル変数）や外から呼ぶ自由関数は作らない
   - ほかの部品を使うときは、`Initialize` の引数で参照を受け取ってポインタのメンバー（読むだけなら `const Camera* m_Camera` など）に持つ。`Initialize` は参照を持ってから `Reset()`（状態を最初に戻す）を呼ぶ。`Initialize` の中では、先に初期化された相手だけを使う
   - コンストラクタでは DirectX を使わない（`main.cpp` の `g_Game` は `WinMain` より前に作られる）。モデルの読み込みなどは `Initialize` で行う
2. `src/game/game.h` の `Game` のメンバーに足し、`Game` の `Initialize`（相手より後ろの順）・`Finalize`（逆順）・`Update`・`Draw` から呼ぶ。R のやり直しで戻すなら `Game::Restart` で `Reset()` を呼ぶ。`main.cpp` は変えない
3. 箱・球・カプセルの仮の形なら、`Draw` で `ShapeDrawBox` / `ShapeDrawSphere` / `ShapeDrawCapsule`（`render/shape.h`）を呼ぶだけで描ける
   - ほかの形を自分で描くときは、`shape.cpp` のように次の順番で設定してから描く：
     `Shader_SetWorldMatrix(...)`（拡大縮小 → 回転 → 移動 の順に掛ける）→ `Shader_SetMaterial(...)`（色）→ 頂点バッファ（とインデックスバッファ）をセットして `Draw` / `DrawIndexed`
4. 動きの計算（当たり判定・速さなど）は `src/physics/` に DirectX を使わないファイルとして分け、単体テストする（`playercalc` が見本）
5. ファイルを Visual Studio のプロジェクトに追加する（`.vcxproj` が変わるので一緒にコミット）
6. クラスと `public` なメンバー関数には Doxygen 形式（`/// @brief`）の日本語コメントを付ける

物を浮島の上に置きたいときは、`Stage::GetStage().TopY`（浮島の上の面の高さ）を y に入れます。浮島の範囲の中かは `StageCalcIsOnPlatform`、その高さに足場（浮島・高台）があるかは `StageCalcHasSupport` で調べます。

## 腕を足すとき

まず次の4つをやり、そのあと下の「腕の書き方」を守って中身を書きます。共通の部品（段階・扇・飛び道具・状態異常・ガード）の使い方は [05_仕組みの詳細.md](05_仕組みの詳細.md) の「腕の共通の仕組み」。

1. `src/game/arm_〇〇.h / .cpp` に `Arm` を派生したクラス（例：`HammerArm`）を作る。コンストラクタは `(int hand, const ARM_LINKS& links)` で `Arm(hand, links)` を呼び、モデルを `LoadModel` で読んで `Reset()` する。5つの純粋仮想関数を `override` する。状態は `private` の `m_〇〇` に持つ（1インスタンスが1本の手）。
2. `arm.cpp` の `ARM_FACTORIES` の該当行を `CreateArm<〇〇Arm>` に置き換える（`#include` も足す）。ほかの腕のファイルは変更不要。
3. 動きの計算は `src/physics/〇〇calc.h / .cpp` に DirectX なしで置き、テストを書く（`ArmPressCalc` が見本）。
4. 新しいファイルを `.vcxproj`・`.vcxproj.filters` に登録する（計算の `.cpp` はテストのプロジェクトにも「既存の項目」で足す）。

### 腕の書き方（No.59〜82 で決めた。新しい腕はここを守る）

**ファイルとクラス**

- 1本の腕 ＝ `src/game/arm_〇〇.h / .cpp` の `Arm` の派生クラス `〇〇Arm`（例：`HammerArm`）。1インスタンスが片手1本。左右それぞれ全種類を起動時に作り、装備の切り替えでは作り直さない（`ArmManager`）。
- その腕だけの計算（状態の流れ・連鎖の選び方など）は `src/physics/〇〇calc.h / .cpp` の DirectX・Windows なしのクラス `〇〇Calc` か関数 `〇〇Calc〜` に置き、`tests/Proto1Tests/〇〇calc_test.cpp` でテストする。**共通の計算（No.59 の `ArmPhaseCalc`・`AreaCalc`、No.70 の `ProjectileCalc` など）だけで足りる腕は、`〇〇calc` を作らない**（中身のないファイルは作らない）。
- 登録：`arm.h` の `ARM_TYPE` で該当の枠を確認し、`arm.cpp` の `ARM_FACTORIES` の行を `CreateArm<〇〇Arm>` にする。新しいファイルは `Proto1.vcxproj`・`.vcxproj.filters`（`src\game` / `src\physics` のフィルター）に、計算の `.cpp` はテストのプロジェクトにも「既存の項目」で足す。
- 依存の向き：`physics` は `game` を使わない。腕から相手をさわるのは `GetFighters()`（`FighterManager`）の関数だけ。`Fighter` の中を直接書き換えない。

**クラスの形**（`arm_hammer.h / .cpp` が見本）

```cpp
// arm_hammer.h
#pragma once

#include "game/arm.h"
#include "physics/armphasecalc.h"

/// @file arm_hammer.h
/// @brief 片手のハンマーの入力・叩きつけと描画

/// @brief 振り上げてから前の足元を叩き、まわりの相手を打ち上げる腕（遅いが強い）
class HammerArm : public Arm
{
public:
	/// @brief 待機状態にする（モデルはないので読み込まない）
	/// @param hand 左 0・右 1
	/// @param links 腕が使うゲームの部品への参照
	HammerArm(int hand, const ARM_LINKS& links);
	/// @brief 振り上げ・叩き・休みを進め、叩きに入ったフレームに着いた所のまわりへ効かせる
	/// @param input このフレームの腕の入力（単押しで攻撃する）
	void Update(const ARM_INPUT& input) override;
	/// @brief 仮の形（腕・柄の円柱と頭の箱）を、振り上げ・叩きに合わせて上下させて描画する
	void Draw() override;
	/// @brief 待機へ戻す
	void Reset() override;
	/// @brief 待機以外なら true を返す
	bool IsActive() const override;
	/// @brief 敵をつかまないので、常に false を返す
	bool IsHolding() const override;
	/// @brief 振り上げ・叩き・休みの間だけ歩く速さを下げる
	float GetMoveScale() const override;

private:
	ArmPhaseCalc m_Phase;
	VEC3 m_Direction = { 0.0f, 0.0f, 1.0f }; // 叩く水平の向き。
	float m_Straighten = 0.0f; // 描画だけのまっすぐ度（0：待機、1：叩く向き）。
};
```

- 状態は `private` の `m_〇〇`。外から読むものは `GetXxx() const`。`g_〇〇`・外から呼ぶ自由関数は作らない。
- コンストラクタは `Arm(hand, links)` を呼び、モデルがあれば `LoadModel` で読んで、最後に `Reset()`。DirectX を使う初期化はコンストラクタでしてよい（`ArmManager::Initialize` から作られるため。`g_Game` の構築時ではない）。
- `Update(const ARM_INPUT&)` の順番：① `dt = fmaxf(0.0f, GameTimeGetDeltaTime())` ② 計算クラスの `Step`（取りやめは `GetPlayer().DidRespawn()`）③ 当たりを調べて `GetFighters()` の関数で効かせる ④ 振動 `Rumble` ⑤ 描画だけの値（`m_Straighten` など）を進める。
- `Draw()` は状態を変えない（`const` でなくても、描くだけにする）。
- `Reset()` は保持・引っぱりなど相手に残した状態を戻す（装備切り替え・時間切れ・やり直し）。吹っ飛びやしびれによる中断は `Interrupt()` を通る。
- 歩く速さを変える腕は `GetMoveScale()` を `override` する（構え中だけ 0.4 など）。ジャンプの速さは変えない。

**調整用の値**

- その腕の `.cpp` の先頭の「// 調整用の値」に `static constexpr` で全部まとめる（秒数・距離・半径・ダメージ・強さ・振動）。計算に渡す値は `〇〇_PARAMS` 構造体にまとめる。
- 吹っ飛ぶ速さ ＝（4 ＋ % × 0.06）× 強さ（0% で強さ2なら 8 m/秒。`knockbackcalc.cpp`）。新しい腕の値は、プランで決めた初期値から始める。

**狙い・当たり・効かせ方**（No.59 で `Arm` に足す共通の関数を使う。腕ごとにコピーしない）

- 肩は `GetShoulder()`、待機の向きは `GetRestDirection()`、キャラの正面は `GetForward()`（No.59）。
- 狙いは `GetAim(keepHeight)`（No.59）：ロックオン中は肩から相手の体の中心へ、いなければ画面の正面へ水平。`keepHeight` が true なら上下も含める（`GrappleCalcAim`）、false なら水平だけ（`TentacleCalcAim`。**高さを捨てる**ことに注意）。近接は false、射撃は true が基本。
- 当たり：相手は `for (int i = 0; i < FIGHTER_COUNT; ++i)` で `GetFighters().GetTarget(i, GetSlot())` を読み、`Available` が false なら飛ばす（自分・復活待ち・ほかの人につかまれている相手は false）。形の判定は `collision.h` と `AreaCalc`（No.59）。1回の攻撃で同じ相手に2回効かせないときは `HitRecord`。
- 効かせ方（全部 `FighterManager`。攻撃した人が記録され、場外にしたら得点になる）：

| したいこと | 関数 |
|---|---|
| % を足して吹っ飛ばす（向きは上下を含めて自由） | `Launch(i, GetSlot(), 向き, ダメージ, 強さ)` |
| % だけ足す（小刻みの攻撃） | `AddDamage(i, GetSlot(), ダメージ)` |
| % を変えずに一定の速さで押す | `Push(i, GetSlot(), 速度)` |
| つかむ・動かす・離す（投げる） | `Grab` / `MoveHeld` / `Release` |
| しびれ・遅く・燃える・隠れる | `ApplyStatus`（No.75） |
| ガードを崩す | `BreakGuard`（No.80） |
| 自分の % を減らす | `Heal`（No.69） |

- 吹っ飛ばす向きは「水平の向き ＋ 少し上」を正規化して使う（`AreaCalcLaunchDirection(向き, 上)`、No.59）。
- No.80 のあとは、`Grab`・`Hit`・`AddDamage`・`Launch`・`Push`・`ApplyStatus` の先頭の引数に「攻撃が来た位置」（近接は自分の肩、飛び道具は弾の位置、爆発は爆心）を渡す。ガードされたら false が返る。

**オンライン対戦で同じに動かすための約束**（No.26 のロックステップ。破ると DESYNC）

- 腕の動きは入力（`ARM_INPUT`・`GetPlayer()` の入力）と `GameTimeGetDeltaTime()` だけで決める。`rand`・時計・`ActionGet〜` の直接読み取り・描画の結果を、動きの計算に使わない。ばらつきが欲しいとき（ガトリングの弾のぶれなど）は、撃った回数から決まる決まった並びを使う。
- カメラ（`GetCamera()`）は各スロットの入力から全員の PC で同じに動くので、狙いに使ってよい（今の腕と同じ）。
- 回転の見た目（ガトリングの銃身など）だけに使う値は、描画の中で `GameTimeGetElapsed()` から作ってよい。

**描画（仮の形）**

- モデルのない腕は `DrawStubArm(向き, 長さ, 色)`（No.59。肩から円柱を描き、手の位置を返す）＋ `ShapeDrawBox` / `ShapeDrawSphere` / `ShapeDrawCylinder` で武器を描く。色は `GetColor(効いているか)`（左右の色と、効いている間のオレンジ）。
- 待機は `GetRestDirection()`、構え・攻撃は狙いの向きへ、描画だけの「まっすぐ度」を 0.1 秒で 0↔1 に進めて `ArmCalcBlendDirection` でまぜる（今の腕と同じ）。
- 当たり範囲の表示は、その腕のメンバーに残り秒数を持ち、`Draw` で描く。
- モデルができたら `LoadModel` と `DrawPiece` に替える（OBJ は読み込みで Z が反転する。曲がった形は `MODEL_ROLL` が要ることがある。開発ログの「磁石の腕をひねり 0 で描き〜」）。

**コメント・文字コード**

- クラス・`public` なメンバー関数・ヘッダーの関数と構造体に Doxygen 形式の日本語コメント（`/// @brief`）。bool の引数は「〜を設定する（true：〜、false：〜）」、構造体はメンバーを全部説明する。
- `.cpp` / `.h` は BOM付きUTF-8・CRLF。文字列は CP932 で表せる文字だけ（波ダッシュなどは使わない）。

**テストと確かめ方**

- 計算のファイルを足したら、主な動きだけをテストする（端っこ・おかしな入力だけのテストは足さない）。1/60 秒刻みで時間を進めたときの時間切れも1つ確かめる（開発ログの「盾の2秒タイマー」）。新しい計算のファイルは、まとめて1回わざと壊してテストが失敗するのを確かめる。
- 段階3（Claude）：`run-tests.ps1`（Debug / Release）・Debug / Release のビルド警告 0・画面確認（見た目が変わるので、腕ごとに1回。タイトルバーの装備名がその腕になってから撮る）。
- 使い回す既存の関数は、プランに書く前・使う前に中身を読む（開発ログの「プランで使う関数を名前だけで決め〜」）。

## 効果音の足し方（`src/audio/se.h`）
- 鳴らすだけなら、鳴らしたい所で `SePlay(SE_HAMMER_TAP);`（`#include "audio/se.h"`）。候補が複数ある音（`(1)` `(2)` 付き）は、鳴らすたびにランダムに1つ選ぶ。
- 途中で止めたい音（レーザーの溜め・モーニングスターの振り回し）は、メンバーに `SeVoice m_ChargeSe;` を持ち、`Play` で鳴らして `Stop` で止める。`Keep` は鳴り終わっていたらもう一度鳴らす（長く続く動作用）。
- 新しい音を足すとき：WAV（16bit PCM）を `assets/sounds/se/` に置く → `se.h` の `SE_ID` に名前を足す → `se.cpp` の `SE_TABLE` に1行（ファイルと音量）足す。表に書き忘れるとビルドで止まる（`static_assert`）。
- 音は「メニュー・戦闘」のジャンルに分かれ、オプションの「サウンド」で全体とジャンルごとの音量を変えられる（この PC だけ。`SeSetVolumeLevel`）。音量はほかのオプションと一緒に、オプションの「保存する」で `settings.ini` へ保存し、起動時に読む（自動では保存しない）。新しい音は `se.cpp` の `GetGenre` に書かなければ戦闘の音になる（メニューの音を足したら `GetGenre` にも足す）。
- 音量は `se.cpp` の `SE_TABLE` の数字。「(1)」「(2)」のない候補が2つある音（刀のヒット・刀の移動・レーザーの溜め・ミサイルのロックオンと爆発）は、決まるまで1つ目を仮に使っている（表のコメントにもう一方の名前がある）。
- 鳴らすのはゲームの計算の結果を見てからで、音はゲームの計算を変えない（候補を選ぶ乱数もゲームの乱数とは別）。オンラインでも全員の PC で同じ場面で鳴る。
- 戦闘の音は、聞き手（この PC で遊ぶ人）から遠いほど小さい。自分が関わらないほかの人どうしの音は、`sespatialcalc.cpp` の `THIRD_PARTY_SILENT_DISTANCE`（30 m）で聞こえなくなる。キャラの声はない（No.207 で消した）。メニューの音は `game/menuse` が、`Game::Update` の前後の状態の変わり方から選ぶ。
- MP3 を WAV に変換するには、Windows の Media Foundation で 16bit PCM に書き出す（ffmpeg があれば `ffmpeg -i 元.mp3 -acodec pcm_s16le 先.wav` でもよい）。
- 音の機器がない PC では `SoundInitialize` が失敗するが、音なしで動き続ける。

## キャラの足し方（No.89）

- 待機・走り・左腕・右腕（必須）と、後ろ走り・ジャンプ・落下・着地（なくてもよい）の FBX を `assets/models/` に置き、`physics/scenecalc.h` の `CHARACTER_COUNT` の手前にキャラ番号を足す。最初に選ばれるキャラは同じファイルの `CHARACTER_DEFAULT`（今は MekaGirl。ダミーもこのキャラ）。
- `game/character.cpp` の表に、番号と同じ順で表示名・FBX 8つ（ないものは nullptr）・上半身の根元の骨とねじる背骨の名前・高さ・足元・正面の回転・描画用の肩位置・腕の骨（なければ `{}`）・腕のモデルの大きさを1行分足す。画面で足元・正面・腕の付け根を合わせる。
- 新しいクリップを Maya で作るときは、同じリグ・同じ骨の名前で、ルートを動かさずその場で再生する形にして、テイク1つの FBX に書き出す。MekaGirl の元のシーンは `assets/models/source/mekagirl_motion.mb`（待機 1–73・走り 101–117・左腕 201–273・右腕 301–337・後ろ走り 401–417・ジャンプ 501–508・落下 601–625・着地 701–706、24fps）。武器の攻撃クリップ（No.103）は同じシーンの右手 1001〜・左手 2001〜（100 フレームずつ）で、`tools/maya/build_weapon_clips.py` を mayapy で実行して作る（`build` で `.mb` にキーを打ち、`export` で `assets/models/mekagirl_atk_*.fbx` に骨だけ書き出す。右手は `CLIPS`、左手は別の振り方を `LEFT_CLIPS` に書く。`LEFT_CLIPS` は右手として書いた形を左右反転して左手のクリップにする。区切りのフレームは左右でそろえる）。区切りのフレームを変えたら各腕の `.cpp` の `*_CLIP_SECONDS` もそろえる。骨は軸に沿っていないので、向きは子の骨への実際の方向で解く。
- Maya の元データは `assets/models/source/` にすべて置く（別の PC でも同じものが使える。Git LFS）。MekaGirl の作成途中のシーンと最初に書き出した FBX は `mekagirl/`、以前の体（`mechani_body`）と `protomodel.mb` は `mechani/`。Downloads などの PC の中だけに元データを置かない。
- 体のカプセルと攻撃の起点は共通。キャラ番号はオンラインのロビー通知で共有し、入力パケットやチェックサムの対象には含めない。キャラ番号を足した場合は通信の版も上げる。

## 当たり判定の使い方（`src/physics/collision.h`）
- 形は3つ：`SPHERE`（中心・半径）、`CAPSULE`（線分の両端・半径。プレイヤー・ダミーは縦、触腕は斜め）、`BOX`（向きなしの直方体。浮島）。
- `CollisionSphereSphere` / `CollisionSphereCapsule` / `CollisionCapsuleCapsule` / `CollisionSphereBox` は `HIT_RESULT` を返す。
  `Hit` が true なら、1つ目の形を `Normal` の向きに `Depth` だけ動かすと離れる（重ならないように押し出すときに使う）。ちょうど触れているだけなら `Hit` は false。
- 攻撃（触腕など）は、始めるときに `HitRecord::Clear`、当たったら `HitRecord::TryAdd(相手の番号)` が true のときだけダメージや吹っ飛びを与える（同じ攻撃で2回当たらない）。

## 単体テスト（`tests/Proto1Tests/`）
- **Google Test**（2026-11-06 に Visual Studio 標準の単体テストから移した）。`third_party/googletest` のソースを一緒にコンパイルする exe（コンソール）で、`main` は `gtest_main.cc` にある。ソリューションを開くと `Proto1Tests` として入っている。
- 実行のしかた：
  - コマンド：`.\tools\run-tests.ps1`（テストを作り直してから全部実行する。失敗したテストだけが `[  FAILED  ]` の行に出る）
  - Visual Studio：**テスト → テスト エクスプローラー** → 「すべて実行」（「C++ によるデスクトップ開発」に入っている Google Test 用のアダプターが見つける）
  - 1つのテストだけ：`.\tests\Proto1Tests\bin\Debug\Proto1Tests.exe --gtest_filter=StageCalcTest.*`（先に `run-tests.ps1` でビルドしておく）
- テストできるのは **DirectX を使わないファイル**だけ（ウィンドウや GPU がなくても動くもの）。だから計算は `src/physics/` などに分けて書く。
- 書き方（`tests/Proto1Tests/mathutil_test.cpp` が見本）：

  ```cpp
  // 両端と真ん中の値になる（説明は日本語のコメントに書く。テストの名前は英語）
  TEST(MathUtilTest, Lerp_EndsAndMiddle)
  {
      EXPECT_NEAR(4.0f, Lerp(2.0f, 6.0f, 0.5f), EPSILON);   // 期待する値, 実際の値, 許す誤差
      EXPECT_EQ(1.0f, Saturate(2.0f));                       // ぴったり同じか（整数・enum・文字列など）
      EXPECT_TRUE(Saturate(-1.0f) == 0.0f);                  // true か（false を確かめるときは EXPECT_FALSE）
  }
  ```
  - テストごとに同じ準備（static の状態を戻すなど）をするときは、`class 〇〇Test : public ::testing::Test` を作って `SetUp()` に書き、`TEST_F(〇〇Test, 名前)` にする（見本は `gametime_test.cpp`）。
  - 失敗したときに出す説明を足すときは `EXPECT_TRUE(ok) << "説明";`。
  - `EXPECT_〇〇` は失敗してもそのテストの続きを実行する。続けると落ちてしまうとき（空の配列を読むなど）は `ASSERT_〇〇` にする（`void` の関数の中だけで使える）。
- 新しくテストしたい `.cpp` があるときは、`Proto1Tests` のプロジェクトにも「既存の項目」でその `.cpp` を追加する。

## 気をつけること
- **ポリゴンの表は時計回り。** 見る側から見て頂点が時計回りに並んでいない面は描かれません（バックフェースカリング）。
- **シェーダーの定数バッファ**は `shader.h` / `shader.cpp` の構造体と `shaderCommon.hlsli` の並びをそろえること。片方だけ変えると色や位置がおかしくなります。
- **シェーダー（`.hlsl` / `.hlsli`）は BOMなしUTF-8** で保存する。BOM があるとコンパイルが `X3000: Illegal character` で失敗します。
  C++ のファイル（`.cpp` / `.h`）は **BOM付きUTF-8**。
- ビルドすると `.cso`（コンパイル済みのシェーダー）がプロジェクトのフォルダにできます（Git には入れない）。
  exe を直接ダブルクリックすると .cso が見つからずエラーになるので、Visual Studio から実行してください。
