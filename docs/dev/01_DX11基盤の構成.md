# DX11 基盤の構成

授業（DX21）のひな形をもとに、3D ゲームを作り始められるようにした土台です（`HEW2026GitTest` から、水のレイトレーシングを除いて持ってきたもの）。
起動すると、空に浮かぶ緑の浮島・その上に立つプレイヤー（赤いカプセル）とダミーの敵3体（青いカプセル）・左上の半透明パネル（2D）が表示されます。
カメラはプレイヤーの背後から追いかける TPS カメラです（マウス・右スティックで回す。歩いても自動では回り込まない）。

浮島・プレイヤー・カメラ・2D パネルは仮の形です。企画書（`docs/plan/`）に合わせて作り変えていきます。

## 操作
| 操作（キーボード＋マウス） | パッド（DUALSHOCK 4） | 動き |
|---|---|---|
| W / A / S / D | 左スティック | 歩く（前 = カメラが向いている向き） |
| Space | × | ジャンプ |
| マウス / ← → ↑ ↓ | 右スティック | カメラを回す |
| 左クリック / 右クリック | L1 / R1 | 左右の触腕（伸ばしてつかむ／もう一度で投げる） |
| E | □ | はたく（まだ何も起きない。No.16） |
| R | OPTIONS | やり直し（まだ何も起きない。No.14） |
| Tab | — | マウスのロック（カーソルを隠して見回す）の ON / OFF |
| ESC | — | 終了 |

ウィンドウを選ぶと、自動でマウスがロックされます（カーソルが消えます）。
ほかのウィンドウに切り替えたときや、終了確認が出たときは自動でロックが外れます。
浮島から落ちて場外に出ると、浮島の真ん中に戻ります。
ダミーにぶつかると押せます。押して浮島から落とすと、2 秒後に最初の場所に 0% で戻ります（Debug ビルドでは出力ウィンドウに「ダミー〇：場外」「復活」と出る）。
触腕で敵をつかむと手元へ引き寄せ、同じボタンをもう一度押すとカメラの上下左右の向きへ投げます。保持は3秒で解除され、投げると12%加算します。F1の仮攻撃は削除しました。

### 速さ・感度を変える
それぞれのファイルの上のほう（「調整用の値」）にまとまっています。

| ファイル | 値 | 意味 | 初期値 |
|---|---|---|---|
| `player.cpp` | `MOVE_SPEED` / `JUMP_SPEED` / `GRAVITY` | 歩く速さ・ジャンプの速さ・重力（1秒あたり） | `6` / `9` / `25` |
| `action.cpp` | `MOUSE_SENSITIVITY` | **マウス感度**。大きいほど速く回る（0.001f〜0.005f くらいが目安） | `0.00125f` |
| `action.cpp` | `MOUSE_INVERT_Y` | `true` でマウスの上下を逆にする | `false` |
| `action.cpp` | `KEY_LOOK_SPEED` / `PAD_LOOK_SPEED` | 矢印キー・右スティックで回る速さ（1秒あたり） | 120° / 180° |
| `camera.cpp` | `FOLLOW_DISTANCE` | カメラとプレイヤーの距離 | `8` |
| `camera.cpp` | `FOLLOW_SPEED` | カメラがプレイヤーに追いつく速さ（大きいほどぴったり、小さいほど遅れてついてくる） | `10` |
| `camera.cpp` | `PITCH_MIN` / `PITCH_MAX` | 見下ろせる角度・見上げられる角度 | -70° / 30° |

## フォルダ構成
| フォルダ | 入れるもの |
|---|---|
| `src/core/` | ウィンドウ・メインループ・DX11・シェーダーの読み込み・時間・デバッグ出力 |
| `src/input/` | キーボード・マウス・パッド、入力を「行動」に変える仕組み |
| `src/render/` | 形・2D・数字の表示など、描画の部品 |
| `src/game/` | プレイヤー・カメラ・ステージ・敵・触腕・試合の流れ |
| `src/physics/` | 当たり判定・吹っ飛びの計算（DirectX を使わない。単体テストする） |

- `#include` は `src` からのパスで書く（例：`#include "core/dx11.h"`）。プロジェクトの設定で `src` をインクルードのフォルダにしてある。

- 細かいルール（依存の向き・計算と描画を分ける・調整用の値）は `CLAUDE.md` の「コードの構成」。

## 新しいオブジェクトを足すとき
`player.cpp` をコピーして作るのがいちばん早いです。

1. `〇〇Initialize / Finalize / Update / Draw` の4つの関数を作る
2. `main.cpp` の `Initialize`・`Finalize`・`Update`・`Draw` から呼ぶ
3. 箱・球・カプセルの仮の形なら、`Draw` で `ShapeDrawBox` / `ShapeDrawSphere` / `ShapeDrawCapsule`（`render/shape.h`）を呼ぶだけで描ける
   - ほかの形を自分で描くときは、`shape.cpp` のように次の順番で設定してから描く：
     `Shader_SetWorldMatrix(...)`（拡大縮小 → 回転 → 移動 の順に掛ける）→ `Shader_SetMaterial(...)`（色）→ 頂点バッファ（とインデックスバッファ）をセットして `Draw` / `DrawIndexed`
4. 動きの計算（当たり判定・速さなど）は `src/physics/` に DirectX を使わないファイルとして分け、単体テストする（`playercalc` が見本）
5. ファイルを Visual Studio のプロジェクトに追加する（`.vcxproj` が変わるので一緒にコミット）
6. ヘッダーの関数には Doxygen 形式（`/// @brief`）の日本語コメントを付ける

物を浮島の上に置きたいときは、`StageGet().TopY`（浮島の上の面の高さ）を y に入れます。浮島の範囲の中かは `StageCalcIsOnPlatform` で調べます。

## プレイヤーとカメラ
- `main.cpp` の `Update` で、`ActionUpdate` → `StageUpdate` → `PlayerUpdate` → `DummyUpdate` → `CameraUpdate` → `TentacleUpdate` の順に呼ぶ（ダミーは動いたあとのプレイヤーに押され、カメラはそのあとのプレイヤーを追いかける）。
- ダミーの体の動き（重力・着地）は、プレイヤーと同じ `PlayerCalcStep` に「歩かない・ジャンプしない」を渡して動かしている。
- プレイヤーとダミーの体は、足元から作った縦のカプセル（`DummyCalcBodyCapsule`）どうしで当たり判定をする。横から重なったらダミーだけを横に押す（プレイヤーは押し戻されない）。真上から乗ったときはプレイヤーを押し上げる。
- プレイヤーの移動の向きは、カメラの左右の向き（`CameraGetYaw()`）で決める。W（左スティックを上）で、カメラが向いている向きへ歩く。
- 動きの計算は `PlayerCalcStep`（`physics/playercalc.h`）：横の速度 → ジャンプ（立っているときだけ）→ 重力 → 着地（浮島の上の面を上から通り過ぎたときだけ）。浮島の横の面とはぶつからない。
- カメラ（No.9 の TPS カメラ）は、毎フレーム次の順に動く（計算は `physics/cameracalc.h`）。
  1. 「カメラを回す」行動で左右・上下の向きを変える（上下は `PITCH_MIN`〜`PITCH_MAX`）。**プレイヤーが歩いても自動では回り込まない**（触腕をカメラの向きへ伸ばすので、勝手に回ると狙いにくいため。2026-10-23 に決めた）
  2. 見ている点を、プレイヤーの頭のあたりへなめらかに近づける（`CameraCalcSmooth`。カメラの位置ではなく見ている点を遅らせるので、回したときに画面が揺れない）
  3. 見ている点から、見ている向きの反対へ `FOLLOW_DISTANCE` 下がったところに置く（`CameraCalcOrbitPosition`）
  4. 見ている点からカメラへの線が浮島にぶつかるなら、ぶつかる手前（面から `STAGE_MARGIN`）まで近づける（`CameraCalcClipToStage`）。見上げても浮島の中に入らない
- カメラは浮島としかぶつからない。ダミーなどは通り抜けて見える。

## 描画の順番（`main.cpp` の `Draw`）
1. `Clear()` で画面と深度バッファを消す
2. **3D**：`SetDepthEnable(true)` → `CameraDraw()` → ライトON → 浮島・プレイヤーを描く
3. **2D（UI）**：`SetDepthEnable(false)` → ライトOFF → 2Dを描く（描いた順に上に重なる）
4. `Present()` で画面に出す（垂直同期あり。`dx11.cpp` の `VSYNC` で切り替えられる）

## メインループ（`main.cpp` の `WinMain`）
- `Update` と `Draw` は **1秒に60回**（17・17・16ミリ秒の間隔を繰り返す）。待っている間は `Sleep(1)` で休むので、CPU をほとんど使わない
- 来ているウィンドウメッセージ（マウスの移動など）は、毎回全部処理してからフレームを進める
- **タイトルバーに FPS** が出る。60 より下がっていたら、処理が重くて間に合っていない
  （1フレームの秒数は 1/60 秒で固定しているので、FPS が下がるとゲーム全体がゆっくりになる）
- **垂直同期**（`dx11.cpp` の `VSYNC`）：モニターの書き換えに合わせて表示するので、画面のちらつき（ティアリング）が出ない

## 時間の使い方（`src/core/gametime.h`）
- `main.cpp` の `Update` の最初で `GameTimeUpdate()` を呼び、時間を1フレーム分進める。
- 動きは **「1秒にどれだけ進むか × `GameTimeGetDeltaTime()`」** で書く（例：`playercalc.cpp` の移動。`body.X += body.VelocityX * dt`）。
  こう書いておくと、`GameTimeSetScale(0.0f)` で時間を止めたとき（ヒットストップ）に動きも止まる。
- 1フレームの秒数は 1/60 秒で固定（実際にかかった時間ではない）。同じ操作で毎回同じ結果になり、吹っ飛びなどの計算が安定する。
- 「○秒たったら」は `TIMER` を使う：`TimerStart(timer, 90.0f)` → 毎フレーム `TimerUpdate(timer, GameTimeGetDeltaTime())` → `TimerIsFinished(timer)`。
- カメラを回す速さ（矢印キー・右スティック）も「1秒に何度 × dt」。マウスは動かした量そのまま（dt を掛けない）。
  そのため、`GameTimeSetScale(0.0f)` で時間を止めると、矢印キーと右スティックでは回らなくなる（マウスでは回る）。

## 入力の使い方（`src/input/action.h`）
- ゲームの側は、キーやボタンではなく **行動** を見る：`ActionIsTrigger(ACTION_ARM_LEFT)`（左の触腕を押した瞬間）、`ActionGetMove()`（移動の向き）など。
  キーボードでもパッド（DUALSHOCK 4）でも同じように動く。
- `main.cpp` の `Update` で、`KeyboardUpdate` → `MouseUpdate` → `PadUpdate` → Tab でマウスのロック → `ActionUpdate` の順に呼ぶ。
- キーの割り当て（`ACTION_KEYS`）・パッドのボタンの割り当て（`ACTION_PAD_BUTTONS`）・マウス感度（`MOUSE_SENSITIVITY`）・右スティックで回る速さ（`PAD_LOOK_SPEED`）は `action.cpp` の「調整用の値」で変える。スティックの遊びは `pad.cpp` の `STICK_DEAD_ZONE`。
- ボタンは「キーボードかパッドのどちらかを押している」、移動は「W/A/S/D と左スティックの強く入れているほう」、カメラは「マウス＋矢印キー＋右スティック」。
- パッドは `WndProc` の `WM_INPUT`（データ）と `WM_INPUT_DEVICE_CHANGE`（つないだ・外した）で受け取る。USB でつなぐ（Bluetooth は読まない）。
- Debug ビルドでは、行動のボタンを押すと出力ウィンドウに「行動：〇〇」と出る（確かめ用。パッド（No.6）を実物で確かめたら消す）。
- プレイヤーは `ActionGetMove()`・`ActionIsTrigger(ACTION_JUMP)`、カメラは `ActionGetLook()` を使う。キーやボタンを直接見ているゲームのコードはない（Tab のマウスのロックだけ `main.cpp` がキーを見ている）。

## 気をつけること
- **ポリゴンの表は時計回り。** 見る側から見て頂点が時計回りに並んでいない面は描かれません（バックフェースカリング）。
- **シェーダーの定数バッファ**は `shader.h` / `shader.cpp` の構造体と `shaderCommon.hlsli` の並びをそろえること。片方だけ変えると色や位置がおかしくなります。
- **シェーダー（`.hlsl` / `.hlsli`）は BOMなしUTF-8** で保存する。BOM があるとコンパイルが `X3000: Illegal character` で失敗します。
  C++ のファイル（`.cpp` / `.h`）は **BOM付きUTF-8**。
- ビルドすると `.cso`（コンパイル済みのシェーダー）がプロジェクトのフォルダにできます（Git には入れない）。
  exe を直接ダブルクリックすると .cso が見つからずエラーになるので、Visual Studio から実行してください。

## 当たり判定の使い方（`src/physics/collision.h`）
- 形は3つ：`SPHERE`（中心・半径）、`CAPSULE`（線分の両端・半径。プレイヤー・ダミーは縦、触腕は斜め）、`BOX`（向きなしの直方体。浮島）。
- `CollisionSphereSphere` / `CollisionSphereCapsule` / `CollisionCapsuleCapsule` / `CollisionSphereBox` は `HIT_RESULT` を返す。
  `Hit` が true なら、1つ目の形を `Normal` の向きに `Depth` だけ動かすと離れる（重ならないように押し出すときに使う）。ちょうど触れているだけなら `Hit` は false。
- 攻撃（はたく・触腕）は、始めるときに `HitRecordClear`、当たったら `HitRecordTryAdd(record, 相手の番号)` が true のときだけダメージや吹っ飛びを与える（同じ攻撃で2回当たらない）。

## 触腕（No.13）
- `src/game/tentacle.h / .cpp`：左右の入力、敵との連携、球をつないだ描画。最大長8、伸長24/秒、収縮30/秒、保持3秒、投げ12%・強さ2を調整用定数で管理する。
- `src/physics/tentaclecalc.h / .cpp`：待機・伸長・保持・収縮、命中順、時間切れ、浮島との接触を DirectX なしで計算する。
- 伸長方向は開始時に固定し、投げる方向は再入力時の `CameraGetDirection()` を使う。
- 左腕の後に右腕を処理し、`DummyGrab` の保持状態で二重つかみを防ぐ。`HIT_RECORD` は1回の伸長ごとにリセットする。
- `DummyUpdate` は保持中の通常物理を止める。`TentacleUpdate` はカメラ更新後に保持位置を決め、`DummyMoveHeld` で反映する。
- プレイヤー復活を `PlayerDidRespawn()` で検出して両腕を解除する。敵は元の位置で離し、復活先へ運ばない。
- 投げは `DummyRelease` → `DummyHit` でダメージ・速さを計算し、`KnockbackCalcDirectedVelocity` で上下を含む方向へ飛ばす。通常攻撃の固定角の計算は維持する。
- 最大距離または浮島に達した空の腕は戻る。保持する敵は半径・半高で拡張した浮島の箱を越えない位置に止める。
