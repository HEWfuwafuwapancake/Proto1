## 2. 腕

### 腕の共通の仕組み（No.35 から）

- `src/game/arm.h / .cpp` に、片手の腕の基本クラス `Arm`（純粋仮想関数 `Update(const ARM_INPUT&)`・`Draw()`・`Reset()`・`IsActive()`・`IsHolding()`）と、左右の装備を持つ `ArmManager` がある。`ArmManager` は起動時に左右それぞれ全種類の腕を `ARM_FACTORIES`（腕の種類 → `CreateArm<腕のクラス>`、未実装は `nullptr`）から作って持ち、装備している腕だけを更新・描画する。
- **No.93 腕の入力**：`Fighter::IsPress` で `PLAYER_INPUT.Buttons` の押下を読み、左右それぞれの `ArmPressCalc` で `ARM_INPUT` を作る。0.25 秒より前の解放で `Tap`、0.25 秒に達したフレームで `HoldStarted`、押下中は `Pressed`。腕の動作中（`Arm::CanTakeTap` / `CanTakeHold` が false）は入力を捨てず、単押しは 0.2 秒覚えておき、長押しは押し続けている間待って、受け付けられたフレームで渡す。装備切り替えや中断で押し始めを持ち越さない。
- **No.93 突進と中断**：`Fighter::Update` は `ArmManager::GetRushVelocity()` の水平速度を歩きに優先して `PlayerBodyCalc::Step` に渡す。腕は体の後に更新するので1フレーム前の状態を使う。吹っ飛びやしびれでは `Arm::Interrupt()` を呼ぶ。標準は `Reset()`。
- 腕が使う相手（`FighterManager`・自分のスロット番号・カメラ・ステージ）は `ARM_LINKS` にまとめて `Arm(int hand, const ARM_LINKS& links)` で受け取り、派生クラスは `protected` の `GetPlayer()`（自分の`Fighter`）・`GetFighters()`・`GetSlot()`・`GetCamera()`・`GetStage()` で使う。候補は`GetTarget(相手のスロット, GetSlot())`、攻撃・保持操作にも自分のスロットを渡す。肩の位置 `GetShoulder()`・待機の向き `GetRestDirection()`・左右と効いている間の色 `GetColor()`・モデル1個の配置 `DrawPiece()`・右手の X を鏡写しにして読む `LoadModel()` も `Arm` の `protected` で共通にする（値と計算は `arm.cpp`）。
- `src/physics/armcalc.h / .cpp` は使える腕の直接選択と巡回（DirectX なし）。1段目は 1 触手・2 ハンマー・3 ナックル・4 レーザー・5 刀・6 モーニングスター・7 槍・8 ミサイル。数字だけで左手、Shift＋数字で右手、または Q / E で手と段を選んで数字を押す。十字キーの左右で手を選び、上下で使える腕を巡回する。
- `ArmManager::Update(試合中か)` は試合シーンで、カメラとキャラの向きの更新後に呼ぶ（`Game::Update`）。装備切り替えは時間切れ後も受け付け、腕の更新は試合中だけ左→右の順。切り替える手は今の腕を `Reset()` してから付けかえる（敵はダメージなしで離す）。`ArmManager::Reset` は装備を変えない。
- No.25：F1〜F4で腕の切り替え先（1P〜4P、初期は1P）を選ぶ。Q / E と数字・Shift＋数字は選んだ人のスロットだけに届く。`ActionGetEquipKey(player)`・`ActionGetEquipMode(player)`はスロット0〜3を受け取り、省略時は1P。切り替えモードはスロットごとに持ち、`ActionGetEquipPlayer()`で選択先を読む。腕の振動は`Arm::Rumble`から本人のパッドへ出し、キーボードの人の腕では振動しない。ライトバーは`Game::UpdatePadLights`で1P赤・2P青・3P緑・4P黄にし、未参加は消灯する。色の値は`Fighter::GetPlayerColor`で体・HUDと共用する。
- **No.59 の共通部品**（腕の書き方は [01_DX11基盤の構成.md](01_DX11基盤の構成.md) の「腕を足すとき」）：

## 3. 体・カメラ

### プレイヤーとカメラ
- `main.cpp`の`ActionUpdate`のあとに`Game::Update`を呼ぶ。キャラ選択（`SCENE_TITLE`）では全機器の決定を`VersusCalc::LobbyDecide`（参加 → 準備OK → 全員準備OKなら1Pで開始）、戻るを`LobbyCancel`（準備OKの取り消し → 参加をやめる → 1Pは前の画面）へ渡し、試合開始時に`ConfigurePlayers`で機器と画面を割り当てる。試合は`Stage` → `FighterManager::Update`（全員の体・場外とKO・体当たり）→ 人ごとの`Camera::Update` → `FighterManager::UpdateFacing` → 人ごとの`ArmManager::Update` → `SceneCalc::Step` → `Match::Update`。時間切れ後は体と腕を止め、カメラと装備切り替えは受け付ける。RETRYは`Restart`、結果の「キャラ選択へ」は準備OKだけ消して`ConfigurePlayers`、TITLEは参加を消して`ConfigurePlayers`。タイトル・結果では試合の時間を止める。ライトバーは全シーンで参加者に合わせる。
- ダミーの体の動き（重力・着地）は、プレイヤーと同じ `PlayerBodyCalc::Step` に「歩かない・ジャンプしない」を渡して動かしている。
- 人とダミーの体は、足元から作った縦のカプセル（`DummyCalcBodyCapsule`）どうしで当たり判定をする。人対ダミーは従来どおり横からダミーだけを押す。人対人は横の押し出しを半分ずつ受け、頭に乗ったときは上の体を押し上げる（`VersusCalcPushBodies`）。復活待ち・保持中・吹っ飛び中・引っぱられ中の体は体当たりから除く。
- プレイヤーの移動の向きは、カメラの左右の向き（`Camera::GetYaw()`）で決める。W（左スティックを上）で、カメラが向いている向きへ歩く。
- キャラの左右の向きは `Fighter::GetYaw()`。ターゲットがいればターゲットへ、いなければ歩く方向へ `TURN_SPEED` の上限つきで回る。対象も移動もなければ最後の向きのまま。腕のボタンを押した瞬間、または `ArmManager::IsActive()`（触腕なら伸長・保持・収縮中）が true の間は、更新後のカメラの正面へ即座に向く。肩の球はキャラの向きで置く。No.30 の伸長方向は下の「触腕」を参照。投げる方向はカメラの正面へ水平にする。
- 動きの計算は `PlayerBodyCalc::Step`（`physics/playercalc.h`）：横の速度 → ジャンプ（立っているときだけ）→ 重力 → 着地（浮島の上の面を上から通り過ぎたときだけ）。浮島の横の面とはぶつからない。
- カメラ（No.29 のバネと No.33 のロックオン）は、毎フレーム次の順に動く（計算は `physics/cameracalc.h`）。
  - 最初に自分を候補から除き、相手の生存・場外・保持状態を調べる。開幕・やり直し・対象が消えたときは `CameraCalcPickFocus` で正面に最も近い相手（全周・距離無制限）を選ぶ。左右の弾きは `CameraCalcNextTarget` で対象への向きを基準に指定側の最小角を選ぶ。保持中は対象を退避して自由カメラへ、解放後は退避した相手、選べなければ正面の相手へ戻る。`Camera::GetTarget()` はロック中の相手のスロット番号（0〜3で自分以外）、なし・保持中は-1。
  - ロックオン中は、以下の自由カメラの手順1の左右角を敵への水平角に、手順3の注視点の目標を `CameraCalcFocusPoint` に置き換える。上下は手動。切り替え後 `SWITCH_TIME` の間は角度のバネに `SWITCH_SMOOTH_TIME` を使い、速度を持ち越す。ジャンプ中の接地高さの保持は共通。
  - 対象がいないとき・保持中は次の自由カメラとして動く。
  1. 手動入力を左右・上下の目標角度へ足す（上下は -35°〜0°）。試合中は横入力に比例して左右の目標角度を回す（sway）。手動操作後は `MANUAL_PAUSE` 秒止める
  2. 左右・上下の角度を別々の臨界減衰バネ（`CameraCalcSmoothDampAngle` / `CameraCalcSmoothDamp`）で追う。速度は呼ぶ側で値ごとに保持する
  3. 注視点の XZ は `LOOK_DEADZONE` を超えた分だけ目標を動かす。Y は `Fighter::IsOnGround()` で最後に立っていた足元＋頭の高さを記憶し、ジャンプ中は変えない。足元が浮島の上面より下へ落ちたら落下を追う。XZ・Y を別のバネで追う
  4. 注視点からカメラへの線が浮島にぶつかるなら、ぶつかる手前（面から `STAGE_MARGIN`）まですぐ近づける（`CameraCalcClipToStage`）。離れるときだけ距離のバネで戻す
  5. 追った角度・距離と注視点から `CameraCalcOrbitPosition` で位置を出す。復活・やり直しではバネを使わず目標へ合わせ、速度をすべて0にする
- カメラは浮島としかぶつからない。ダミーなどは通り抜けて見える。

### ロックオンの計算（No.33）

- `cameracalc` に中央の敵の選択・最短角の回転・プレイヤー全身が画面に残る視点の上限をまとめる。DirectX は使わない。
- `CameraCalcPickFocus` / `NextTarget` / `YawTo` / `FocusPoint` と単体テストを使う。`ArmManager::IsHolding()` で自由カメラへの切り替えを決める。キャラの回転は No.32 で共通にした `core/mathutil.h` の `TurnYaw` を `PlayerCalcFacing` から使う。

## 4. 入力とパッド

### 入力（詳しい版）
- ゲームの側は、キーやボタンではなく **行動** を見る。腕は `Fighter::IsPress(ACTION_ARM_LEFT)` などから押下を読み、`ArmPressCalc` で単押し・長押しを分ける。
  キーボードでもパッド（DS4 / DualSense・XInput・Switch Pro 形式）でも同じように動く。
- `main.cpp` の `Update` で、`KeyboardUpdate` → `MouseUpdate` → `PadUpdate` → Tab でマウスのロック → `ActionUpdate` の順に呼ぶ。
- 行動（`ACTION`）は通信で送るボタンのビットを兼ねていて、**16 個で使い切っている**（No.114）。これ以上足すときは `PLAYER_INPUT::Buttons` と `lockstepcalc` の通信の形式も変える。
- キーの割り当て（`ACTION_KEYS`）・パッドのボタンの割り当て（`ACTION_PAD_BUTTONS`）・マウス感度（`MOUSE_SENSITIVITY`）・右スティックで回る速さ（`PAD_LOOK_SPEED`）は `action.cpp` の「調整用の値」で変える。スティックの遊びは `pad.cpp` の `STICK_DEAD_ZONE`。
- 各人は参加した機器だけの行動・移動・カメラを読む。パッド0〜3とキーボード4は独立する。機器番号なしの旧合成入力もAPIとして残すが、参加後の対戦には使わない。
- パッドは `WndProc` の `WM_INPUT`（データ）と `WM_INPUT_DEVICE_CHANGE`（つないだ・外した）で受け取る。USB でつなぐ（Bluetooth は読まない）。
- `Game` が毎フレーム `ActionGetPlayerInput(device)` で入力を作り、人のスロットへ配る。`Fighter::SetInput` に今と前の `PLAYER_INPUT` を渡し、プレイヤーとカメラは `GetMoveInput()`・`IsTrigger()`・`GetLookInput()` から読む。シーンの決定・やり直し・メニュー上下も1Pの `PLAYER_INPUT` を使う。タイトルの参加は各機器の今と前の入力を比べる。
- 移動は1を32767、カメラは1ラジアンを4096としてint16に丸め、ローカルも復元した値を使う。ボタンは押下ビットの変化で押した瞬間を求める。ターゲット切り替えだけは既存の1フレームのイベントなので、連続して届いてもそれぞれ有効にする。
- 装備の直接選択も `PLAYER_INPUT.Equip` に入れる。ローカルでは `Game` が `ActionGetEquipKey(slot)` を各スロットへ配り、`ArmManager` は `Fighter::GetEquipInput()` から読む。F1〜F4、Q / E、数字・Shift＋数字の選択先は従来どおり。選択モードのタイトルバー表示はローカル入力側に残す。

### PS5 コントローラー（No.46）

- 純正 DualSense（VID `054C` / PID `0CE6`）を USB で使う。PS4 の初代・2代目と混在して、パッド合計4台まで。Bluetooth・DualSense Edge・センサー・アダプティブトリガーは対象外。
- USB入力は64バイト・ID `01`。両スティックは [1]〜[4]、ボタンは [8]〜[10]。PS4 と同じビットを同じ `PAD_STATE` に変換する。短い Bluetooth の簡易入力（同じID `01`）と通常入力（ID `31`）は受け付けない。

### XInput・Switch Pro 形式（No.53）

- `pad.cpp` が DS4・DualSense と同じ4枠に登録する。ソニーと Switch は Raw Input、XInput は接続済みを毎フレーム、未割り当てを1秒ごとに調べる。外れた枠だけ空け、非選択中は入力と振動を0にする。`action.cpp` とゲーム側の操作は共通のまま。

- ボタンは位置で対応する（下→×、右→○、左→□、上→△）。Xbox の A・B・X・Y、Switch の B・A・Y・X の順。Windows に依存しない変換・初期化バイト列のテストコードは `padcalc_test.cpp`。簡易入力のY方向と各実機の動作は段階3で管理者が確認する。
- Debug では対応外のゲームパッドの VID/PID を一度だけ出す。茶色のサードパーティパッドが読めなければ、この番号を調べる。

### Switch 2 Pro コンの USB 入力（No.54）

- VID `057E` / PID `2069`。HID のゲームパッドを見つけたら、SetupAPI で GUID `{6F13725E-EF0E-4FD3-AE5F-B2DE989EC825}` の `MI_01` を探す。`CM_Get_Parent` でUSBの親までたどってHIDと同じ実機だけを開く（シリアルだけで組を決めない）。WinUSB は機器側の指定で自動で付くので、Zadig や外部ライブラリは要らない。

- Bluetooth・振動・ジャイロ・ランプ・補正値の読み込みは使わない。Windows SDK の `winusb.lib`・`setupapi.lib`・`cfgmgr32.lib` を使う。プロトコルの出典とライセンスは [03_Switch2_SDLライセンス.md](03_Switch2_SDLライセンス.md)。

### 試合の流れ（No.14）
- `src/game/match.h / .cpp`：`Match`（制限時間・得点・時間切れ）。やり直しは `Game::Restart`。`src/physics/matchcalc.h / .cpp`：得点・時間・状態の計算（DirectX なし）。
- `VersusCalc`が最後の攻撃者を記録し、体の場外イベントでその人に+1する。人対人・人対ダミーは同じ。未攻撃の自滅とダミーの攻撃では加点しない。場外で攻撃記録を消し、次の復活へ持ち越さない。`Grab`・`AddDamage`・`Hit`・`Launch`・`Push`が攻撃記録を更新し、通常の体当たりは更新しない。全員のKO合計を`MatchCalc`へ渡して得点イベントと制限時間を扱い、HUDと結果は個人の`FighterManager::GetScore(slot)`を読む。同時に2体落とせば+2。時間切れと同じフレームのKOも入る。時間切れ後は体を更新しないので得点も止まる。落ちた人の減点はない。

### ロックステップの計算（No.26 段階A）

- `LockstepCalc::Initialize(playerMask, delay)` に人のスロットのビットと遅延を渡す（省略時3、0〜120）。最初の遅延分は全員無入力で埋める。`StoreLocalInput` は次の実行フレーム＋遅延へ入力を置く。同じフレームを待っている間は再採取せず、保管済みの入力を再送する。`IsReady` がtrueなら全員の入力で1回進めて `Advance` を呼ぶ。
- 入力は最大256フレーム保管する。順不同の受信も `StoreInput` で保管し、`GetReceivedThrough(mask)` は0から抜けなく受け取れた最後の番号を返す。重複は同じ入力なら許し、矛盾は拒否する。
- `SelectUnacknowledged` は送信先の累積ACKより後の入力を、指定した全スロットがそろったものから古い順に最大8フレーム選ぶ。返したパケットの `Acknowledged` には、呼び出し側が相手からの受領番号を入れる。`DiscardAcknowledged` には全送信先のACKの最小値を渡し、実行済みの分だけを消す。未確認の入力を勝手に上書きせず、満杯なら保管を失敗させる。
- パケットはリトルエンディアンで、識別子4バイト・版2・ビルド1・スロットマスク1・遅延2・累積ACK4・フレーム数1。続いて各フレームの番号4と、マスクのスロット順に入力12バイト（移動4・カメラ4・ボタン2・手1・腕1）を置く。無選択は手と腕を255、未受領ACKは全ビット1で表す。最大431バイト。長さ・版・値を確認してから出力を返す。ビルドの種類も運び、一致の接続判定は段階C。セッションのメッセージは、さらに `src` のソースの中身から作った識別番号（`SessionCalcSetProgram`。ビルドの前に `tools/make-sourceid.ps1` が中間フォルダに `generated/sourceid.h`（`SOURCE_ID`）を作り、`main.cpp` が起動時に設定する。改行の違いは無視するので、同じソースならどの PC・フォルダでビルドしても同じ番号）を運び、ソースが違う参加は `SESSION_FAILURE_PROGRAM` で断る。コンパイラの版（`SESSION_COMPILER` = `_MSC_FULL_VER`）も運び、違っても断らずにタイトルバーで知らせる（`SessionCalc::HasCompilerDifference`）。起動時に `_set_FMA3_enable(0)` を呼び、sinf などの計算を CPU によらずそろえる（オンラインのずれ対策）。
- `CalculateChecksum` は全4体の位置XYZ・%（IEEE754）・KOをスロット順にFNV-1aへ入れる。60フレーム間隔の呼び出しと比較は段階C。Windows・DirectX・gameへの依存はない。ソケット・セッション・起動引数は段階Bで追加する。

### モード選択と IP 入力（No.48）

- `SceneCalc` が GAME START → 対戦方法 → キャラ選択（ロビーを兼ね、ルールもここで切り替える）→ 試合 → 結果の遷移と IP 入力を持つ（No.172 でスマブラ式にした）。1P の上下の選択位置（ルールの行・自分のカード・人のいない枠）と、人のいない枠の相手（ダミー / CPU の強さ）は `VersusCalc` が持つ。オンラインのキャラはロビーで `NetSession::CycleLocalCharacter` で変え、毎回送り直す接続のメッセージでホストへ届く。引数なしは GAME START、`--host` / `--join <IP>` はロビーから始まる。メニュー・ロビーの Backspace／×は1つ前へ戻り、ロビーを出ると通信と参加を閉じる。切断・参加拒否は理由をタイトルバーに残してモード選択へ戻る。
- `SessionAddressCalc`（`net/sessioncalc`）は4区切りの文字・選択位置・0〜255の検査を持つ。自分の IPv4 の前3区切りを初期表示し、数字・`.`・Backspace またはパッドの十字キーで編集する。Backspace は入力を削除し、全欄が空なら戻る。空欄・範囲外では決定できない。
- `ActionGetMenuInput` は通信しないメニュー入力を返す。キーボードの数字・`.`・Backspace は押した順を `KeyboardGetAddressText` に残す。試合の `PLAYER_INPUT`・通信パケット・版は変更しない。
- `Game` が選んだモードから `NetSession::Initialize` / `Finalize` を呼ぶ。初期化は前の接続を閉じてから準備し、終了・失敗後は `IsOnline()` が false になる。メニューから開くホストの遅延は3。ホストの IPv4 一覧は `Hud::DrawScene` が大きく描く。

### UDP 接続とロビー（No.26 段階B）

- `net/netsocket.h / .cpp`：`NetSocket` が Winsock の初期化・UDPの送受信・終了を担当する。`ws2_32.lib` のみを使用。`FIONBIO` で受信も送信も待たない。ホストは UDP 27026、参加側は空きポートを使う。IPv4のIPとポートで相手を区別する。
- `net/sessioncalc.h / .cpp`：Windows・DirectX・gameに依存しない。`SessionCalcParseOptions` が `--host` / `--join <IPv4>` / `--delay N`（0〜120。省略すると `LOCKSTEP_AUTO_DELAY` で、ホストが試合の開始時に `GetAutoDelayPing`（人ごとの直近2秒の ping の 90% の値の、いちばん遅い人の値。同じ `Echo` の再送は測らない）から `SessionCalcAutoDelay` で決める）を読む。指定なしは従来のローカル対戦。`SessionCalc` はホストを0、参加順に1〜3へ割り当てる。全員が機器選択済み・2人以上のとき、ホストの再決定で開始。初回開始後の新規参加は受け付けない。
- 接続メッセージの識別子は `P1S1`（入力の `P1N1` と区別）。No.56で版を5へ更新。58バイトの封筒は識別子4・版2・種類1・参加側スロット1・接続マスク1・選択済みマスク1・遅延2・対戦中1・ビルド1・ホストの起動番号4・参加側の起動番号4・試合番号4・送信時刻4・返す相手時刻4・チェック対象フレーム4・チェックサム4・比較済みACK4・実行ファイル識別番号4・返信までの待ち（Hold）4・コンパイラの版4の順。種類はJOIN / READY / STATE / INPUTS / REJECT。INPUTSだけ既存の入力パケットを続ける。最大489バイト。構造体を直接送らない。長さ・値を読んでから、送信元・起動番号・試合番号・方向別スロットを確認する。制御通知の版不一致は読み取り後に理由を返して拒否する（古い長さの封筒は読み取らず、同じ版のexeを使う）。
- ホストは状態通知を毎回送り、参加側はJOIN / READYを再送する。開始通知が失われても次のSTATEで開始する。TITLEでロビーへ戻っても機器と接続を保持。次の開始で試合番号を増やし、前の入力と開始通知を使わない。RETRYは同じ試合番号の入力列で扱う。
- 入力は自分用の `LockstepCalc` と実行用の `LockstepCalc` に分ける。`NeedsInput` のときだけ `CaptureInput` で次の実行フレーム＋遅延の入力を固定する。満杯でも採取値は保持。参加側の実行用はホストの返送でだけ埋まる。`TakeFrame` は先行入力を保管でき、全員の入力がそろった場合だけ1フレーム進める。
- 参加側→ホストのACKは全員分をホストから受け取れた番号。ホスト→参加側のACKはその参加者の入力を受け取れた番号。ホストは全送信先の最小ACKまで、参加側はホストのACKまで採取履歴を保持する。実行前の分は消さない。TITLE直前の入力はロビー中も再送し、全員に届くまで次の開始を待つ。
- `game/netsession.h / .cpp`：`Game` が持つ `NetSession` が受信・機器選択・一度だけの入力採取・毎回の再送をまとめる。最初に決定を押した機器を固定する。装備の数字キーはF1〜F4の選択先に関係なく自分に配る。接続先・自分の番号・人数・選択済み人数・遅延はタイトルバーに出す。
- `main.cpp` は `Sleep(1)` の前に `Game::PollNetwork` → `NetSession::Poll` を呼ぶ。Pollは `SetTime` → `Receive` を行い、ホストでは `GetCompleteThrough()`（`m_Shared.GetReceivedThrough(m_Mask)`）が受信前より増えたときだけ全参加者へ `MakeInputs` をすぐ送る。全員分がそろわないと送らない。1/60秒の `Update` でもPollを呼び、切断判定・機器選択（Decide）・入力採取・定期再送と、Gameからの `TakeFrame` はこの更新周期を保つ。タイトルバーのFPSの横に、同じ測定期間に成功した `TakeFrame` の回数を1秒あたりに直した「進行: 〇/s」をオンラインだけに出す。
- `Game::Update` はオンラインで入力が足りなければゲームの更新を飛ばす。受信・再送・描画は続ける。試合・結果・RETRY / TITLEは全員共通の入力で進み、結果の操作は0番のホストだけ。全員のカメラを全画面の大きさで更新し、自分のスロットだけ描く。機器は自分だけ実機、ほかは `VERSUS_DEVICE_REMOTE`。振動・ライトバーもこのPCで選んだ機器だけへ送る。

### 同期の見張りと切断（No.26 段階C）

- `Game::Update` の計算・シーン遷移・KO集計が終わった直後に、実行済みの59、119、179…フレームの全4体（ダミーも含む）の位置・%・KO数を渡す。`SessionCalc::RecordChecksum` が既存の `LockstepCalc::CalculateChecksum` を使う。同じ試合番号・フレームの値だけを比較し、相手の計算が遅れていれば待つ。チェックサムは比較済みACKが返るまで古い順に再送する。相互に比較・受領が済んだ履歴だけを消し、最初のずれはTITLEからの次の開始まで保持。タイトルバーとDebug出力へ相手・フレーム番号を出す。
- `NetSession` は起動からの単調時計のミリ秒を `SetTime` に渡し、受信後に `CheckTimeouts` を呼ぶ。`SessionCalc` が3秒判定を計算するので、Windows・DirectXなしのテストで時間を進められる。ホストが参加側を切断したら、固定済みの人の枠と入力列は保ち、`TakeFrame` でその人の未受領分だけを無入力で埋めて全員へ配る。切断者のACKを待たず履歴を消し、遅れて届いた入力は使わない。初回開始前のロビーだけは空き枠へ戻す。参加側がホストを失うと `Game` は入力・参加枠・試合・カメラ・シーンを初期化してオフラインのタイトルへ戻す。
- 接続のJOINで版とビルドを照合してから枠を割り当てる。不一致はREJECTを返し、参加側もSTATE / REJECTの版とビルドを確かめる。理由はオフラインのタイトルでもタイトルバーに残す。
- 各通知に送信時刻と相手の最後の時刻、相手のStampを受け取ってから返すまでのミリ秒（Hold）を載せる。返ってきた自分の時刻との差からHoldを引いてpingを計算する（PC間の時計合わせは不要）。Holdが経った時間より大きければ測らない。自動delayの余裕 `AUTO_DELAY_MARGIN` は2のまま。入力待ちで `TakeFrame` が失敗した更新回数を数える。ロビー中は数えず、TITLEから次の開始でリセットする。表示とUDPだけがWindows側にあり、比較・時間・待機数の計算はすべて `src/net/sessioncalc` にある。
- 接続コマンド・Tailscaleの入れ方・自動の遅れと `--delay` での固定・ファイアウォールの許可は [コマンド一覧](../team/04_コマンド一覧.md) の6節を参照。

### OBJ モデル（No.22）

- `src/render/objcalc.h / .cpp`：OBJ 文字列から三角形の位置・法線を作る。Z と三角形の順序を反転して左手系へ変換する。`ObjCalcParseMtl` で MTL の `newmtl`・`Kd` を読み、`usemtl` で頂点に材質の番号を付ける。DirectX 不使用、テストコードあり。

  OBJ に `mtllib` があれば同じフォルダの MTL を読み、頂点色を `Kd` にする（MTL のない腕のモデルは白）。`ModelLoad` の `tintMaterial` に材質名を渡すと、その部分だけを `ModelDrawTinted` の色で描ける。

### FBX モデルとテクスチャ（No.87）

- `ModelLoad` は拡張子で読み方を分ける。`.obj` は上の自作の読み込みのまま、それ以外（`.fbx` など）は `third_party/assimp`（Assimp 5.2.4）で読む。呼び出し方（`ModelLoad`・`ModelDraw`・`ModelDrawTinted`・`mirrorX`・`tintMaterial`）は OBJ と同じ。
- Assimp には `Triangulate | MakeLeftHanded | FlipUVs | PreTransformVertices | GenSmoothNormals | SortByPType` を渡す。ノードの移動・回転・拡大は頂点に焼き込み、Z の反転だけで左手系にする（OBJ と同じ向き。三角形の順は入れ替えない）。単位はファイルのまま（Blender の FBX も cm で出てくる。例：半径 0.2m の球は半径 20）。点・線だけのメッシュは描かない。
- 材質の色のテクスチャ（Diffuse、なければ Base Color）は、FBX に埋め込まれていればそれを、なければモデルと同じフォルダの画像を読む（パスで見つからなければファイル名だけで探す）。テクスチャを貼る部分の頂点色は白、ほかは材質の Diffuse 色。読めなければ Debug 出力に出して材質の色で描く。
- 頂点はメッシュごとに三角形を並べ直して1つの頂点バッファにし、同じテクスチャ・同じ色替えが続く部分は1回の `Draw` で描く（色替えする材質は後ろにまとめる）。Assimp のデータは読み込み後すぐ解放する。
- `src/render/texture.h / .cpp`：Windows 標準の WIC で画像（PNG・JPEG など）をファイル・メモリから読み、ミップマップつきのテクスチャを作る（`TextureLoadFromFile`・`TextureLoadFromMemory`・`TextureCreateBGRA`）。モデル以外でも使える。COM は `main.cpp` が初期化済み。
- Assimp の DLL（`assimp-vc143-mt.dll`）はビルドのあと `Proto1.vcxproj` の `CopyAssimpDll` が exe の隣にコピーする。Win32 用のファイルはないので x64 だけ。
- 確認（2026-11-06）：Blender の `ball.fbx`（埋め込み PNG）を一時ビルドで描き、向き・裏表・鏡写し・テクスチャ（埋め込み／ファイルの両方。チェック柄で UV の上下も）が正しく、既存の OBJ も描けることを画面で見た。

### 骨つきのキャラモデルとアニメ（No.88 から）

- `FighterManager` がキャラごとに `SkinnedModel` を持ち、待機 FBX のメッシュ・骨と8つのクリップ（待機・走り・左腕・右腕・後ろ走り・ジャンプ・落下・着地。No.90）をそのキャラの Fighter 間で共有する。後ろの4つはファイルがなければ代わり（後ろ走り＝走りの逆再生、ほか＝待機）で動く。ジャンプと着地はループせず最後の姿勢で止める。複数のクリップがある FBX では Take 001 以外の先頭を使う。Assimp は左手系へ変換し、ピボット用ノードの生成を切り、頂点に効く骨を4本までにして重みをそろえる。アニメのチャンネルと骨をノード名で対応させる。
- `render/animcalc` でキーの補間と親から順に変換を計算する。30fps の末尾の重複キーは折り返しに使う。クリップを替えると直前に表示した姿勢から 0.15 秒かけてつなぐ。メッシュごとの骨行列は最大64本を b5 に渡し、`shaderVertex3DSkinned.hlsl` が位置と法線を変形する。
- 腕の更新後に `Fighter::UpdateAnimation` がゲームの dt で姿勢を進める。姿勢は描画だけに使う。
- **見た目の動き（No.90）**：`render/motioncalc`（DirectX 不使用、単体テストあり）が、脚（モデル全体）の向き・上半身のねじれ・傾き・全身のクリップ・再生速度を決める。ゲームの向き `Fighter::m_Yaw`（狙い。腕・盾・攻撃に使う）は変えず、通信・チェックサムにも入れない。
  - 走っているときの脚は進む向きへ回る（体の向きより速い）。上半身は骨のねじれで `m_Yaw` を向き、ねじれは ±75° まで（超える分は脚を引っぱる）。進む向きと狙いの差が 110° を超えると後ろ走り（やめる境目には10°の余裕）。No.141 で横走りを足したが、No.143 で取りやめた。止まっていると脚は狙いの向きへ戻る。
  - 全身のクリップは、空中なら上昇＝ジャンプ／下降＝落下、着地の直後 0.2 秒は着地、地面では走り・後ろ走り・待機。走りの再生速度は横の速さ ÷ 歩く速さ（下限 0.5）。吹っ飛び中・保持中・引っぱられ中は走らせない（脚は狙いの向き、空中は落下）。
  - 腕を使っている間、その手のクリップ（両手なら後から発動した手）は「上半身の根元の骨」とその子孫だけに 0.15 秒かけて重ね、脚は走りなどを続ける。
  - ねじれは `AnimCalcRotateY` で、キャラの表のねじる骨（最大3本）に等分してモデル空間の上下の軸まわりに足す。傾きは足元を中心にモデル全体へ掛ける（走ると前へ、曲がると内側へ）。
  - 調整する値は `fighter.cpp` の「調整用の値」（`LEG_TURN_SPEED`・`MAX_TWIST`・`BACK_RUN_ANGLE`・`LEAN_FORWARD` など）。
- **空中の技のアニメ（No.141）**：ハンマーの空中単押しは全身の `HammerHop` と `AIR_TAP_CLIP_SECONDS` を使う。ナックルは長押し開始時に空中・場外・引っぱり中でない条件を描画専用の `m_AirRushClip` に記録し、休みまで `KnuckleAirRush` を維持する。実際の突進が上向きになる条件やタイミングは変えない。
- **単押しの段階攻撃（No.167）**：ナックル・刀・触手は3段、ハンマー（地上）は2段をくり返す。段と受付は `physics/combocalc`（`ComboCalc`）。休みに入ったときに `Open`（休みの秒数＋`COMBO_WINDOW`）で受付を開き、受付の間の単押しは休みを切り上げて次の段を出す（腕の `CanTakeTap` も休みの間に true を返す）。刀の3段目の行き先は `ComboCalcPierceEnd`（浮島から出したときは、ふちの内側で止める）。触手はつかんでいる間に腕のほうで投げる時を決め、`TentacleCalc` の自動の投げは使わない。クリップは `tools/maya/build_combo_clips.py`（右手として書き、左手は左右反転。フレーム 6001〜7400）。
- **ダッシュのアニメ（No.144）**：`Fighter` がダッシュを始めた瞬間に、描画専用の経過秒・地面か空中か・向き（`m_DashAnim*`）を記録する。`MotionCalcDash` が `DASH_CLIP_SECONDS`（9/24 秒：飛び出し 2・進む 3・止まる 4 フレーム）の間だけ `Dash`／`AirDash` を選び、`MotionCalc` は脚（モデル全体）をダッシュの向きへすぐそろえる（上半身は狙いへ上限までねじり、脚は引っぱらない）。再生位置は経過秒（`SKINNED_REQUEST::ClipTime`）。優先はやられ → ダッシュ → 走りなどで、腕のクリップは今までどおり上に重ねる。ジャンプや腕の突進でダッシュをやめたらクリップもやめる。ファイルがなければ `Run`・`Fall` で代わりに動く。クリップは `tools/maya/build_dash_clips.py`。
- **横ダッシュ（No.146）**：`MotionCalcDash` は、狙いから見たダッシュの向きが `SideDashMinAngle`〜`SideDashMaxAngle`（45°〜135°）なら、地面・空中とも `SideDashLeft`／`SideDashRight` を選ぶ。このときは脚を回さず、体ごと狙いの向きのまま（ねじれなし）横へ滑る。それ以外は No.144 のとおり。ファイルがなければ `Run`。
- **ガード・パリィのアニメ（No.140）**：`ArmManager::GetBodyClip` はその手で防いだ直後の `Parry`（12/24秒）または `GuardHit`（8/24秒）→ 構えの `GuardRaise`（4/24秒で止める）→ 装備の攻撃の順に選ぶ。防いだ手は描画用の `GUARD_FEEDBACK::Hand` に記録し、構えを解いたあとや腕が壊れたあとも結果を見せる。
  - `GetActiveHand` はガード開始と攻撃開始のうち後の手を優先する。同じフレームなら後で処理する攻撃、両手の同時ガードなら右を優先する。描画用の `m_LastBodyHand` と、突進速度を選ぶ `m_LastActiveHand` は分ける。`ParryCalc::GetGuardSeconds` は既存の経過秒を読むだけで、ガード判定は変えない。
- **触手のアニメ（No.139）**：（C4 のクリップは No.153 で腕ごと消した。トゲはハンマーの叩き・叩きつけのクリップを使う）`TentacleArm::GetBodyClip` は回転（全身）を優先し、伸長・足場への引っぱり・保持・投げを上半身に重ねる。投げ後0.3秒は判定が待機へ戻っても描画だけ続ける。再生位置の区切りは各腕の `*_CLIP_SECONDS`。任意のFBXがなければその手を前に出すクリップを使う。
- **やられのアニメ（No.138）**：`MotionCalcHitReaction` が全身のクリップを選ぶ。優先は「つかまれ中＝`HitHeld` → 吹っ飛ばされてから0.33秒＝`HitFlinch` → しびれ中＝`HitStun` → 吹っ飛び中＝`HitLaunched` → 通常の動き」。腕の攻撃の重ね方はそのまま。
  - `SetLaunchVelocity`（`Hit`・`Launch`・`Push`）で描画専用の経過秒を0に戻す。のけぞりだけ `SKINNED_REQUEST::ClipTime` で再生位置を指定し、連続で当たったら同じクリップでも先頭から流し直す。復活時は経過秒を大きな値にしてのけぞりを消す。
  - `HitFlinch` は最後の姿勢で止め、ほかの3つはループする。`ClipTime` が負なら従来どおり経過時間で進める。のけぞりへ切り替えるときは0.05秒でつなぎ、ほかは0.15秒。調整する値は `fighter.cpp` の `FLINCH_ANIM_SECONDS`・`HIT_BLEND_SECONDS`。
  - MekaGirl の `mekagirl_hit_flinch.fbx`・`mekagirl_hit_launched.fbx`・`mekagirl_hit_stun.fbx`・`mekagirl_hit_held.fbx` は任意。ファイルがなければ、しびれは待機、ほかは落下で代わりに動く（MEKA も同じ）。描画専用で、当たり判定・通信・チェックサムには入れない。
- **腕をアニメの骨に付ける（No.90）**：キャラの表の `ArmChains`（左右の肩・肘・手首・手先の骨）があるキャラは、`Fighter::GetArmBone` が今の姿勢から肩の骨のワールド座標・上腕（肩→肘）の向き・手先までの長さを返す。`Arm::GetDrawShoulder` はその肩に、腕ごとの取付のずらし × `ArmScale` と、キャラの `ArmOutward`（付け根を外へ出す距離＝肩幅）を足す（触腕の肩の塊が肩の骨に来る）。待機の長さは付け根・節3つ・先っぽを今の大きさで描いた長さ。
  - 触腕はアニメでは振らない。`physics/tentacleropecalc`（重い鎖の物理）で、付け根の箱の真ん中（肩）を根元にしてぶら下げる。最初の節が箱の下半分（上腕）で、人の肩の可動域（前 180°・後ろ 50°・外 180°・内 15°。基準は `Fighter::GetUpperBodyAxes` の上半身の向き。方角の間は楕円でつなぐ）の中で振れる。1フレームを4つに分け、節の長さは両側の点を引っぱり合わせ（肩は固定）、つなぎ目ごとの可動域（箱→最初の節 60°、途中の節 14°、先っぽ 20°）を付け、上限に当たって戻した分は勢いにしない（ガチャガチャしない）。揺れは体に対する分だけを減らし（3.5/秒）、空気抵抗（1.0）で走ると前傾より大きく後ろへ流れる。走り出し・急停止の速さの変化は 70% を腕も一緒に受ける（大きく振られず、止まると前へ約 20° 振れて落ち着く）。体（足元から上半身の傾きに沿って肩の高さまでの円柱。半径は肩の横の距離 × 1.1 ＋ 節の太さ。前傾で肩が前へ出た分は半径に入れない）にはめり込まない（箱は可動域だけで止める）。鎖は描画だけで、1フレームに1回だけ進める（画面分割で何度描いても同じ）。付け根の箱は待機中は鎖の最初の節の向きで、伸ばすほど箱の真ん中を支点に先端の方へ回る（肩も回して見える）。節は回した箱の下端から先端（当たり判定の先端）へ伸ばす（肩から外れて見えない）。伸ばし始めは鎖の形からまっすぐへつなぐ。調整する値は `tentacle.cpp` の `ROPE_*`。
  - 節の向き：モデルの X をキャラの左右の軸に合わせる（付け根の箱の平たい面が体に付き、張り出しが外側）。吸盤側（-Z）は「右 × 腕の向き」へ向ける（前へ出した腕なら下、垂れた腕なら後ろ）。前は腕が真下を向くとワールドの +Z を補助の軸にしていたので、キャラが向きを変えると箱がおかしな向きになっていた。描画だけで、当たり判定の肩（`Arm::GetShoulder`）はメカの値のまま。
  - `ArmScale` は腕のモデルを描く大きさの倍率（メカ 1、MekaGirl 0.6。MekaGirl の待機中は付け根＋節3つ＋先っぽ）。今は触腕だけがこの倍率で描かれ、ハンマーの仮の形はメカの大きさのまま肩の骨に付く。

## 8. エフェクト

### ヒットストップ（No.224）

- `FighterManager::Launch` で当たりが効いたら、ダメージ%と吹っ飛ぶ速さから `HitstopCalcFrames`（`src/physics/hitstopcalc`）で止めるフレーム数を決め、当てられた人（震わせる）と当てた人に `StartHitstop` する。区切りは `fightermanager.cpp` の「調整用の値」の `HITSTOP`。ダメージ%だけの当たり（`AddDamage`。レーザーの単発など）は止めない。
- ガードで防いだら、防いだ人と攻撃した人を 4 フレーム、パリィは防いだ人 6・攻撃した人 12 フレーム止める（`arm.cpp` の `ArmManager::UpdateGuards`）。攻撃した人は `FighterManager::GetGuardedAttacker` で分かる。
- 止まっている人は `Fighter::Update` の頭で戻り（位置・タイマーも進まない）、`ArmManager::Update`・`UpdateAnimation`・連打で抜ける数え方も止まる。重なったら残りの長い方（足さない）。
- 止まっている間は `IsTrigger` が false で、前の入力を止まる前のままにする。止まっている間に押して押し続けたボタンは、動き出したフレームに押した瞬間として効く。
- 試合の動きが変わるので、残りのフレーム数をオンラインのずれの見張り（`LOCKSTEP_STATE::Hitstop`）に入れている。

### 画ぶれ（No.225）

- 揺れの強さは `CameraShakeCalc`（`src/physics/cameracalc`）が持ち、`Camera::Update` で時間とともに減らす。ずれは `CameraCalcShakeOffset`（決まった波。乱数なし）で、`Camera::MakeMatrices` で最後のカメラの位置にだけ足す（追従のバネ・向き・入力の向きは変えない）。
- 揺らすきっかけは `FighterManager::AddShake` で人ごとにためる：当たり（中 0.3・強 0.6・決め手 1.0。ヒットストップの区切りと同じ）、場外（横の壁 0.6・下 0.4。場外になった人と最後に当てた人）、ガード 0.2・パリィ 0.4（`arm.cpp`）。
- `Game` が腕の更新のあとに `TakeShake` で取り出して、その人のカメラへ渡す。当てた人・当てられた人の画面だけが揺れる。描画だけなので通信の確かめには入れない。

### パーティクル（No.226）

- 粒の動き（位置・速さ・重力・減り・寿命・大きさと色の移り変わり）は `ParticleCalc`（`src/physics/particlecalc`）。同時に 512 個まで持ち、超えたらいちばん古く出した粒と入れ替える。
- 出し方は `EffectManager`（`src/game/effect`）の `EFFECT_TABLE`（型ごとの数・飛ばし方（円すい・輪・その場）・速さ・寿命・大きさ・色）。`Spawn(型, 位置, 向き)` で出す。ばらつきは専用の乱数（試合の乱数と別）で、通信の確かめには入れない。
- `Game` が持ち、腕の更新のあとに `Update`、各画面で腕のあとに `Draw`（`ShapeDrawSphere` / `ShapeDrawBox` を半透明で）。`FighterManager` が参照を持ち、腕は `FighterManager::SpawnEffect` で出す。
- 当たり（`FighterManager::SpawnHitEffects`）：当てられた人の胸の当てた人の側に、ヒットストップの区切りで 弱＝火花（小）、中＝火花＋輪、強＝火花（大）＋大きな輪、決め手＝さらに吹っ飛ぶ向きへ光の筋。
- ガード・パリィの広がって消える光（No.132）は `EFFECT_GUARD_FLASH` / `EFFECT_PARRY_FLASH` に移した（`ArmManager::UpdateGuards` で出す）。PARRY! / GUARD の文字はそのまま `hud.cpp`。

### 腕の破壊・撃破・復活・% の見た目（No.227）

- 腕が壊れたら（耐久切れ・パリィできずにガード）、肩から破片（灰色の箱）と白い光を出す（`ArmManager::SpawnBreakEffects`。ガードで壊れたときは体の前へ飛ばす）。耐久 25 以下の腕からは 0.25 秒ごとに細い煙、3回に1回小さな火花（`UpdateWearEffects`）。
- 場外になったら、場外の場所にその人の色の光の柱（横の壁は `EFFECT_PILLAR_WALL`、下は `EFFECT_PILLAR_FALL`）。復活したら上から光の柱を降ろし、足元に輪。無敵が切れた瞬間に光の粒（`FighterManager::Update`）。
- % の見た目は `damagecolorcalc`（`src/render`）：数字の色（0% 白 → 50% 黄 → 100% オレンジ → 150% 赤 → 200% 暗い赤）、体に混ぜる赤（70% から 160% で 0 → 0.55）、煙の段（100% 灰色・150% 黒と火花）。150% 以上は体の赤みをうっすら点滅させる（`Fighter::Draw`）。
- HUD は % が増えた瞬間に数字を大きくして震わせ（増えた量が多いほど大きく）、KO 数が増えた瞬間は数字を大きく黄色にする（`Hud::Update` で前のフレームと比べる）。

### パリィ・ガードのエフェクトと画面の光（No.228）

- 防いだら `ArmManager::SpawnGuardEffects`（`arm.cpp`）：防いだ所に火花（ガードは攻撃が来た向きへ小さく、パリィは黄色い `EFFECT_PARRY_SPARK` を大きく放射）、攻撃した人の胸の防いだ側に火花（弾かれた）。パリィでは攻撃した人の胸に黄色い輪。
- 画面に重ねる白い光は `SCREEN_FLASH`（`effect.h`。ふち・全体の強さ）。`FighterManager::AddScreenFlash` で人ごとにため、`Game` が `TakeScreenFlash` で HUD へ渡す。`Hud::DrawScreenFlash` が HUD のいちばん下に描く。
- 強い当たり（ヒットストップの「強」・「決め手」）は当てた人・当てられた人の画面のふちを光らせ（0.6・1.0）、パリィはパリィした人の画面全体を明るくする（0.8）。消える秒数・濃さは `hud.cpp` の「調整用の値」。

### 動きのエフェクト（No.229）

- `Fighter::Update` が、そのフレームに跳んだ（地上・空中）・着地した（軽い・重い）・ダッシュを始めた（地上・空中）ことを `FIGHTER_MOVE_EVENT` のビットで覚える（`GetMoveEvents`）。重い着地は 0.9 秒より長く宙にいたとき。見た目だけで、通信の確かめには入れない。
- `FighterManager::SpawnMoveEffects` がそれを読んで出す：地上のジャンプ・軽い着地は土ぼこりの輪、重い着地は大きな輪＋画ぶれ 0.2（その人だけ）、空中ジャンプは足元の白い輪、地上ダッシュは後ろへ土ぼこり、空中ダッシュは後ろに空気の輪。
- ダッシュ中は 3 フレームごとに足元の位置を覚え、`Fighter::Draw` が今の姿勢のモデルをその位置へ薄く描く（残像。0.18 秒で消える）。
