## 2. 次にやること：No.58 FPS 表示にフレームの間隔とカクつきを足す（プランは管理者が確認済み。Codex が実装 → Claude が確認）

**なぜ 60 から動かないか**：`main.cpp` のループは 17・17・16 ミリ秒の予定時刻でしか Update・Draw せず、遅れたフレームは予定時刻から進めるので、次のループですぐ追いつく（100ミリ秒より遅れたときだけ仕切り直す）。
FPS は「1秒に何回 Update・Draw したか」なので、1フレームだけ重くても追いつきで 60 回になり、数字に出ない。ずっと重いとき（Present の垂直同期待ちで毎フレーム 33ms かかる など）は 30 前後に下がるので、**60 張り付きは「平均では間に合っている」意味で、数え方の誤りではない**。見えていないのは一瞬のカクつきだけ。

やること（段階2・Codex）：
1. `src/core/framestats.h` / `.cpp` を足す（Windows・DirectX を使わない。`timer.h` と同じ「構造体＋自由関数」の書き方）。
   - `struct FRAME_STATS`：1秒分の集計（フレーム数・処理時間の合計・最大のフレーム間隔・カクつきの回数）。
   - `FrameStatsAdd(stats, intervalMs, workMs)`：1フレーム分を足す。`intervalMs` は前のフレームの始まりからの間隔、`workMs` は Update の始まりから Present の直前まで（垂直同期の待ちを入れない）。
   - `FrameStatsTake(stats)`：1秒分の結果（平均の処理時間・最大の間隔・カクつきの回数）を返して集計を空にする。
   - 調整用の値：`HITCH_MS = 25.0f`（1.5フレーム。これより間隔が長いフレームを「カクつき」と数える）。
2. `main.cpp`：`QueryPerformanceCounter` でフレームの始まり（Update の前）と Present の直前を測り、`FrameStatsAdd` に渡す。1秒ごとの FPS の計算のところで `FrameStatsTake` し、タイトル（デバッグ用ウィンドウ）の FPS を
   `FPS: 60（最大 17ms・処理 3.2ms・カクつき 0）` のように出す。最初のフレームと、100ミリ秒以上遅れて仕切り直したフレームの間隔は数えない（ウィンドウをつかんだときなどで数字が跳ねないように）。
3. `tests/Proto1Tests/framestats_test.cpp`：16.7ms を 59 回と 50ms を 1 回足すと、最大 50・カクつき 1、`Take` のあとは空になる、の主な動き1つ。`framestats.cpp` を既存の項目で追加。壊す確認もする。
4. `.vcxproj` / `.filters` に追加、Debug / Release で警告 0、`run-tests.ps1` が通る。`docs/dev/01_DX11基盤の構成.md` の core の表に1行足す。

確認（段階3・Claude）：ビルドとテスト、起動してデバッグ用ウィンドウの表示を見る（重い場面・ウィンドウを動かした直後の数字）。
