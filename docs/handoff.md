### No.172 スマブラ式のキャラ選択（プラン。管理者の確認待ち。CPU より先にやる）

**目的**：起動してすぐ1人でキャラを選ぶのをやめて、遊び方を決めてから**参加する全員が1つの画面でそれぞれキャラを選ぶ**形にする（スマブラの「キャラ選択画面」）。試合のあともこの画面へ戻れるようにする。

**今の流れ**：GAME START → キャラ選択（1P だけ）→ ルール（GAME / DEBUG）→ 対戦方法（SOLO / LOCAL VS / HOST / JOIN）→（LOCAL・オンラインだけ）ロビー → 試合 → 結果（もう一度 / メニューへ）

**新しい流れ**：GAME START → 対戦方法（SOLO / LOCAL VS / HOST / JOIN / OPTIONS）→ ルール（GAME / DEBUG。オンラインはホストだけ選ぶ）→ **キャラ選択（今のロビーと1つにする）** → 試合 → 結果（もう一度 / **キャラ選択へ** / メニューへ）

**キャラ選択の画面**
- 1P〜4P のカードを横に4つ並べる。カードには、選んでいるキャラのモデル（今のプレビューを小さくしたもの）・名前・状態を出す。状態は「○ で参加」「選択中」「準備OK」の3つ。
- 1人ずつ自分の機器で操作する：○ で参加 → 左右でキャラを変える → ○ で準備OK。× で準備OKを取り消し、もう一度 × で参加をやめる。
- 参加した人が全員「準備OK」になったら、画面に「READY TO FIGHT」の帯を出し、1P が ○ を押すと試合が始まる。
- 1P が参加していない・準備OKでないときに × を押すと、ルール選択へ戻る。
- 空いている枠はカードに「ダミー」と出す（CPU の No.173 で「CPU / ダミー」を切り替えられるようにする）。
- SOLO も同じ画面を使い、参加できるのは決定を押した機器（1P）だけにする。

**直すところ**
- `physics/scenecalc`：`SCENE_CHARACTER_SELECT` を GAME START の直後から外し、上の新しい流れにする。今のロビー（`SCENE_TITLE`）をキャラ選択として使う。結果に「キャラ選択へ」の項目を足す。
- `physics/versuscalc`：枠ごとの「準備OK」を持たせ、全員準備OKかを返す関数を足す（計算なのでテストする）。
- `game/game.cpp`：参加・キャラ変更・準備OKの入力を枠ごとに渡す。SOLO もロビーを通す。
- `game/codex_menu.cpp`：GAME START の説明を新しい順に直す。1P だけのキャラ選択の画面を消し、ロビーの画面を4枚のカードにする（`DrawLobby`）。
- テスト：`scenecalc_test`・`versuscalc_test` に、新しい流れと全員準備OKの判定を足す。

**オンライン**：今はキャラを接続前に決め、ロビーでは変えられない。キャラ選択の画面で変えるには、ロビーの間にキャラと準備OKを送る通信が要る（通信の版を上げる）。

1. 新しい流れ（対戦方法 → ルール → キャラ選択）の順でよいか。

### No.24 動いて戦う CPU（No.173〜175。プラン。No.172 のあとにやる）

**目的**：1人でも「4人で殴り合って場外へ飛ばし合う」試合を遊べるようにする。今の「プロトではやらない（ボット AI）」を外すことになる。

**作り方の方針**
- CPU は**人と同じ入力（`PLAYER_INPUT`：移動・ボタン・カメラ）を毎フレーム作って体に渡す**。腕・カメラ・ガード・当たり判定・耐久はそのまま人と同じものを使い、CPU のための特別な動きは作らない。
- 考える部分は DirectX を使わない `src/physics/cpucalc.h/.cpp`（`CpuCalc`）に置き、単体テストする。今の状況（`CPU_VIEW`）を受け取り、`PLAYER_INPUT` を返す。乱数は `RandomCalc` を試合の種とスロット番号から作る（同じ種なら同じ動き）。
- 状況を集めて `CpuCalc` に渡すのは `src/game/cpu.h/.cpp`（`Cpu` クラス。1体に1つ。`Game` が持つ）。
- CPU のカメラは**ハードロック**で使う。狙う相手を変えたいときは、人と同じくターゲット切り替えのボタン（`ACTION_TARGET_LEFT/RIGHT`）を押す。攻撃の向きはハードロックが相手へ合わせてくれるので、CPU は「近づく・離れる・押す・離す」を決めるだけでよい。
- 反応の遅れ（例：0.25秒ごとに考え直す）と、ためらい（乱数）を入れ、人が見て「動きが読める・勝てる」強さから始める。

**機器と「人」の区別を分ける**（今は `IsHuman()` が「画面がある」と「腕・カメラを持つ」の両方の意味になっている）
- `versuscalc.h` に `VERSUS_DEVICE_CPU`（-4）を足す。
- 「腕・カメラ・カプセルを拾う・復活で腕を戻す・通信の検算に腕を入れる・キャラの色」は**人と CPU**（新しく `IsFighting()` のような名前で分ける）。
- 「画面・HUD・パッドのライト・振動」は**人だけ**（今の `IsHuman()` のまま）。
- 直すところ：`game.cpp`（`m_Humans` のループのうち、カメラ・腕の更新を人と CPU に）、`fighter.cpp`（`SetInput`・`Update` の `IsHuman()`）、`fightermanager.cpp`（`BindPlayer`・復活先・体当たり）、`armcapsule.cpp`、`match.cpp`、`hud.cpp`（頭の上の % の色と「CPU」の文字）。
- `ArmCapsule` に、出ているカプセルの位置を読む関数を足す（CPU が拾いに行くため）。

**CPU の動き（上から順に優先）**
1. **復帰**：浮島の上にいない（`StageCalcIsOnPlatform` でない・下へ落ちている）なら、浮島の中心へ向かって移動し、空中ジャンプとダッシュを使う。ハンマーの空中の跳ね・ナックルの空中の突進・刀のワープなど、その腕に戻る技があれば使う。
2. **ふちを避ける**：浮島のふちの近くで、ふちの外へ向かう移動は止める（相手を追って自分から落ちない）。
3. **腕を拾う**（GAME だけ）：空いている手があり、近くにカプセルがあればそこへ行く。
4. **攻める**：いちばん近い相手（%の高い相手を少し優先）へ近づき、**腕ごとの間合い**に入ったら攻撃する。腕ごとの「間合い・単押しか長押しか・長押しの長さ」は `cpucalc.cpp` の「調整用の値」に表でまとめる（例：ナックル・刀は近く、槍は中くらい、レーザー・モーニングスターの投げは遠く。素手・触手は近づいてつかむ）。単押しの段階攻撃は、間をあけて続けて押す。
5. **守る**：相手が近くで攻撃を始めたら、ある確率でガードする（ガードできる腕のとき）。

**どこで CPU が出るか**
- SOLO と LOCAL VS の空いている枠。キャラ選択の画面（No.172）で、空いている枠のカードを「CPU / ダミー」で切り替える（ダミーは練習用に残す。はじめは CPU）。
- オンラインの空いている枠は**今のままダミー**。CPU をオンラインにも出すには、全員の PC で同じ入力を作れるかの確認と通信の版の更新が要るので、別のタスクにする。
- DEBUG の CPU は人と同じく触手から始め、腕は変えない。

**段階（1つずつ PR にする）**
- **No.173 段階1：土台**：`VERSUS_DEVICE_CPU`、人と CPU の区別、`Cpu`・`CpuCalc` の枠、「相手へ近づいて単押しする・ふちを避ける・落ちたら戻る」だけ。キャラ選択の画面の「CPU / ダミー」の切り替え。
- **No.174 段階2：腕の使い分け**：腕ごとの間合い・長押しの表、カプセルを拾う、腕の復帰技、ガード。
- **No.175 段階3：強さ**：管理者が遊んで決める。必要ならオプションに「CPU の強さ（よわい・ふつう・つよい）」を足す（反応の遅れ・攻撃の多さ・ガードの確率だけを変える）。

**テスト**（`tests/Proto1Tests/cpucalc_test.cpp`）
- 相手が遠ければその方へ移動する／間合いに入れば攻撃のボタンを押す／浮島の外にいれば中心へ向かってジャンプする／ふちでは外へ歩かない／同じ種なら同じ入力になる。
- わざと計算を壊して、上のテストが失敗することを確かめる（`cpucalc` は新しいファイルなので対象）。

**管理者に確かめたいこと**
1. 「ボット AI はプロトではやらない」を外して、No.24 として進めてよいか。
2. 空いている枠のはじめを CPU にし、キャラ選択の画面でダミーに戻せる形でよいか。
3. オンラインの空いている枠はダミーのまま（CPU は別タスク）でよいか。
