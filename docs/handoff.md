**残すもの**：上下の範囲を狭める（-35°〜0°）・腕と投げる向きを水平にする。

**A. バネ（SmoothDamp）の計算**（`physics/cameracalc` に置いてテストする）
- 臨界減衰バネ：今の値・目標・速度（呼ぶ側が持ち、毎フレーム更新）・目標に着くまでのおよその時間（smoothTime）・dt から、次の値を出す。目標へなめらかに加速し、行き過ぎずに減速して止まる。
  - 例：Unity の `Mathf.SmoothDamp` と同じ式（`omega = 2 / smoothTime`、`exp` の近似を使う形）。dt を使うので、フレームレートが変わっても同じ動きになる。
- 角度用：目標との差を -180°〜180° に直してから同じ計算をする（350°→10° は 20° だけ回る）。
- テストすること：目標に近づき行き過ぎない／dt＝0 で変わらない／角度は 180° のまたぎで近い方へ回る／1/60 秒×60回と 1/30 秒×30回でほぼ同じ所に着く／速度を持ち越す（動いている途中で目標を変えても、速度がいきなり0にならない）。

**B・C. 要素ごとに分けて追い、最後にカメラの位置を出す**
- ① 左右の角度（yaw）・② 上下の角度（pitch。カメラの高さ）・③ カメラまでの距離・④ 見ている点 を、それぞれ別のバネで目標へ近づけ、最後に `CameraCalcOrbitPosition` で位置を出す。角度で追うので、カメラはプレイヤーを中心に円を描いて回る。
- 目安の速さ：角度は速め・距離は中くらい・高さ（見ている点の Y）はゆっくり。
- 自分で回す入力（`ActionGetLook()`）は、左右・上下の**目標**の角度に足す（上下は -35°〜0° に収める）。重く感じたら速さで調整する。
- 横移動についてくる sway：移動の入力の横の成分（`ActionGetMove().X`、右がプラス）に比例して、**目標の**左右の角度を同じ側へ回す（`目標 += move.X × FOLLOW_TURN_SPEED × dt`）。
  前・真後ろへ歩くだけ（X＝0）では回らない。自分で回したあと `MANUAL_PAUSE` 秒は止める。試合中（`MatchIsPlaying()`）だけ回す。
- 距離：目標は `FOLLOW_DISTANCE`。浮島にめり込むときは**すぐに**近づける（めり込んで見えるのを防ぐ）。離れるときだけバネで戻す。

**D. 小さな動きは無視する**
- 見ている点の左右（XZ）：プレイヤーの頭と、今の見ている点の目標の差が遊び（`LOOK_DEADZONE`）より小さければ目標を動かさない。超えたら、超えた分だけ目標を動かす。
- 見ている点の高さ：目標は「最後に立っていたときの足の高さ＋頭の高さ」。ジャンプ中は目標を変えない（着地したら、ゆっくり追う）。場外に落ちたときは、浮島の下の線より下まで追う（落ちていくのが見えるように）。
- プレイヤーが復活したとき（`PlayerDidRespawn()`）は、バネを使わずにすぐ見ている点をプレイヤーに合わせる（速度も0にする）。やり直しも同じ（`CameraInitialize`）。

**G. 調整用の値**（`camera.cpp` の上。まわりと同じくタブでそろえた説明つき）
- `YAW_SMOOTH_TIME`（最初は 0.12 秒）・`PITCH_SMOOTH_TIME`（0.12 秒）・`DISTANCE_SMOOTH_TIME`（0.3 秒）・`LOOK_SMOOTH_TIME`（左右 0.15 秒）・`LOOK_HEIGHT_SMOOTH_TIME`（0.5 秒）・`LOOK_DEADZONE`（0.3）・`FOLLOW_TURN_SPEED`（90°/秒）・`MANUAL_PAUSE`（0.5 秒）。

### No.32 のプラン（No.29 のあと。管理者確認済み）

- **キャラの向き**：プレイヤーに左右の向き（yaw）を持たせる。歩いているときは、歩く向き（入力をカメラの向きでワールドの向きに直したもの）へ、1秒に回る角度の上限つきで回る。止まっているときは最後の向きのまま。
- **腕を伸ばすとき**：腕のボタンを押した瞬間に、キャラは画面の正面（カメラの左右の向き）を向く。**腕は今と同じく画面の正面へ水平に伸びる**（2026-10-24、管理者が決めた）。
  腕が出ている間（伸びる・つかむ・戻る）は、キャラは画面の正面を向いたまま、歩くと横歩きになる。投げる向きも画面の正面（今のまま）。
- **見た目**：プレイヤーは向きの分からないカプセルなので、肩の球（`tentacle.cpp` の `Position()`。今はカメラの向きで置いている）をキャラの向きで置く。
- **計算**：向きの計算は `src/physics/` に置いてテストする（例：`PlayerCalcFacing`。歩く向きへ回る・止まると変わらない・腕を出すと画面の正面になる・回る速さの上限・-180°〜180° のまたぎ・dt＝0）。
  回す処理は `CameraCalcTurnYaw` と同じなので、DirectX を使わない共通の場所へ移して使い回す（置き場所は実装のときに決める）。
- 「調整用の値」：キャラが1秒に回る角度（最初は 720° くらい）。
- `player.h` に向きを返す関数（例：`PlayerGetYaw()`）を足す。腕が出ているかは `tentacle.h` に関数を足して調べる。
- ターゲットがいるときの向きは No.33 で足す（ターゲットの方を向く）。

### No.33 のプラン：敵へのロックオン（No.32 のあと。管理者確認済み）

- **ターゲットの決め方**（2026-10-24、管理者が決めた）：
  - 開幕・やり直しのときは、画面の正面（カメラの左右の向き）にいちばん近い敵（`CameraCalcPickFocus` を角度・距離の制限なしで使う）。
  - **右スティックを左右に弾くと、弾いた方向にいる次の敵へ切り替える**。「弾いた方向」は、プレイヤーから今のターゲットへの向きを基準に、その左側／右側にいる敵のうち、いちばん角度の近い敵。その側にいなければ切り替えない。
    計算は `cameracalc` に置いてテストする（例：`CameraCalcNextTarget`。右・左／その側にいない／選べない敵を飛ばす／180° のまたぎ）。
  - 弾く入力は `input/action` に行動として足す（例：`ACTION_TARGET_LEFT` / `ACTION_TARGET_RIGHT`。押した瞬間だけ true）。
    パッド：右スティックの X が遊び（例：0.3）の中から 0.7 を超えた瞬間。一度遊びの中へ戻るまで次は出ない。キーボード：← / →。マウス：短い時間（例：0.15 秒）に左右へ一定量（例：40 ピクセル）より動いたら。続けて出ないよう少し間を空ける。値は `action.cpp` の「調整用の値」。
  - ターゲットが場外・復活待ちになったら、画面の正面にいちばん近い敵へ自動で移る。選べる敵がいなければ、ターゲットなし（No.29 の自由なカメラ）。
- **カメラ**：目標の左右の角度を「プレイヤーからターゲットへの向き」にして、No.29 のバネで追う。ロックオン中は左右を自分で回せない（右スティックの左右・← → は切り替えに使う）。上下は今までどおり回せる。

- **つかんでいる間**：ロックオンを止め、自由なカメラ（自分で左右に回せる。場外の方を向いて投げるため）。離したら、前のターゲットが選べればそれへ、だめなら画面の正面にいちばん近い敵へ戻る。
