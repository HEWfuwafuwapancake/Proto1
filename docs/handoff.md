### No.32 のプラン（No.29 のあと。管理者確認済み）

- **キャラの向き**：プレイヤーに左右の向き（yaw）を持たせる。歩いているときは、歩く向き（入力をカメラの向きでワールドの向きに直したもの）へ、1秒に回る角度の上限つきで回る。止まっているときは最後の向きのまま。
- **腕を伸ばすとき**：腕のボタンを押した瞬間に、キャラは画面の正面（カメラの左右の向き）を向く。**腕は今と同じく画面の正面へ水平に伸びる**（2026-10-24、管理者が決めた）。
  腕が出ている間（伸びる・つかむ・戻る）は、キャラは画面の正面を向いたまま、歩くと横歩きになる。投げる向きも画面の正面（今のまま）。
- **見た目**：プレイヤーは向きの分からないカプセルなので、肩の球（`tentacle.cpp` の `Position()`。今はカメラの向きで置いている）をキャラの向きで置く。
- **計算**：向きの計算は `src/physics/` に置いてテストする（例：`PlayerCalcFacing`。歩く向きへ回る・止まると変わらない・腕を出すと画面の正面になる・回る速さの上限・-180°〜180° のまたぎ・dt＝0）。
  回す処理は `CameraCalcTurnYaw` と同じなので、DirectX を使わない共通の場所へ移して使い回す（置き場所は実装のときに決める）。
- 「調整用の値」：キャラが1秒に回る角度（最初は 720° くらい）。
- `player.h` に向きを返す関数（例：`PlayerGetYaw()`）を足す。腕が出ているかは `tentacle.h` に関数を足して調べる。
- ターゲットがいるときの向きは No.33 で足す（ターゲットの方を向く）。

### No.33 のプラン：敵へのロックオン（No.32 のあと。管理者確認済み）

- **ターゲットの決め方**（2026-10-24、管理者が決めた）：
  - 開幕・やり直しのときは、画面の正面（カメラの左右の向き）にいちばん近い敵（`CameraCalcPickFocus` を角度・距離の制限なしで使う）。
  - **右スティックを左右に弾くと、弾いた方向にいる次の敵へ切り替える**。「弾いた方向」は、プレイヤーから今のターゲットへの向きを基準に、その左側／右側にいる敵のうち、いちばん角度の近い敵。その側にいなければ切り替えない。
    計算は `cameracalc` に置いてテストする（例：`CameraCalcNextTarget`。右・左／その側にいない／選べない敵を飛ばす／180° のまたぎ）。
  - 弾く入力は `input/action` に行動として足す（例：`ACTION_TARGET_LEFT` / `ACTION_TARGET_RIGHT`。押した瞬間だけ true）。
    パッド：右スティックの X が遊び（例：0.3）の中から 0.7 を超えた瞬間。一度遊びの中へ戻るまで次は出ない。キーボード：← / →。マウス：短い時間（例：0.15 秒）に左右へ一定量（例：40 ピクセル）より動いたら。続けて出ないよう少し間を空ける。値は `action.cpp` の「調整用の値」。
    マウス切り替え後の待ち時間は **0.3秒**（2026-10-24、管理者の回答）。
  - ターゲットが場外・復活待ちになったら、画面の正面にいちばん近い敵へ自動で移る。選べる敵がいなければ、ターゲットなし（No.29 の自由なカメラ）。
- **カメラ**：目標の左右の角度を「プレイヤーからターゲットへの向き」にして、No.29 のバネで追う。ロックオン中は左右を自分で回せない（右スティックの左右・← → は切り替えに使う）。上下は今までどおり回せる。
  - 見ている点の目標は `CameraCalcFocusPoint`（プレイヤーとターゲットの両方を画面に入れる）にし、No.29 のバネで追う（目標が変わっても見ている点は跳ばない）。
  - **E. 切り替えのとき**：`SWITCH_TIME` 秒の間だけ、角度のバネを速め（`SWITCH_SMOOTH_TIME`）にする。速度は持ち越すので、切り替え中にもう一度切り替えても、今の回る速さのまま新しい向きへ向かう。
- **つかんでいる間**：ロックオンを止め、自由なカメラ（自分で左右に回せる。場外の方を向いて投げるため）。離したら、前のターゲットが選べればそれへ、だめなら画面の正面にいちばん近い敵へ戻る。
- **キャラの向き**：ターゲットがいるときは、ターゲットの方を向く（歩くと横歩き・後ろ歩きになる。2026-10-24、管理者が決めた）。腕を伸ばすときに画面の正面を向くのは No.32 のまま。
- `camera.h` に `CameraGetTarget()`（今のターゲットのダミーの番号。なしは -1）を足す。No.30・31 はこれを使う。
- 「調整用の値」：`SWITCH_SMOOTH_TIME`（最初は 0.06 秒）・`SWITCH_TIME`（0.3 秒）・`TARGET_POINT_RATE`（見ている点をターゲットへずらす割合。0.25）・画面の端の余白（0.15）。
- 確かめること：テスト・ビルドは No.29 と同じ。画面：開幕に正面の敵へ向く／← → で隣の敵へすっと移ってふわっと止まる／横に歩くとターゲットのまわりを円を描いて回る／ターゲットを場外へ落とすと次の敵へ移る／つかんでいる間は自由に回せる。

- **時間**：動きは「1秒にどれだけ × `GameTimeGetDeltaTime()`」で書く。1フレームは 1/60 秒で固定（No.4 で決めた。`docs/dev/01_DX11基盤の構成.md` の「時間の使い方」）。
- **ビルド**：MSBuild の場所は PC によって違う（Community の PC と Enterprise の PC がある）。`vswhere.exe` で探してから使う（`docs/lessons.md` 参照）。
- **作業場所**：Claude が確かめのために一時フォルダ（%TEMP%）の worktree でビルドするときは `/t:Rebuild` を付ける（`docs/lessons.md` 参照）。

## 4. 別の PC・新しいセッションで始めるとき（Claude・Codex がやること）

Claude（Claude Code）でも Codex でも、共有の `Proto1` フォルダで同じ手順で続きから始める。もう一方の AI が作業中でないことを確認する（`AGENTS.md`）。

1. `CLAUDE.md`（Codex は `AGENTS.md` も）・`docs/lessons.md`・このファイル・`docs/tasks.md`・`docs/dev/01_DX11基盤の構成.md` を読む
2. `git status` だけを先に見る（自分のものではない変更があればユーザーに聞く）
3. `.\tools\fetch-latest.ps1` で develop を最新にし、`gh pr list` で開いている PR を確かめる
4. Notion の「Proto1（腕ダフルアームズ）」で、`tasks.md` と状態がそろっているか確かめる（ずれていたらユーザーに聞く。Notion を読めない AI は飛ばして、最後に管理者に伝える）
5. 「次にやること」の続きから始める（プランが確認待ちなら、ユーザーに確認を取ってから実装する）

## 5. 作業を終えるとき

- このファイルの「今の状態」「次にやること」「最終更新」を書き直す（どの PC の、どの AI（Claude／Codex）で更新したかも）
- `tasks.md` と Notion の状態をそろえる（Notion を書き換えられない AI は、管理者に「Notion の No.〇 を〇〇に」と伝える）
- 次にやるタスクのプランをまだ出していないときは、「次にやること」に「プランに入れること」のメモを残す（次の AI がそこから始められるように）
- 途中で終わるときは、作業中のブランチを `save-work.ps1` で GitHub に送っておく（別の PC で `start-work.ps1 <同じ作業名>` すると続きから始められる）
