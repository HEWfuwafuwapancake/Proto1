## ぶつからない（コンフリクトしない）ための決まり

1. **タスクごとに、触ってよいファイルが決まっている。** 各プランの「触ってよいファイル」に書いていないファイルは変えない。
   足りないと分かったら、勝手に広げずに管理者（Shota）に聞く。
2. **`.vcxproj`・`.vcxproj.filters`（本体とテスト）は No.114 だけが触る。** 新しい計算のファイルは No.114 が空で作って登録しておくので、
   ほかのタスクはその中身を書くだけにする。ファイルを新しく足したくなったら管理者に聞く。
3. **`docs/tasks.md`・`docs/handoff.md`・`docs/decisions.md`・Notion は触らない。** 管理者がマージのときにまとめて直す
   （`CLAUDE.md` の「作業を終えるとき」の handoff の書き直しは、このタスクではしない）。
   値や動きを変えたら、**自分のタスクのプラン（このフォルダの自分のファイル）だけ**を書き直す。
4. **入力の行動（`ACTION_〇〇`）とキー・ボタンの割り当ては No.114 だけが足す。**
5. 1タスク＝1ブランチ＝1 PR。ブランチ名は各プランに書いてある。

## 進め方（頼まれた人へ）

- はじめに `CLAUDE.md`（AI が Codex なら `AGENTS.md` も）と、このファイル、自分のタスクのプランを読む。
- 作業は `.\tools\start-work.ps1 <ブランチ名>` で始め、`.\tools\save-work.ps1 "やったこと"` で保存し、`.\tools\submit-pr.ps1` でレビューを頼む。
  `develop` へのマージは管理者が行う。
- PR の前に確かめること：Debug / Release のビルドが警告 0、`.\tools\run-tests.ps1` と `.\tools\run-tests.ps1 -Release` が全部通る。
  新しく足した計算は、わざと壊してテストが失敗することを1回確かめる（`CLAUDE.md` の「単体テスト」）。
- 見た目や操作が変わるタスクは、ゲームを動かして DEBUG のルールで実際に試す。試せなかったことは PR に「未確認」と書く。
- プランの数字は**はじめの値**。遊んで変えたほうがよければ変えてよい（各ファイルの上の「調整用の値」に置く）。
  プランの**動きそのもの**を変えたくなったら、先に管理者に聞く。
