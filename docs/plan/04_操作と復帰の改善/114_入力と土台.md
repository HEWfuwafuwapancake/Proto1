## やること

### 1. 行動を3つ足す

`src/input/actioncalc.h` の `ACTION` の `ACTION_EQUIP_PREV` のあと、`ACTION_COUNT` の前に足す。

| 行動 | パッド | キーボード | 使うタスク |
|---|---|---|---|
| `ACTION_DASH` | 右ボタン（`PAD_BUTTON_CIRCLE`。Xbox の B） | `C` | 115 |
| `ACTION_GUARD_LEFT` | ZL（`PAD_BUTTON_L2`） | `Z` | 118 |
| `ACTION_GUARD_RIGHT` | ZR（`PAD_BUTTON_R2`） | `X` | 118 |

- `ACTION_COUNT` は 13 から 16 になる。`PLAYER_INPUT::Buttons` は `uint16_t` なので**ちょうど使い切る**。
  `actioncalc.h` に `static_assert(ACTION_COUNT <= 16, ...)` を足し、これ以上足せないことをコメントに書く。
- `src/net/lockstepcalc.cpp` の `BUTTON_MASK = (1u << ACTION_COUNT) - 1u` は 16 でも `0xFFFF` になる。式が正しく動くことを確かめる（通信の形式は変えない）。
- ○ は今も `ACTION_DECIDE`（メニューの決定）に使っている。同じボタンに2つの行動が付くが、決定はメニューと TIME UP、ダッシュは試合中だけなので、そのままでよい。

### 2. キーボードの読み方を直す

`src/input/action.cpp` の `UpdateKeyboardInput` は、今 `ACTION_TARGET_LEFT` より前の行動しかキーを読まない。
`ACTION_KEYS` の並びは `ACTION_COUNT` 個あるので、**ターゲット切り替えの2つを除く全部**を読むようにし、新しい3つのキーを `ACTION_KEYS` に足す
（装備切り替えの4つはキーなし＝0 のまま）。`C`・`Z`・`X` がほかで使われていないことは grep で確かめる。

### 3. 新しい計算のファイルを空で作り、プロジェクトに登録する

ほかのタスクが `.vcxproj` を触らずに済むようにする。中身は各タスクが書く。

| 作るファイル | 中身を書くタスク |
|---|---|
| `src/physics/dashcalc.h` / `.cpp`、`tests/Proto1Tests/dashcalc_test.cpp` | 115 |
| `src/physics/risecalc.h` / `.cpp`、`tests/Proto1Tests/risecalc_test.cpp` | 116 |
| `src/physics/escapecalc.h` / `.cpp`、`tests/Proto1Tests/escapecalc_test.cpp` | 117 |
| `src/physics/parrycalc.h` / `.cpp`、`tests/Proto1Tests/parrycalc_test.cpp` | 118 |

- ヘッダーは `#pragma once` と `/// @file`・`/// @brief`（何の計算を入れるファイルか、どのタスクが書くか）だけ。
  `.cpp` は自分のヘッダーを `#include` するだけ。テストは `#include <gtest/gtest.h>` と自分のヘッダーだけ（テストは 0 件でよい）。
- 登録先：`Proto1.vcxproj`・`Proto1.vcxproj.filters`（フィルターは今ある `guardcalc` と同じ名前を使う）、
  `tests/Proto1Tests/Proto1Tests.vcxproj`・`.filters`（テストと、`..\..\src\physics\〇〇.cpp` の両方）。
- C++ は BOM付きUTF-8・CRLF。空のファイルでも警告が出ないこと（Debug / Release とも警告 0）を確かめる。
