## 管理者が決めたこと（2026-11-13）

- 最大耐久はどの腕も **100**。耐久が少しでも残っていれば、どの攻撃も使える（50 未満でも強攻撃が使える）。
  0 になったら、その動作が終わってから素手に戻る（今の「使い切った腕」と同じ）。
- 1回の動作で減るのは**1回だけ**（当たりなら「当たり」の値、1人も当たらずに終わったら「外れ」の値）。何人に当たっても同じ。
- 移動に使う技（ハンマーの空中の跳ね・ナックルの空中の突進・刀の長押し）は、**移動しただけで必ず減る**。
- 攻撃判定のない腕は今は作らないので考えない。

### 耐久の減り方（はじめの値。各腕のファイルの「調整用の値」に置く）

| 腕 | 弱・当たり | 弱・外れ | 強・当たり | 強・外れ | そのほか |
|---|---|---|---|---|---|
| 触手 | 34（つかんだ・足場に付いた） | 15（何もつかめなかった） | 50（回転が当たった） | 25 | |
| ハンマー | 50 | 25 | 50（衝撃波） | 30 | 空中の跳ねは当たっても外れても 50 |
| ナックル | 34 | 15 | 50（地上の突進） | 25 | 空中の突進は当たっても外れても 50 |
| C4 | 34（爆発が当たった） | 15（爆発したが誰にも当たらない） | 50 | 25 | 場外へ落ちて爆発しなかった：5 |
| ガンランス | 5（弾1発ごと） | 5（弾1発ごと） | 50（突き刺し。3発の撃ち込みを含む） | 25（突進の空振り） | |
| 刀 | 34 | 15 | 50（飛んで当たった） | 40（飛んだが当たらない） | |
| ガード | — | — | — | — | パリィは 0、パリィできずに防いだら 50 |

### Claude が決めたこと（管理者の確認で変わることがある）

- 触手で**足場に付いた**（復帰・高台へ飛ぶ）ときは「弱・当たり」の 34。
- 刀の長押しは、飛んだ瞬間に 40 減らし、通り道か一閃が当たったら 10 足す（合わせて 50）。
- 試合の設定の「腕の使用回数」は「腕の耐久の持ち」に名前を変え、段（×0.5・×1・×1.5・×2・無制限）はそのまま。
  減る量 ＝ 元の減る量 ÷ 倍率 の切り上げ（0 より大きい値は最低 1）。無制限の段では減らない。通信で送る段の並びは変えない。
- 画面の左下・右下の腕の名前の横には、残りの回数の代わりに耐久（0〜100 の数字と細いバー）を出す。
- DEBUG は No.131・132 では今までどおり減らない。No.133 で、DEBUG でも減って見えるが 0 でも壊れないようにする（メーターで試すため）。
- 通信の版は 9 → 10 にする（No.131。耐久の意味が変わり、古い exe と混ぜると DESYNC するため）。

## 進め方（Codex へ）

1. はじめに `CLAUDE.md`・`AGENTS.md`・このファイル・そのタスクのプランを読み、Notion の「Proto1 開発ログ」の「タイトル」「要点」「対応モジュール」を読む。
2. 各タスクで次をくり返す。管理者の確認は待たない（このプランが確認済み）。
   1. `.\tools\start-work.ps1 <ブランチ>`（前のタスクのマージ後なので develop の最新から始まる）
   2. プランの「触るファイル」を変える。プランにない大きな変更が要ると分かったら、止まらずに一番近い形で作り、
      プランの「実装したこと」と PR に理由を書く（動きそのものを変える判断は避け、プランどおりの動きを優先する）。
   3. Debug / Release x64 のビルドが警告 0、`.\tools\run-tests.ps1` と `.\tools\run-tests.ps1 -Release` が全部通る。
   4. 新しく足した計算の関数（131 の `TuningCalcDurabilityCost`）は、わざと壊してテストが落ちることを1回確かめて戻す。
   5. プランの末尾に「実装したこと」（2〜4行）を書き、`docs/plan/03_新しいアームの仕様.md` の該当の所も直す。
   6. `docs/tasks.md` の状態を ✅、PR の番号を書く。`.\tools\save-work.ps1 "No.〇 …"` → `.\tools\submit-pr.ps1`
   7. `gh pr merge <番号> --merge --admin --delete-branch` でマージして、次のタスクへ（1つずつ頼まれたときはここで終える）。
3. ゲームの画面確認・操作の確認はしない（管理者がまとめて遊ぶ）。各プランの「管理者が遊んで確かめること」を、
   最後に `docs/handoff.md` の「次にやること」へ集めて書く。
4. 終わったら `docs/handoff.md`（今の状態・次にやること・最終更新：Codex）を書き直し、Notion の該当の No を「完了」と
   PR のリンクにする（書き換えられなければ、最後に管理者へ伝える）。
5. 途中で直せない問題（ビルドやテストがどうしても通らない）が出たら、そのタスクのブランチを `save-work.ps1` で保存し、
   handoff.md の「今の状態」に止まった所と理由を書いて終える。

## 全体の決まり

- 調整する値は各ファイルの上の「調整用の値」に `static constexpr` で置く。
- `src/game` に `g_` 変数や自由関数を足さない。クラスと public なメンバーには Doxygen の日本語コメントを付ける。
- `core`・`physics`・`net` は `game` を使わない。デバッグ用ウィンドウ（`core`）とゲームの値の受け渡しは `main.cpp` が行う（No.125 と同じ）。
- 新しいファイルは作らない予定（作るなら `.vcxproj` と `.filters` に登録する）。
