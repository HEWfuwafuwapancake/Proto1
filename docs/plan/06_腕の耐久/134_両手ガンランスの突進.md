# No.134 両手ガンランス：片手が突進・突き刺し中は、もう片手を使えなくする

- ブランチ：`gunlance-two-hand-lock`
- 先に読む：[00_全体と進め方.md](00_全体と進め方.md)（進め方は同じ）
- 前提：No.131〜133 がマージ済み（`arm.h / arm.cpp` を触るため）

## 起きていること

- 腕は片手ごとに動きを決めていて、もう片手の動作を見ていない。
- 片手のガンランスで相手を突き刺している（`IsHolding`。歩く速さ 0）間に、もう片手で長押しすると突進が始まる。
  `ArmManager::GetRushVelocity` がその突進の速さを返すので、刺した相手ごと体が動く。
- 左右で同時に長押しすると、両手とも突進する。片方が刺さったり終わったりしても、もう片方の突進で動き続ける。

## やること

- `Arm` に仮想関数を足す：`virtual bool LocksOtherHand() const { return false; }`
  （Doxygen：「この腕の動作中、もう片手の腕に新しい動作を始めさせないなら true を返す（基本は false）」）。
- `GunlanceArm` で上書きする：突進中か突き刺し中（`m_Calc.IsRushing() || m_Calc.IsHolding()`）なら true。
  弾を撃ったあとの構え（`m_PoseSeconds`）は含めない。
- `ArmManager::Update` の手ごとの処理で、**もう片手の今の腕**が `LocksOtherHand()` なら、ガード中と同じように
  `m_Presses[hand].Reset(pressed)` して入力を空にする（単押しも長押しも始めない。押し続けていても、離して押し直すまで始めない）。
  すでに動いているこちらの手の動作は止めない（`arm.Update(input)` は空の入力で呼ぶ）。
- 左右で同時に長押ししたときは、先に更新する左手の突進だけが始まり、右手は始まらない（左手を先に更新する今の順番で決まる）。
- 鍵をかけるのはガンランスだけ（ほかの腕は今のまま）。

## 管理者が遊んで確かめること

- 両手ガンランスで、片手で突き刺している間にもう片手を長押ししても突進せず、体が動かない。
- 片手で突進している間は、もう片手の単押し・長押しが出ない。突き刺しが終わったら、押し直せばもう片手が使える。
- 左右同時の長押しでは、左手だけが突進する。
- 片手ガンランスの突進・突き刺し・射撃は今までと同じ。

## 実装したこと

- `Arm::LocksOtherHand()` を追加し、ガンランスだけ突進・突き刺し中に true を返す。射撃後の構えは対象にしない。
- `ArmManager::Update` は反対の手の現在の装備を見て入力をリセットし、空の入力で更新を続ける。禁止中に押したボタンは押し直すまで発動せず、左右同時の長押しは先に更新する左手だけが突進する。
- ガンランスの仕様表に制限を追記。画面・操作確認は管理者が行うため、確認項目を `handoff.md` に残す。
- Debug / Release x64 ビルドは警告0・エラー0、`run-tests.ps1` は両構成352件通過。新しい計算はないためテスト追加・わざと壊す確認は対象外。
