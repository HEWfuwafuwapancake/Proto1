企画書「腕ダフルアームズ 〜変な腕でぶっ飛ばせ！〜」のプロトタイプを作るためのタスクです。

## このプロトタイプでやること・やらないこと

| やること | やらないこと（プロトでは入れない） |
|---|---|
| TPS（背面）視点の 3D 乱闘アクション | インターネット対戦・4人対戦（敵はその場に立つダミー） |
| PS4 純正コントローラー（DUALSHOCK 4）を PC に USB でつないで遊ぶ | ステージが崩れる・縮む |
| 腕は **触腕（タコ）だけ**：つかんで投げる | 腕カプセル・腕チェンジ・合体・腕を奪う・柱で復帰 |
| スマブラ式：殴られるほどダメージ%が増え、%が高いほど遠くへ飛ぶ | 動いて攻撃してくる敵（ボット AI） |
| 制限時間の中で、敵を場外へぶっ飛ばすとスコアが増える | Maya のモデルの読み込み（はじめは箱・球などの仮の形で作る） |

## 優先度の決め方

| 基準 | 優先度が上がる | 優先度が下がる |
|---|---|---|
| ① 目的に直結するか | 「ぶっ飛ばして点を取る」遊びに直接かかわる | なくても遊びを確かめられる |
| ② ほかのタスクの前提になるか | これがないと先に進めないタスクがある | ほかのタスクから使われない |
| ③ 大きな設計変更や外部ライブラリが要るか | Windows と Visual Studio に入っているものだけで作れる | 要る（**後回し**） |

## きれいな構成にするための方針（タスク 2 で決めて、以降はこれに従う）

- **授業のひな形の書き方は守る**：モジュールごとに `〇〇Initialize / Finalize / Update / Draw`。
- **役割ごとにフォルダを分ける**（案）：`src/core`（ウィンドウ・DX11・シェーダー・時間）、`src/input`（キーボード・マウス・パッド・行動への変換）、`src/render`（形・2D・数字の表示）、`src/game`（プレイヤー・カメラ・ステージ・敵・触腕・試合）、`src/physics`（当たり判定・吹っ飛びの計算）、`shaders/`、`tests/`。
- **ゲームの計算と描画を分ける**：吹っ飛びや当たり判定などの計算は DirectX を使わないファイルに置き、単体テストできるようにする。
- **入力は「行動」で受け取る**：プレイヤーは「キーボードの W」ではなく「移動」「つかむ」などの行動を見る。キーボードでもパッドでも同じように動く。
- **調整する値は1か所に**：移動の速さ・吹っ飛びの強さなどは、各ファイルの上の「調整用の値」にまとめる。

## 進め方

1. 優先度：高の **No.1 から順に**進める（「前提」の列のタスクが終わっていること）。
2. 各タスクは **プラン（何をどう作るか・どのファイルを触るか・どう確かめるか）を出す → 管理者が確認 → 実装 → テスト → 完了チェック** の順。
3. 1つのタスク＝1つのフィーチャーブランチ＝1つの PR。完了したらこの表の「状態」を ✅ にする。
4. 進める中で新しく必要になったタスクは、この表に足してから始める。
