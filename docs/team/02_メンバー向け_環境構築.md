# メンバー向け：開発環境の準備と毎日の作業

このプロジェクトに参加するメンバー（開発者）向けの手順。
**Git も Visual Studio も何も入っていない Windows PC** から始める前提で書いてある。すでに入っているものは飛ばしてよい。

| このプロジェクト | |
|---|---|
| 組織名 | `HEWfuwafuwapancake` |
| リポジトリ名 | `Proto1` |
| リポジトリのURL | https://github.com/HEWfuwafuwapancake/Proto1 |

**最初の1回（手順 0〜8）** と、**毎日の作業（9）** に分かれている。最初の1回は全部で1〜2時間くらい（ほとんどは Visual Studio のダウンロード待ち）。

---

## 0. 用意するもの

- Windows 10 / 11 の PC（**管理者としてソフトをインストールできる**こと。学校のPCでできない場合は先生に相談）
- 空き容量 **30GB 以上**（Visual Studio が大きい）
- メールアドレス（GitHub の登録用）
- スマホ（GitHub の2段階認証で使う）

---

## 1. PowerShell の使い方（ここだけは覚える）

このガイドのコマンドは、すべて **Windows PowerShell** に入力する。

- **開き方**：スタートボタン → 「powershell」と入力 → **Windows PowerShell** をクリック
  （「PowerShell 7」や「コマンドプロンプト」ではなく、**Windows PowerShell**）
- **コマンドの入れ方**：このガイドの灰色の枠をコピー → PowerShell の画面で **右クリック**（または `Ctrl + V`）で貼り付け → **Enter**
- **今いるフォルダ**：行の先頭に `PS C:\Users\あなたの名前>` のように表示されている
- **閉じて開き直す**：ソフトを入れたあとは、PowerShell を **×で閉じて、もう一度開く**（新しく入れたコマンドが使えるようになる）

## 2. GitHub アカウントを作る

1. https://github.com/signup を開き、メールアドレス・パスワード・ユーザー名を入力して登録する。
   - **ユーザー名は英数字**。チームのみんなに見えるので、分かりやすい名前にする。
2. 届いたメールのコードを入力して、メールアドレスを確認する。
3. 2段階認証（2FA）を設定する：右上のアイコン → **Settings** → **Password and authentication** → **Enable two-factor authentication**。
   スマホの認証アプリ（Google Authenticator や Microsoft Authenticator）で QR コードを読み取る。表示される **リカバリーコードは必ず保存** する。
4. **ユーザー名を管理者に伝える。**

---

## 3. Visual Studio 2022 を入れる（DirectX 11 の開発に必要）

1. https://visualstudio.microsoft.com/ja/downloads/ を開き、**Community 2022** の「無料ダウンロード」を押す。
2. ダウンロードされた `VisualStudioSetup.exe` を実行する（「このアプリがデバイスに変更を加えることを許可しますか？」→ **はい**）。
3. 「ワークロード」の画面で **「C++ によるデスクトップ開発」** にチェックを入れる。
   - 右側の「インストールの詳細」で **Windows 11 SDK** にチェックが入っていることを確認する（DirectX 11 はこれに入っている）。
4. 右下の **インストール** を押す。終わるまで 30分〜1時間ほど待つ。
5. 終わったら Visual Studio を一度起動し、Microsoft アカウントでサインイン（なければ「後で行う」でもよい）。

---

## 4. Git と GitHub CLI を入れる

PowerShell を開いて、1行ずつ実行する（途中で「許可しますか？」と出たら **はい**）。

```powershell
winget install --id Git.Git -e --source winget
```

```powershell
winget install --id GitHub.cli -e --source winget
```

- 「使用条件に同意しますか？」と聞かれたら `Y` → Enter。
- `winget` が見つからないと出たら：Microsoft Store で **「アプリ インストーラー」** を更新してから、もう一度実行する。
  それでも駄目なら、ブラウザで入れる：Git は https://git-scm.com/download/win （インストーラーは全部「Next」のままでOK）、GitHub CLI は https://cli.github.com/ の「Download for Windows」。

**PowerShell を閉じて開き直して**、入ったか確認する：

```powershell
git --version
```

```powershell
gh --version
```

どちらもバージョンが表示されればOK（`git version 2.xx...`、`gh version 2.xx...`）。

## 5. スクリプトを実行できるようにする

Windows は最初、PowerShell のスクリプト（`.ps1`）を実行できない設定になっている。次の1行で、自分のアカウントだけ許可する。

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

「実行ポリシーを変更しますか？」と聞かれたら `Y` → Enter。

## 6. GitHub にログインする

```powershell
gh auth login --web --git-protocol https
```

1. `First copy your one-time code: XXXX-XXXX` と8文字のコードが出るので、メモする（または選んでコピー）。
2. **Enter** を押すとブラウザが開く。GitHub にログインして、コードを入力 → **Continue** → **Authorize github**。
3. PowerShell に `✓ Logged in as あなたのユーザー名` と出ればOK。

## 8. プロジェクトを取ってきて設定する

```powershell
New-Item -ItemType Directory -Force $HOME\source\repos | Out-Null
cd $HOME\source\repos
gh repo clone HEWfuwafuwapancake/Proto1
cd Proto1
.\tools\setup-member.ps1
```

`setup-member.ps1` がやること：
- 名前とメールアドレスを聞いてくる → **GitHub のユーザー名** と **GitHub に登録したメールアドレス** を入力
- Git の設定、GitHub へのログイン確認、Git LFS（画像・音声用）の有効化
- 最後に環境チェック（`check-env.ps1`）

最後に **「環境は整っています。」** と出れば準備完了。
`[NG]` が出たら、`→` のあとに書いてある通りに直して、もう一度 `.\tools\setup-member.ps1` を実行する。
（`[注意] 今のブランチ : develop` は、まだ作業を始めていないだけなので気にしなくてよい）

プロジェクトを Visual Studio で開くには：

```powershell
start .\Proto1.sln
```

（エクスプローラーで `ユーザー\あなたの名前\source\repos\Proto1` を開いて `.sln` をダブルクリックしてもよい）

## 9. 毎日の作業

PowerShell を開いたら、まずプロジェクトのフォルダに移動する：

```powershell
cd $HOME\source\repos\Proto1
```

覚えるコマンドは **3つ**（＋便利なもの1つ）。

| いつ | コマンド | 何が起きるか |
|---|---|---|
| 作業を始めるとき | `.\tools\start-work.ps1 <作業名>` | develop の最新から `feature/<作業名>` を作って切り替える。2回目以降は develop の最新を取り込む |
| こまめに（休憩前・帰る前） | `.\tools\save-work.ps1 "やったこと"` | コミットして GitHub に送る |
| 作業が終わったら | `.\tools\submit-pr.ps1` | 管理者に「develop に入れてください」とお願いする（プルリクエストを作る） |
| PR がマージされたあと／develop の最新を見たいだけのとき | `.\tools\fetch-latest.ps1` | 作業は始めずに、develop に新しくマージされたものを取ってきて一覧表示する。develop にいればフォルダの中身も最新になる。**マージ済みのフィーチャーブランチにいたら、自動で develop に戻って古いブランチを片付ける** |

### 流れの例

```powershell
# 1. 作業開始（作業名は英小文字・数字・ハイフン）
.\tools\start-work.ps1 player-move

# 2. Visual Studio で .sln を開いて作業する

# 3. こまめに保存（Visual Studio で Ctrl+S してから）
.\tools\save-work.ps1 "プレイヤーを WASD で移動できるようにした"

# 4. 次の日。続きをやる前に develop の最新を取り込む
.\tools\start-work.ps1 player-move

# 5. できたらプルリクエスト
.\tools\submit-pr.ps1
```

### プルリクエストを出したあと

- 管理者が確認して **develop にマージ** する。マージされたら `.\tools\fetch-latest.ps1` を実行する（develop に戻り、終わったブランチも自動で片付く）。
- 次の作業は、**新しい作業名で** `.\tools\start-work.ps1 <新しい作業名>`。マージ済みのブランチで続けて作業しない（消えたブランチが GitHub に復活してしまう）。
- 「ここを直して」と言われたら、**同じブランチのまま** 直して `save-work.ps1` するだけでプルリクエストに反映される。
- 自分のプルリクエストの状態は `gh pr status` で見られる。

### Visual Studio の注意

- 新しい `.cpp` / `.h` は **Visual Studio の中で作る**（ソリューションエクスプローラーで「ソース ファイル」か「ヘッダー ファイル」を右クリック → 追加 → 新しい項目）。
  エクスプローラーで作ったファイルはプロジェクト（`.vcxproj`）に登録されず、他の人の Visual Studio に表示されない。
  登録し忘れたまま `save-work.ps1` すると、「プロジェクトに登録されていません」と止まって教えてくれる。
- `save-work.ps1` / `start-work.ps1` を実行する前に、Visual Studio で **すべて保存（Ctrl+Shift+S）** しておく（Ctrl+S だけだと `.vcxproj` が保存されないことがある）。
- `start-work.ps1` のあと「ファイルが外部で変更されました」と出たら **はい（再読み込み）**。
- Visual Studio にも Git の機能（右下のブランチ名など）があるが、コミットや push は **スクリプトを使う**。

## やってはいけないこと（やろうとしても GitHub が止める）

| やろうとしたこと | 何が起きるか | 代わりに |
|---|---|---|
| `develop` や `main` に直接 push | `push declined due to repository rule violations` と出て拒否される | `start-work.ps1` でフィーチャーブランチを作る |
| プルリクエストを自分でマージ | ボタンが押せない | 管理者に頼む |
| `feature/` 以外の名前でブランチを作る | push が拒否される | `start-work.ps1 <作業名>` を使う |

詳しいルールは [03_ブランチ運用ルール.md](03_ブランチ運用ルール.md)、コマンドのまとめは [04_コマンド一覧.md](04_コマンド一覧.md)。

## 困ったとき

| 状況 | 対処 |
|---|---|
| `このシステムではスクリプトの実行が無効になっている…` | 手順 5 をやる |
| `git` / `gh` は、コマンドレット…として認識されません | PowerShell を閉じて開き直す。それでも駄目なら手順 4 をやり直す |
| `Repository not found` / `Could not resolve to a Repository` | 招待を承認していない（手順 7）か、ログインしたアカウントが違う（`gh auth status` で確認） |
| develop のまま作業を始めてしまった | そのまま `.\tools\start-work.ps1 <作業名>` を実行する。変更ごと新しいフィーチャーブランチに移る |
| `競合しました` と出た | Visual Studio で競合したファイルを開き、「Merge Editor」で残す内容を選んで保存 → `.\tools\save-work.ps1 "競合を解決"`。分からなければ管理者に相談 |
| `GitHub に送れませんでした` | 別のPCで同じブランチを触った可能性。`.\tools\start-work.ps1` → `.\tools\save-work.ps1` |
| 画像やモデルが開けない（中身が数行のテキストになっている） | `git lfs pull` |
| 何かおかしい | `.\tools\check-env.ps1` を実行して、`[NG]` を直す |
