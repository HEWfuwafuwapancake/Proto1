# コマンド一覧

よく使うコマンドと、その機能のまとめ。
すべて **Windows PowerShell** で、**プロジェクトのフォルダの中**で実行する。

```powershell
cd $HOME\source\repos\Proto1
```

> `.\to` まで打って **Tab キー** を押すと `.\tools\` まで補完される。続けて `st` ＋ Tab で `start-work.ps1` になる（タイプミス防止）。

---

## 1. 毎日使うもの（全員）

| コマンド | 機能 | いつ使う |
|---|---|---|
| `.\tools\start-work.ps1 <作業名>` | develop の最新から `feature/<作業名>` を作って切り替える。すでにあれば切り替えて develop の最新を取り込む | 作業を始めるとき |
| `.\tools\start-work.ps1` | 今のフィーチャーブランチに develop の最新を取り込む | 作業の続きを始めるとき（他の人の変更を取り込みたいとき） |
| `.\tools\save-work.ps1 "やったこと"` | コミットして GitHub の自分のブランチに送る | こまめに（休憩前・帰る前・区切りごと） |
| `.\tools\submit-pr.ps1` | develop へのプルリクエストを作る（保存していない変更は先に保存される） | 作業が終わったとき |
| `.\tools\fetch-latest.ps1` | develop の最新を取ってきて、新しく入った PR を一覧表示する。マージ済みのブランチにいたら develop に戻して片付ける | PR がマージされたあと／develop の最新を見たいとき |

### 1日の流れ

```powershell
.\tools\start-work.ps1 player-move          # 作業開始
.\tools\save-work.ps1 "移動を追加"            # こまめに保存
.\tools\submit-pr.ps1                       # 終わったらプルリクエスト
# （管理者がマージしたら）
.\tools\fetch-latest.ps1                    # develop に戻る＆片付け
.\tools\start-work.ps1 jump                 # 次の作業は新しい作業名で
```

### オプション付きの使い方

| コマンド | 機能 |
|---|---|
| `.\tools\submit-pr.ps1 "タイトル"` | プルリクエストのタイトルを指定して作る（省略すると最初のコミットのメッセージ） |
| `.\tools\submit-pr.ps1 -Web` | プルリクエストを作ったあと、ブラウザで開く |
| `.\tools\save-work.ps1 "やったこと" -NoProjectCheck` | `.vcxproj` に登録していない `.cpp` / `.h` を、わざと入れるとき（普段は使わない。`third_party/` の中はもともと調べない） |

| `gh auth status` | 今どのアカウントでログインしているか確認する | 「Repository not found」と出たとき |

## 3. 状態を確認する（全員・見るだけなので安全）

| コマンド | 機能 |
|---|---|
| `git branch --show-current` | 今いるブランチの名前を表示する |
| `git status` | 保存していない変更（変更・追加・削除したファイル）を表示する |
| `git log --oneline -10` | 最近のコミットを10件表示する |
| `git log --oneline --graph -20` | ブランチの分かれ方・合流を図で表示する |
| `git branch` | 手元にあるブランチの一覧（`*` が今いるブランチ） |
| `git branch -a` | GitHub 上のブランチも含めた一覧 |
| `git diff` | 保存していない変更の中身（何行目をどう変えたか）を表示する。`q` で閉じる |
| `gh pr status` | 自分のプルリクエストの状態（レビュー待ち・マージ済みなど） |
| `gh pr list` | 開いているプルリクエストの一覧 |
| `gh pr view <番号> --web` | プルリクエストをブラウザで開く |

> `git log` や `git diff` の表示が画面に収まらないときは、スペースで次のページ、`q` で終了。

## 4. 片付け・やり直し（全員・使う前に確認）

| コマンド | 機能 | 注意 |
|---|---|---|
| `git switch develop` | develop に切り替える | 切り替えたら必ず `.\tools\fetch-latest.ps1`（手元の develop は古いことがある） |
| `git branch -d feature/〇〇` | マージ済みのブランチを手元から消す | まだマージしていなければ消さずに止まる（安全） |
| `git push origin --delete feature/〇〇` | GitHub 上のブランチを消す | マージ済みのものだけ。管理者に確認してから |
| `git restore <ファイル名>` | そのファイルの保存していない変更を取り消す（最後に保存した状態に戻す） | **取り消した変更は戻せない** |

## 6. オンライン対戦（PC 2〜4台・1台に1人）

### つなぎ方

**全員が同じ develop の版**（`.\tools\fetch-latest.ps1` で最新にする）を、各自の PC で **Release** でビルドして使う。
ソースが違う exe からは参加できない（「参加拒否：ソースが違います」と出る）。Debug と Release を混ぜても断られる。起動の引数はいらない。

1. GAME START で ○ / Enter → 対戦方法を選ぶ。
2. **ホスト**：`ONLINE HOST` を選ぶ。画面にこの PC の IP アドレスが大きく出るので、参加する人に伝える（同じ LAN のもの。Tailscale なら `100.x.x.x`）。
3. **参加する人**：`ONLINE JOIN` を選び、ホストの IP を入れて ○ / Enter。最初から自分の IP の前の3つ（例 `192.168.1.`）が入っているので、たいていは最後の数字だけ打てばよい。
   - キーボード：数字・`.`（次の区切りへ）・Backspace（1文字消す。全部空ならモード選択へ戻る）
   - パッド：十字キー ← → で区切りを移り、↑ ↓ で値を変える
4. ロビー（キャラ選択）で全員が準備OKになったら、ホストが開始する。

- ロビーで Backspace / × を押すと1つ前へ戻る（ロビーから出ると通信を閉じる）。
- 試合が始まったあとは、新しい人の参加も、切断した人の参加し直しもできない。顔ぶれを変えるときは、全員がロビーから出てつなぎ直す。

### 離れた相手とは Tailscale でつなぐ

1. 全員の PC に [Tailscale](https://tailscale.com/docs/how-to/quickstart) の Windows 用アプリを入れる。
2. 管理者が [同じネットワーク（tailnet）への招待](https://tailscale.com/docs/features/sharing/how-to/invite-any-user) を送り、全員が招待を受けてログインする（別々の tailnet のままではつながらない）。
3. ホストの `100.x.x.x` のアドレスを参加する人に伝え、`ONLINE JOIN` で入れてもらう。

初めて起動したとき Windows のファイアウォールに聞かれたら、`Proto1.exe` の **プライベートネットワーク** を許可する（ホストは UDP 27026 を使う）。
つながらなければ、同じ tailnet にログインしているか・ホストの IP・ファイアウォールの許可を確かめる。学校などのネットワークでは、PC どうしの通信が止められていることがある。

### 遅れ（delay）と表示

- 入力の遅れは、ホストが試合を始めるときに ping から自動で決める（4〜20。タイトルバーに `delay 6（自動）` のように出る）。試合の途中では変えない。
- 自動でもカクつくときだけ、起動の引数で固定する（下の例）。遅れを増やすと止まりにくくなるが、操作が効くまでの時間は長くなる。
- タイトルバーの `ping` はホストとの往復のミリ秒、`待ち ...f` は入力がそろわず止まった回数（次の試合で 0 に戻る）。
- `DESYNC 〇P frame 〇〇` は、全員の計算がずれたという表示。`VS の版が違う人がいます` も出ていたら、全員の Visual Studio を最新に更新してそろえる。
- 参加者が3秒届かなくなったら、ホストはその人を無入力にして試合を続ける。ホストが3秒届かなくなったら、参加者は対戦方法の画面へ戻る。

### 起動の引数（2つ起動して確かめるとき・遅れを固定するとき）

リポジトリのフォルダで実行する（下は Debug の例。Release は `x64\Release`）。

```powershell
.\x64\Debug\Proto1.exe --host                  # ホストとしてロビーへ（--delay 10 を付けると遅れを 10 に固定）
.\x64\Debug\Proto1.exe --join 192.168.1.10      # 参加する（同じ PC なら 127.0.0.1）
.\x64\Debug\Proto1.exe --join 127.0.0.1 --windowed
```

| 起動の引数 | 機能 |
|---|---|
| `--host` / `--join <IP>` | メニューを飛ばして、ホスト／参加のロビーへ直接入る |
| `--delay <数>` | 入力の遅れを固定する（0〜120。付けなければ自動） |
| `--windowed` | 1280×720 のウィンドウで起動する（同じ PC で2つ起動するとき） |
| `--fullscreen` | 枠なしの全画面で起動する（ふだんは最大化したウィンドウで起動し、F11 / Alt+Enter で全画面と切り替える） |
| `--debugwindow` | FPS・装備・接続・ping などの情報を別ウィンドウに出す（Debug は付けなくても出る） |

- デバッグ用ウィンドウは情報を見るだけ。試合の設定などの数値は、ゲームのメニューの「オプション」で変える。×で閉じても隠れるだけで、ゲームは続く。

## 7. 使わないもの

| コマンド | 理由 |
|---|---|
| `git push --force` | 他の人の作業を消してしまうことがある |
| `git reset --hard` | 保存していない変更が全部消える |
| `git commit` / `git push`（直接） | `save-work.ps1` の安全チェック（`.vcxproj` の登録漏れ・大きいファイル・develop への直接保存）が働かない |
| `git checkout -b` / `git switch -c`（直接） | ブランチ名や作る元を間違えやすい。`start-work.ps1` を使う |

詳しい手順は [01_管理者向け_環境構築.md](01_管理者向け_環境構築.md) / [02_メンバー向け_環境構築.md](02_メンバー向け_環境構築.md)、ブランチのルールは [03_ブランチ運用ルール.md](03_ブランチ運用ルール.md)。
