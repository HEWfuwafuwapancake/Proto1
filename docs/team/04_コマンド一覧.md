# コマンド一覧

よく使うコマンドと、その機能のまとめ。
すべて **Windows PowerShell** で、**プロジェクトのフォルダの中**で実行する。

```powershell
cd $HOME\source\repos\Proto1
```

> `.\to` まで打って **Tab キー** を押すと `.\tools\` まで補完される。続けて `st` ＋ Tab で `start-work.ps1` になる（タイプミス防止）。

---

## 1. 毎日使うもの（全員）

| コマンド | 機能 | いつ使う |
|---|---|---|
| `.\tools\start-work.ps1 <作業名>` | develop の最新から `feature/<作業名>` を作って切り替える。すでにあれば切り替えて develop の最新を取り込む | 作業を始めるとき |
| `.\tools\start-work.ps1` | 今のフィーチャーブランチに develop の最新を取り込む | 作業の続きを始めるとき（他の人の変更を取り込みたいとき） |
| `.\tools\save-work.ps1 "やったこと"` | コミットして GitHub の自分のブランチに送る | こまめに（休憩前・帰る前・区切りごと） |
| `.\tools\submit-pr.ps1` | develop へのプルリクエストを作る（保存していない変更は先に保存される） | 作業が終わったとき |
| `.\tools\fetch-latest.ps1` | develop の最新を取ってきて、新しく入った PR を一覧表示する。マージ済みのブランチにいたら develop に戻して片付ける | PR がマージされたあと／develop の最新を見たいとき |

### 1日の流れ

```powershell
.\tools\start-work.ps1 player-move          # 作業開始
.\tools\save-work.ps1 "移動を追加"            # こまめに保存
.\tools\submit-pr.ps1                       # 終わったらプルリクエスト
# （管理者がマージしたら）
.\tools\fetch-latest.ps1                    # develop に戻る＆片付け
.\tools\start-work.ps1 jump                 # 次の作業は新しい作業名で
```

### オプション付きの使い方

| コマンド | 機能 |
|---|---|
| `.\tools\submit-pr.ps1 "タイトル"` | プルリクエストのタイトルを指定して作る（省略すると最初のコミットのメッセージ） |
| `.\tools\submit-pr.ps1 -Web` | プルリクエストを作ったあと、ブラウザで開く |
| `.\tools\save-work.ps1 "やったこと" -NoProjectCheck` | `.vcxproj` に登録していない `.cpp` / `.h` を、わざと入れるとき（普段は使わない） |

## 2. 最初の1回・困ったとき（全員）

| コマンド | 機能 | いつ使う |
|---|---|---|
| `.\tools\setup-member.ps1` | Git の設定・GitHub ログイン・LFS の有効化・環境チェック | PC ごとに最初の1回 |
| `.\tools\check-env.ps1` | 環境チェック（Visual Studio / Windows SDK / Git / LFS / GitHub CLI / 接続先）。`[NG]` の項目は `→` の通りに直す | 何かおかしいとき |
| `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` | PowerShell のスクリプトを実行できるようにする | 「スクリプトの実行が無効」と出たとき（PC ごとに1回） |
| `gh auth login --web --git-protocol https` | GitHub にログインする | 最初の1回／ログインが切れたとき |
| `gh auth status` | 今どのアカウントでログインしているか確認する | 「Repository not found」と出たとき |
| `git lfs pull` | 画像・モデル・音声の中身をダウンロードし直す | 素材ファイルが開けない（中身が数行のテキストになっている）とき |

## 3. 状態を確認する（全員・見るだけなので安全）

| コマンド | 機能 |
|---|---|
| `git branch --show-current` | 今いるブランチの名前を表示する |
| `git status` | 保存していない変更（変更・追加・削除したファイル）を表示する |
| `git log --oneline -10` | 最近のコミットを10件表示する |
| `git log --oneline --graph -20` | ブランチの分かれ方・合流を図で表示する |
| `git branch` | 手元にあるブランチの一覧（`*` が今いるブランチ） |
| `git branch -a` | GitHub 上のブランチも含めた一覧 |
| `git diff` | 保存していない変更の中身（何行目をどう変えたか）を表示する。`q` で閉じる |
| `gh pr status` | 自分のプルリクエストの状態（レビュー待ち・マージ済みなど） |
| `gh pr list` | 開いているプルリクエストの一覧 |
| `gh pr view <番号> --web` | プルリクエストをブラウザで開く |

> `git log` や `git diff` の表示が画面に収まらないときは、スペースで次のページ、`q` で終了。

## 4. 片付け・やり直し（全員・使う前に確認）

| コマンド | 機能 | 注意 |
|---|---|---|
| `git switch develop` | develop に切り替える | 切り替えたら必ず `.\tools\fetch-latest.ps1`（手元の develop は古いことがある） |
| `git branch -d feature/〇〇` | マージ済みのブランチを手元から消す | まだマージしていなければ消さずに止まる（安全） |
| `git push origin --delete feature/〇〇` | GitHub 上のブランチを消す | マージ済みのものだけ。管理者に確認してから |
| `git restore <ファイル名>` | そのファイルの保存していない変更を取り消す（最後に保存した状態に戻す） | **取り消した変更は戻せない** |

## 5. 管理者だけ

| コマンド | 機能 |
|---|---|
| `.\tools\admin\merge-pr.ps1` | develop 向けの開いているプルリクエストを一覧表示する |
| `.\tools\admin\merge-pr.ps1 <番号>` | プルリクエストを確認して develop にマージし、フィーチャーブランチを消す |
| `gh pr checkout <番号>` | プルリクエストの中身を手元に持ってきて、ビルド・動作確認する |
| `.\tools\admin\add-member.ps1 <ユーザー名>` | 開発者として招待する（`feature/*` で作業・プルリクエストまで） |
| `.\tools\admin\add-member.ps1 <ユーザー名> -Admin` | 管理者として招待する |
| `.\tools\admin\add-member.ps1 -List` | 今のメンバーと権限、招待中の人を表示する |
| `.\tools\admin\release.ps1 start 1.0` | develop から `release/1.0` を作る（提出前の調整用） |
| `.\tools\admin\release.ps1 finish` | `release/〇〇` を main に入れて `v〇〇` タグを付け、develop にも反映して消す |
| `.\tools\admin\hotfix.ps1 start 1.0.1` | main から `hotfix/1.0.1` を作る（提出後の緊急修正用） |
| `.\tools\admin\hotfix.ps1 finish` | `hotfix/〇〇` を main に入れて `v〇〇` タグを付け、develop にも反映して消す |
| `.\tools\admin\setup-repo.ps1 -Org <組織名> -Repo <リポジトリ名> -Admins <名前> -Members <名前>,...` | 新しいプロジェクトの GitHub リポジトリ作成・ブランチのルール設定・招待（プロジェクトごとに最初の1回） |

## 6. 使わないもの

| コマンド | 理由 |
|---|---|
| `git push --force` | 他の人の作業を消してしまうことがある |
| `git reset --hard` | 保存していない変更が全部消える |
| `git commit` / `git push`（直接） | `save-work.ps1` の安全チェック（`.vcxproj` の登録漏れ・大きいファイル・develop への直接保存）が働かない |
| `git checkout -b` / `git switch -c`（直接） | ブランチ名や作る元を間違えやすい。`start-work.ps1` を使う |
