# コマンド一覧

よく使うコマンドと、その機能のまとめ。
すべて **Windows PowerShell** で、**プロジェクトのフォルダの中**で実行する。

```powershell
cd $HOME\source\repos\Proto1
```

> `.\to` まで打って **Tab キー** を押すと `.\tools\` まで補完される。続けて `st` ＋ Tab で `start-work.ps1` になる（タイプミス防止）。

---

## 1. 毎日使うもの（全員）

| コマンド | 機能 | いつ使う |
|---|---|---|
| `.\tools\start-work.ps1 <作業名>` | develop の最新から `feature/<作業名>` を作って切り替える。すでにあれば切り替えて develop の最新を取り込む | 作業を始めるとき |
| `.\tools\start-work.ps1` | 今のフィーチャーブランチに develop の最新を取り込む | 作業の続きを始めるとき（他の人の変更を取り込みたいとき） |
| `.\tools\save-work.ps1 "やったこと"` | コミットして GitHub の自分のブランチに送る | こまめに（休憩前・帰る前・区切りごと） |
| `.\tools\submit-pr.ps1` | develop へのプルリクエストを作る（保存していない変更は先に保存される） | 作業が終わったとき |
| `.\tools\fetch-latest.ps1` | develop の最新を取ってきて、新しく入った PR を一覧表示する。マージ済みのブランチにいたら develop に戻して片付ける | PR がマージされたあと／develop の最新を見たいとき |

### 1日の流れ

```powershell
.\tools\start-work.ps1 player-move          # 作業開始
.\tools\save-work.ps1 "移動を追加"            # こまめに保存
.\tools\submit-pr.ps1                       # 終わったらプルリクエスト
# （管理者がマージしたら）
.\tools\fetch-latest.ps1                    # develop に戻る＆片付け
.\tools\start-work.ps1 jump                 # 次の作業は新しい作業名で
```

### オプション付きの使い方

| コマンド | 機能 |
|---|---|
| `.\tools\submit-pr.ps1 "タイトル"` | プルリクエストのタイトルを指定して作る（省略すると最初のコミットのメッセージ） |
| `.\tools\submit-pr.ps1 -Web` | プルリクエストを作ったあと、ブラウザで開く |
| `.\tools\save-work.ps1 "やったこと" -NoProjectCheck` | `.vcxproj` に登録していない `.cpp` / `.h` を、わざと入れるとき（普段は使わない） |

## 2. 最初の1回・困ったとき（全員）

| コマンド | 機能 | いつ使う |
|---|---|---|
| `.\tools\setup-member.ps1` | Git の設定・GitHub ログイン・LFS の有効化・環境チェック | PC ごとに最初の1回 |
| `.\tools\check-env.ps1` | 環境チェック（Visual Studio / Windows SDK / Git / LFS / GitHub CLI / 接続先）。`[NG]` の項目は `→` の通りに直す | 何かおかしいとき |
| `.\tools\run-tests.ps1` | 単体テスト（`tests/`）を作り直して実行する。全部通れば「すべてのテストが通りました」。`-Release` で Release でも試せる | 計算（当たり判定・吹っ飛びなど）を変えたとき・PR を出す前 |
| `.\tools\export-tentacle-obj.ps1` | 触腕の Maya モデル（`assets/models/source/takoasi.mb`）を、ゲームで読む OBJ（`assets/models/`）に書き出す。Maya が入っている PC だけ | Maya でモデルを直したとき |
| `.\tools\export-arm-obj.ps1` | 新しいアーム5種の `.mb` を11個の OBJ に書き出す。グラップリングは上腕・前腕・フックの3つ。引数なしで全部、`grapple` / `drill` / `shield` / `magnet` / `hasami` で1種類。`-Inspect` で各 transform の親・範囲・三角形数も表示。Maya が必要 | 新しいアームのモデルを直したとき |
| `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` | PowerShell のスクリプトを実行できるようにする | 「スクリプトの実行が無効」と出たとき（PC ごとに1回） |
| `gh auth login --web --git-protocol https` | GitHub にログインする | 最初の1回／ログインが切れたとき |
| `gh auth status` | 今どのアカウントでログインしているか確認する | 「Repository not found」と出たとき |
| `git lfs pull` | 画像・モデル・音声の中身をダウンロードし直す | 素材ファイルが開けない（中身が数行のテキストになっている）とき |

## 3. 状態を確認する（全員・見るだけなので安全）

| コマンド | 機能 |
|---|---|
| `git branch --show-current` | 今いるブランチの名前を表示する |
| `git status` | 保存していない変更（変更・追加・削除したファイル）を表示する |
| `git log --oneline -10` | 最近のコミットを10件表示する |
| `git log --oneline --graph -20` | ブランチの分かれ方・合流を図で表示する |
| `git branch` | 手元にあるブランチの一覧（`*` が今いるブランチ） |
| `git branch -a` | GitHub 上のブランチも含めた一覧 |
| `git diff` | 保存していない変更の中身（何行目をどう変えたか）を表示する。`q` で閉じる |
| `gh pr status` | 自分のプルリクエストの状態（レビュー待ち・マージ済みなど） |
| `gh pr list` | 開いているプルリクエストの一覧 |
| `gh pr view <番号> --web` | プルリクエストをブラウザで開く |

> `git log` や `git diff` の表示が画面に収まらないときは、スペースで次のページ、`q` で終了。

## 4. 片付け・やり直し（全員・使う前に確認）

| コマンド | 機能 | 注意 |
|---|---|---|
| `git switch develop` | develop に切り替える | 切り替えたら必ず `.\tools\fetch-latest.ps1`（手元の develop は古いことがある） |
| `git branch -d feature/〇〇` | マージ済みのブランチを手元から消す | まだマージしていなければ消さずに止まる（安全） |
| `git push origin --delete feature/〇〇` | GitHub 上のブランチを消す | マージ済みのものだけ。管理者に確認してから |
| `git restore <ファイル名>` | そのファイルの保存していない変更を取り消す（最後に保存した状態に戻す） | **取り消した変更は戻せない** |

## 6. オンライン対戦（PC 2〜4台・1台に1人）

全員が同じ版・同じビルド（Debug同士、またはRelease同士）の `Proto1.exe` を使う。ゲームはふつうに起動し、ゲームの中から始める（起動の引数はいらない）。

1. GAME START で○／Enter → モード選択。
2. **ホスト**：`ONLINE HOST` を選ぶ。ロビーの上にこのPCのIPv4アドレスが大きく出るので、参加する人に伝える（複数出たら、同じLANのもの。Tailscaleなら `100.x.x.x`）。
3. **参加側**：`ONLINE JOIN` を選び、ホストのIPを入れて○／Enter。最初は自分のIPの前の3つ（例 `192.168.1.`）が入っているので、最後の数字だけ打てばよいことが多い。
   キーボードは数字・`.`（次の区切りへ）・Backspace（1文字消す。全部空ならモード選択へ）。パッドは十字キー ←→ で区切りを移り、↑↓ で値を変える。
4. ロビーで全員が○／Enterを押して自分の機器を決める。全員の選択後、ホストが同じ機器でもう一度○／Enterを押すと開始する。

ロビー・メニューでは Backspace／× で1つ前へ戻る（ロビーから戻ると通信を閉じる）。試合開始後の新規参加・切断した人の再参加はできない。顔ぶれを変えるときは、全員がロビーから戻ってつなぎ直す。メニューから開いたホストの遅れ（delay）は3。

2つ起動して確かめるときや遅れを変えるときは、起動の引数でメニューを飛ばしてロビーへ直接入れる（リポジトリのフォルダを作業フォルダにして起動する。以下は Debug の例）。

```powershell
# ホスト（LANの目安は3。指定なしも3）
.\x64\Debug\Proto1.exe --host --delay 3

# 参加側（ホストのIPv4アドレスへ置き換える。同じPCなら 127.0.0.1）
.\x64\Debug\Proto1.exe --join 192.168.1.10
```

### 離れた相手とはTailscaleでつなぐ

1. 全員のPCに [Tailscale公式の案内](https://tailscale.com/docs/how-to/quickstart) からWindows用アプリを入れる。
2. グループの管理者が [同じネットワーク（tailnet）への招待](https://tailscale.com/docs/features/sharing/how-to/invite-any-user) を送り、全員が招待を受けてログインする。アプリでも全員が同じグループ（tailnet）を選び、接続済みにする。各自別のtailnetのままではつながらない。
3. Tailscaleの端末一覧（またはホストのロビーの表示）でホストの `100.x.x.x` のIPv4アドレスを調べ、参加側へ伝える。参加側は `ONLINE JOIN` でそのアドレスを入れる。

遠い相手で遅れを増やすときは、起動の引数を使う（メニューから開くホストは3のまま）。

```powershell
# 遠い相手では、まず6〜7フレームを目安にする
.\x64\Debug\Proto1.exe --host --delay 6
.\x64\Debug\Proto1.exe --join 100.64.1.2
```

`--delay` はホストの値を全員で使う。LANでは3、pingが80〜100ms程度の遠い相手では6〜7が目安。変更するときはゲームを起動し直す。タイトルバーの `ping` はホストとの往復ミリ秒（ホスト側は各参加者）、`待ち ...f` は入力がそろわず計算を止めた更新回数の累計。ロビー中は増えず、TITLEから次の試合を始めると0に戻る。遅れを増やすと待ちにくくなるが、操作が反映されるまでの時間は長くなる。

初回起動でWindowsのファイアウォールに聞かれたら、`Proto1.exe` の **プライベートネットワーク** を許可する。ホストは **UDP 27026** を使い、参加側は空きポートを使う。つながらなければ、同じtailnetへのログイン・ホストのIP・ファイアウォールの許可を確認する。学校などのネットワークではUDPやPC同士の通信が制限されている場合がある。

`DESYNC ... frame ...` は全員の位置・%・KO数にずれがあった表示（Debug出力にも記録）。参加者が3秒届かなければホストがその人の未受領の入力を無入力で埋め、試合を続ける。配布済みの入力は保つ。ホストが3秒届かなければ参加側はモード選択へ戻る。版・Debug／Releaseが違うと接続時に参加を断り、タイトルバーに理由を表示する。

## 7. 使わないもの

| コマンド | 理由 |
|---|---|
| `git push --force` | 他の人の作業を消してしまうことがある |
| `git reset --hard` | 保存していない変更が全部消える |
| `git commit` / `git push`（直接） | `save-work.ps1` の安全チェック（`.vcxproj` の登録漏れ・大きいファイル・develop への直接保存）が働かない |
| `git checkout -b` / `git switch -c`（直接） | ブランチ名や作る元を間違えやすい。`start-work.ps1` を使う |
